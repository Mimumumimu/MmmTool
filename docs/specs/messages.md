# メッセージ

人どうしが短いメッセージをやり取りする機能の仕様。会話は 1 対 1 とグループの 2 種類で、画面は会話ごとのチャット形式にする。

## 概要

- DB モード (サーバーモード)だけで使う
- 宛先は人。人に送ると、その人が「受け取り先」に指定した送信先へ、通知 (ntfy・Discord・Web 版通知)が届く
- メッセージは、書いた時点で、会話に入っている人が読める。通知の送信は、MmmBatch が別に行う ([mmmbatch.md](mmmbatch.md))
- MmmTool と Web 版は、メッセージと通知の状態を DB に書くだけで、外部へは送らない
- 受け取ったメッセージも、自分が送ったメッセージも、会話で見返せる
- 返信は、返信元のメッセージを指して行う

## 位置づけ

- MmmTool に外部へ接続するコードは入れない
- 画面が書くのは `Message` と `MessageDelivery` の行で、MmmBatch が数秒おきに `MessageDelivery` を読んで通知を送る
  - 表の定義は [database.md](database.md)
  - 送る側は [mmmbatch.md](mmmbatch.md) の「メッセージの送信」
- 通知を送る先の送信先は、メッセージの行にも通知の状態の行にも持たない
  - MmmBatch が、送るときに、受け取る人の受け取り先 (`AppUserSetting`)を読んで、送信先の値を `NotificationChannel` から読む
  - MmmTool の画面も、送信先の値を読まない (値は秘密のため)
- 通知の表に、失敗の理由の列を持たない
  - 理由は MmmBatch のログに残す
  - 経過の記録は、状態を持つ表の役割ではないため

## プロジェクト

| 場所 | 中身 |
| --- | --- |
| `src/NotificationChannels/MmmTool.NotificationChannels.Core` | 機能どうしは参照しないため、どちらの Core にも置かない。リマインダーとメッセージで共有する送信先 (`NotificationChannel`・区分・登録名と値の規則・`INotificationChannelRepository`)と、送信先を受け取り先に指定できる設定の登録口 |
| `src/Users/MmmTool.Users.Core` | ユーザーごとの設定 `AppUserSetting` の型と、保存先のインターフェース。受け取り先は、この設定の 1 行 |
| `src/Plugins/MmmTool.Messages.Core` | 保存先が DB でないとき (ローカルモード)は「使えない」実装を登録し、`IsAvailable` が false になる。持つのは、会話・参加者・メッセージ・通知の状態の型と状態 (`Message`・`MessageDelivery` の状態)・入力の上限 (`MessageLimits`)・保存先のインターフェース (会話と人の一覧の読み出し・差分の取得・メッセージの書き込み・1 対 1 の会話の取得) |
| `src/Plugins/MmmTool.Messages` | `MmmTool.Data*` は参照しない。持つのは、画面 (`Main/`)・端末の控え・DI 登録の入口 (`MessagesPlugin`) |
| `src/Data/MmmTool.Data` / `MmmTool.Data.SqlServer` | 行のクラス・Repository の実装で、他の機能と同じ ([../architecture.md](../architecture.md) の「DB のコードの置き場所」) |

- `NotificationChannel` の登録の画面 (一覧・編集・設定ページの「送信先」)は、リマインダーの機能 (`MmmTool.Reminders`)に置く。移すのは型と Repository のインターフェースだけ。
- 受け取り先と「通知を受け取る」のオン・オフの画面は、[notification-settings.md](notification-settings.md) を見る
  - メッセージは、「通知を受け取る」の機能として、機能番号 5・区分番号 1 と、画面に出す名前「メッセージ」を登録する

## 受け取り先

- 受け取り先は、全機能で共通の設定。指定のしかたと保存は [notification-settings.md](notification-settings.md) を見る
  - メッセージ専用の受け取り先を持たない
- 受け取り先が未指定の人 (指定を外した人と、指定した送信先が削除された人)は、宛先の一覧に出なくなる。
- 管理者がメッセージを無効にした人も、宛先の一覧に出ず、メッセージを送れない ([mmmtooladmin.md](mmmtooladmin.md) の「機能の利用」)
  - 無効にされた人が送ろうとすると、会話が見つからない結果になる。無効にされた人への 1 対 1 は、受け取り先が無いときと同じ結果になる。
  - グループでは、無効にされた人にだけ、通知の状態の行を書かない。ほかの参加者には送る。
- 「メッセージの通知を受け取る」をオフにした人は、宛先の一覧に出る。メッセージは会話に書け、本人は読める。外部への通知だけを送らない。送る側は [mmmbatch.md](mmmbatch.md) の「メッセージの送信」を見る
- 受け取り先が未指定の人には、送れない。会話は開けるが、入力欄は押せず、「受け取り先が未設定です」と出す。
- 自分が受け取り先を指定していないときも、送れない。返事を受け取れない人が、一方的に送る形にしないため。
  - 会話は開けて、読める。入力欄は押せず、「自分の受け取り先が未設定です。設定で指定すると送れます」と出す。相手の案内は出さず、自分の案内だけを出す。
  - 送る処理も、送る人の受け取り先を確かめて、無ければ何も書かずに断る。PC 版と Web 版は同じ処理を使うので、どちらも断る。受け取り先の送信先が削除済みのときも、未指定と同じ。
  - 自分の状態は、会話を開いたときと、ページが見えるようになったとき (Web 版は裏から戻ったとき)に読み直す。設定ページで指定して戻ったときに、送れるようにするため。
- 相手の受け取り先の有無は、会話の要約の控えの値を使わず、会話を開いたときと、ページが見えるようになったとき (Web 版は裏から戻ったとき)に、DB から読み直す。
  - 差分の取得は、新しいメッセージのあった会話の要約しか返さない。相手が受け取り先を指定しても、控えの要約は古いままで、「受け取り先が未設定です」が出続けるため。
  - 読み直した値は、会話の要約と端末の控えにも書き戻す。一覧の行の注記も、今の値になる。
  - 一覧にだけ出ていて、まだ開いていない会話の注記は、開くまで、控えの値のまま。
- 書いたあとに受け取り先を外された通知は、送れないので「失敗」になる。メッセージは、会話に残り、本人が読める。
- 送り手が、受け取り先を選ぶ画面や、前回の宛先を覚える設定を持たない (受け取る人が決めるため)

## 会話の形

- 会話 (`MessageConversation`)の種類は 2 つ
  - 1 対 1: 同じ 2 人の組に、会話は 1 つだけ。名前は持たない。自分との会話も 1 対 1 で、参加者は自分 1 人。
  - グループ: 名前を持つ。メンバーが同じで名前の違う会話を、いくつでも作れる。参加者は 50 人まで。
- グループの作り方と参加者の操作は、[グループ](#グループ)を見る。
- 1 通のメッセージ (`Message`)は、1 つの会話に属し、本文と送った人と返信元を持つ
  - タイトルを持たない (会話の形では、件名を付けないため)
  - 返信元は、同じ会話のメッセージだけを指せる。サーバーが確かめ、守れなければ 400 を返す。
- 通知の状態 (`MessageDelivery`)は、1 通を、送った人以外の参加者 1 人に通知する状態を 1 行ずつ持つ。自分との会話は、自分に 1 行。

## 画面

- 入口は、サイドバーのページ「メッセージ」だけ
  - トレイのメニュー「メッセージ送信」は置かない (人の一覧と会話を持つ画面は、1 通を送る小さなウィンドウに収まらないため)
  - PC 版のページは、別のウィンドウに外せる ([tray-and-main.md](tray-and-main.md))
    - 外す・戻す・機能をオフにしてオンに戻すときは、ページが作り直される。開いていた会話・宛先の人を選ぶ画面・入力中の本文・返信先を、そのまま引き継ぐ (ユーザーの決定)
    - 持つのは `MessagesViewState` ([architecture.md](../architecture.md)の「画面で選んだ状態」)
    - 引き継がない: 会話のメッセージと一覧 (作り直したあとに、控えと DB から読み直す)・送信中の表示・読み込みのエラー
    - 返信先は、読み直した会話のメッセージから、番号で探して戻す。見つからなければ、返信は無くなる。
    - 通知を押して会話を開くときは、外したウィンドウがあればそのウィンドウを前に出して、そこで開く
    - 外している間も、読み続ける部品 (`MessageSyncService`)は 1 つで、同じ会話を 2 か所で読むことはない
- 画面は、左に会話の一覧、右に会話を並べる
  - PC 版の左の幅は 320 の固定。右は残りの幅を使い、720 で止めて、余った幅は右に空ける。右の欄は、中身の幅ではなく、列の幅で決める。中身で決めると、入力した文字の長さで、欄の幅が変わるため。
  - PC 版の枠の中の色は、送信欄のカードと同じ、標準のカードの色にする。地の色のままだと、枠の中と外の区別がつかないため。左の上の行の「新しい会話」と、右の上の行の会話の題名は、同じ高さにして、下の枠の上端をそろえる。
  - PC 版は、会話の一覧とメッセージの一覧を線だけの枠で囲み、送信欄を背景つきの 1 枚のカードにする。作りは、[cli-assist.md](cli-assist.md) の CLI補助の画面と同じ。入力欄は 3 行分の高さ固定で、超えた分は欄内でスクロールする。
  - PC 版の会話の幅は、720 まで。広いウィンドウでも、横に伸ばさない。メッセージの 1 行が長くなりすぎると、読みにくく、送信ボタンも遠くなるため。
- Web 版 (iPhone のブラウザ)にも、同じ作りの画面がある。作りは [web.md](web.md) の「メッセージ (Web 版)」を見る。「送れる状態」の判定は、MmmTool と Web 版で `MessageDraft` を共有する。

### 人の一覧

- 一覧に出るのは、やり取りのある会話だけ。自分が入っている会話で、1 対 1 の会話は相手の表示名、グループは会話の名前で出す。
  - 並びは、最後のメッセージが新しい順
  - 各行は、名前、最後のメッセージの 1 行目、時刻
  - PC 版は、開いている会話の行に、標準の選択の見た目で印を付ける。強調色の縦の印と薄い背景が付く。
    - 会話を開くのは、行を押したときだけ。選択の変更では開かない。矢印キーを押したときや、新着で一覧が並び替わったときに、会話が切り替わらないようにするため。
    - 開いている行を押しても、何もしない (メッセージの表示と、入力中の本文・返信先を残す)
    - 別の会話に切り替えるときは、端末の控えを読み終えるまで前の会話を出したままにし、押した時点の前の会話の見た目を画像に撮って、一覧の上に重ねる。その下で中身を差し替え、一番下へ合わせてから、重ねた画像を薄くしながら、下の新しい会話を濃くする (重ねたフェード)。前の表示を一度で消さないのは、一瞬なくなったように見えるため。空の画面と、先頭から一番下へ飛ぶ動きも見せない。
    - 重ねたフェードは、前の会話と新しい会話で、長さと曲線を分ける。前の会話は 260ms で、始めも終わりもなめらかに消え、新しい会話は 60ms 遅れて、360ms で減速して止まりながら、10px 下から浮かび上がる。
      - 長さは、`MessagesPage.xaml.cs` の `FadeOutDuration`・`FadeInDelay`・`FadeInDuration`・`FadeInRise` で決める。
      - 同じ長さ・同じ曲線で同時に動かさない。吹き出しが重なる位置で、真ん中に背景が透けて、一瞬薄く見えるため。
      - 標準の入場アニメーションにしない。`ContentThemeTransition` などは新しい側しか動かず、前の会話を薄くして消せないため。
      - OS の設定で画面の動きが切られているときは、動きなしで切り替える。
    - 撮った画像は、フェードが終わったら捨てる。続けて押したときは、撮り直さず、残っている画像を使う。
    - 端末の控えが無い会話は、DB から読み終えるまで、仮の行を出す。控えがあるときは、すぐ中身が出るので、仮の行を挟むと点滅して見えるため出さない。
    - メッセージの行ごとの出現アニメーションは付けない (差し替えのたびに、全部の行が透明から現れて、空に見えるため)
    - 矢印キーでは、選択を動かさず、フォーカスだけを動かす
    - 開く行が一覧の見えていない所にあるときは、その行が見える位置までスクロールする
    - 通知から開いたときと、新しい会話ができたときも、その行に印が付く
    - まだ会話が無い空の会話の画面のときは、印を付ける行が無い
  - 各行の最後のメッセージは、グループでは「送った人の名前: 本文の 1 行目」の形にする。自分が送ったものは、名前を「自分」にする。1 対 1 は、本文の 1 行目だけ。
  - 会話が 1 つも無いときは、「新しい会話」から宛先を選ぶ案内を出す。
- 読んでいないメッセージがある会話の行に、名前の左に青い点を付け、名前を太字にする。メールの一覧と同じ形。PC 版と Web 版の両方に付ける。
  - 読んでいないかどうかは、DB の読んだ位置 ([既読](#既読)を見る)から決める。端末ごとには持たない。PC で読めば、iPhone の点も消える。
  - 読んでいないメッセージは、自分の読んだ位置より新しい、他の人が送ったメッセージ。自分との会話は、自分が送ったものも数える。システムメッセージは数えない。数は会話の要約の `UnreadCount` が持つ。
  - 会話を開いて、画面が見えている間に出たメッセージは、読んだことになり、点が消える。
  - 相手に見える既読と同じ値から決めるので、読んだことにするのは、会話を開いていて、画面が見えている間だけ。
  - まとめて読んだことにする操作 (「すべて既読にする」など)を持たない。開かずに読んだことになると、読み忘れに気づけなくなるため。
  - ホーム画面のアイコンの数字は、Web 版の [web.md](web.md) の「通知 (Web 版)」の、ホーム画面のアイコンの数字を見る。
  - PC 版は、新着を通知ダイアログでも知らせる。ダイアログに出しただけでは、読んだことにしない。
- 新しい相手へは、一覧の上の「新しい会話」で、宛先に選べる人の一覧を出して選ぶ。名前や文字を入れて探す操作と、探す欄は無い。
  - PC 版: 左の一覧が、宛先に選べる人の一覧に替わる。上の「戻る」で、会話の一覧へ戻る。
  - Web 版: 右下に浮かべた「新しい会話」を押すと、画面全体が宛先を選ぶ画面になる。上の「キャンセル」で閉じる。
  - 出るのは、受け取り先を指定している人だけ。表示名の順で、各行は名前だけ。読む件数は、100 人まで。
  - 自分も出る。自分に送って、通知が届くことを確かめられるため。
  - 1 対 1 の会話がある人も出る。選ぶと、その会話が開く。
  - 開くたびに読み直す
- 人を押すと、その人との 1 対 1 の会話が開く。やり取りがまだ無ければ、空の会話の画面を出し、会話は最初の送信で作る。選んだだけでは、会話を作らない。メッセージの無い会話を、DB に残さないため。
- 選ぶ画面の先頭に、「新しいグループ」の行を置く。押すと、グループを作る画面に移る。決まりは [グループ](#グループ)を見る。
- 最後のメッセージは、会話の表に持たず、メッセージの表から、会話ごとに最新の 1 通を読んで求める

### 会話

- 古いものが上、新しいものが下に並べる。受け取ったメッセージは左、自分が送ったメッセージは右。
- 最初は最新の 50 件を出す。上へスクロールして先頭に近づいたら、さらに古い 50 件を読み足す。読み足しても、見ていた位置は動かさない。
- 1 つのメッセージは、返信元の引用があればその引用、本文、時刻の順
  - 返信元の引用は、返信元を送った人の名前と、本文の 1 行目
- 本文の `http://` と `https://` で始まる文字は、表示のときにリンクにする。保存した本文は変えない。
  - 見つけ方と、リンクにしてよい URL の判定は、ノートの自動リンクと同じ SDK の `TextLinkFinder` を使う。ファイルのパスはリンクにしない。詳しくは [notes.md](notes.md) の「自動リンク」を見る。
  - PC 版は、押すと `IPathOpener` で既定のブラウザを開く。開けなかったときは、InfoBar に出す。Web 版は、新しいタブで開く。Web 版の作りは [web.md](web.md) の「メッセージ (Web 版)」を見る。
  - 返信元の引用と、会話の一覧の最後のメッセージは、リンクにしない。
- 自分が送ったメッセージには、相手が読んだことを表す「既読」だけを付ける。「既読」は [既読](#既読)を見る。
  - 通知の状態の印 (送信待ち・失敗)を、1 対 1 にもグループにも付けない。メッセージは書いた時点で DB にあり、参加者はアプリを開けば読める。通知 (スマホへの知らせ)が届いたかは、読めるかどうかと関係しないため。
  - 失敗の理由は、MmmBatch のログと画面で見る
- グループでは、他の人のメッセージの吹き出しの上に、送った人の名前を出す。自分のメッセージと、1 対 1 には出さない。
- 他の人のメッセージは、開いている間、自動で出る ([端末の控えと更新](#端末の控えと更新)を見る)
- 受け取り先が未指定の人との会話も開ける。入力欄は押せず、「受け取り先が未設定です」と出す。

### 入力欄

- 会話の下に置く。本文 (必須)と送信ボタン。返信するときは、入力欄の上に返信元の引用を出す。
  - 本文は最大 1,000 字の複数行
  - 送信ボタン (強調色)は、自分と宛先の人の受け取り先があり、空白だけでない本文があるときだけ押せる
  - PC 版は、本文の欄で Ctrl+Enter を押しても送れる。Enter だけなら改行。送れない状態では、何も起きない。CLI補助の送信と同じ操作にそろえる。
- 返信は、メッセージごとの「返信」を押して始める。押すと、入力欄の上に返信元の引用が出て、「返信をやめる」で取り消せる。
- 本文の最初の入力は、空にする
  - 送った人の署名「○○より」を、本文に入れない。受け取る人には、送った人が、通知の見出しに出るため。[mmmbatch.md](mmmbatch.md) の「メッセージの送信」を見る。
  - 手で書く署名は、書き換えられて、ほかの人の名前で送れてしまう。システムが知っている送った人 (`SenderUserId`)は、偽れない。
- 本文は、フォーカスが来たら IME をオンにする (日本語の入力が多いため)
- 文字数は UTF-16 の 1 単位で数え、上限は DB の列の長さ ([database.md](database.md))と同じ (`MessageLimits`)
- 書けなかったとき (`DataFileException`)は、結果の InfoBar に理由を出す。本文は残す。
- 文言は仮 (人の一覧・入力欄・印・案内の文)

## グループ

- 参加者は全員が平等で、管理者を置かない。誰でも、人を追加でき、名前を変えられ、自分が抜けられる。
  - 他の人を外す操作を作らない。間違えて入れた人は、その人が自分で抜けるか、新しいグループを作り直す。
  - 「作った人」を区別する列を持たない。共通の列 `CreatedByUserId` を判定に使わない決まりがあり、全員が平等なら業務の列も要らないため。
- 作る入口は、人を選ぶ画面の先頭の「新しいグループ」。
  - 作る画面で、名前と参加者を決める。参加者は、人を選ぶ画面と同じ、受け取り先を指定している人から、複数選ぶ。
    - PC 版は、左の列が作る画面に替わる。名前の入力欄・選んだ人数・人数の上限の注意書き・チェックつきの人の一覧・「次へ」を並べる。上の「戻る」で、会話の一覧へ戻る。
    - Web 版は、宛先を選ぶシートの先頭の行から、全画面のシートに進む。上のバーの左に「キャンセル」、右に「次へ」を置く。「次へ」を押せない間は、理由 (「グループ名を入れてください」「参加者を選んでください」)を同じ画面に出す。
    - 自分は一覧に出さない。自分は自動で入る。
  - 名前は必須で、50 文字まで。前後の空白は取る。
  - 参加者は、自分のほかに 1 人以上で、自分を含めて 50 人まで。自分は自動で入る。
  - 決めると、空のグループの画面が開く。会話は、1 対 1 と同じく、最初の送信で作る。選んだだけでは作らない。メッセージの無い会話を、DB に残さないため。
  - 作る処理は、会話・参加者・メッセージ・通知の状態を、1 つのトランザクションで書く。
- 会話の上の行に「参加者」を置く。押すと、参加者の画面を出す。PC 版は Flyout、Web 版は全画面のシートで出す。
  - 中身は、参加者の人数と一覧・「グループ名」の入力欄と「保存」・「人を追加」・「グループを抜ける」。
  - 「グループを抜ける」は、確認を出す。題名は「グループを抜けますか？」で、本文は失うものと戻す方法を伝え、実行のボタン「抜ける」は赤にする。
  - 人を追加する画面は、人を選ぶ画面と同じ作りで、すでに入っている人を除く。
  - 1 対 1 には、この操作を出さない。1 対 1 は抜けられない。
- 追加と名前の変更の処理は、参加者であることを確かめる。人数は、会話ごとの DB の鍵 (`sp_getapplock`)のもとで数え直す。同時に追加されても、50 人を超えない。
- 抜けるときは、自分の参加者の行を論理削除する。
  - 会話は、自分の一覧から消える。抜けたあとのメッセージは、読めず、通知も届かない。
  - 抜ける前に自分宛に書かれた、送信待ちの通知は、同じトランザクションで「送らなかった」にする。読めなくなった会話の本文が、通知で届かないようにするため。
  - 最後の 1 人が抜けた会話は、誰も読めないまま残る。
  - 同じグループへまた追加されたときは、参加者の行を新しく足す。読んだ位置は 0 から始まる。
- 追加・名前の変更・抜けたことは、システムメッセージの差分で、ほかの参加者に届く。届いたメッセージの会話の要約を読み直すので、名前・参加者の一覧・読んだ位置が新しくなる。参加者の行の `UpdatedAt` は進めない。
  - 追加された人は、新しい参加者の行の `UpdatedAt` で、入った会話を知る。
- 後から入った人は、入る前のメッセージも全部読める。読める範囲を入った後に絞るかは、あとで決める。
  - 追加された人の未読の数は、会話の過去のメッセージをすべて数える。
- グループ名は、通知の見出しにも入れる。MmmBatch の通知と PC 版の通知ダイアログが、「グループ名 / 送った人」の形にする。
- 人の追加・抜けた・名前の変更は、システムメッセージとして会話に出す。決まりは [システムメッセージ](#システムメッセージ)を見る。グループの作成は出さない。最初のメッセージが始まりを表すため。

## システムメッセージ

グループの人の追加・抜けた・名前の変更を、会話の中に残す 1 通のメッセージ。

- `Message` の行で、`SenderUserId` を 0 にする。0 は、ユーザーではないことを表す値で、`UpdatedByUserId` の MmmBatch と同じ使い方。
- 本文 `Body` には、出来上がった文を入れる。文は次の 3 つ。
  - 追加: 「○○さんが△△さんを追加しました」。1 回で複数人を追加したときは、「○○さんが△△さん・□□さんを追加しました」にする。
  - 抜けた: 「○○さんが抜けました」
  - 名前の変更: 「○○さんがグループ名を『新しい名前』に変更しました」
- 名前は、その時点の表示名で固まる。あとで表示名が変わっても、過去の文は変えない。その時点の出来事の記録のため。種類と人の番号だけを持つ形にしない。DB の列が増え、PC 版と Web 版の両方に文の組み立てが要るため。
- 書くのは、追加・名前の変更・抜けたの処理と同じトランザクション。抜けるときは、自分の参加者の行を削除する前に書く。
- 画面は、吹き出しにせず、中央に小さな薄い文字で出す。時刻と「既読」と「返信」は付けない。
- 扱いは、通常のメッセージと次の点で違う。
  - `MessageDelivery` の行を書かない。通知は送らず、PC 版の通知ダイアログにも出さない。
  - 未読に数えない。会話の要約の `UnreadCount` と、ホーム画面の数字の両方で、`SenderUserId` が 1 以上のメッセージだけを数える。
  - 返信できない。サーバーは、システムメッセージを指す返信を 400 にする。
  - 一覧の最後のメッセージには出る。名前は付けず、本文だけを出す。
- 差分の取得は、通常のメッセージの 3 つの読み方では拾えない。システムメッセージには、通知の状態の行も、自分が送った行も無いため。4 つ目として、「`SenderUserId` が 0 で、基準より後に更新された行のうち、自分が参加している会話のもの」を、`Message (SenderUserId, UpdatedAt)` の索引で読む。

## 既読

送った人の画面に、相手が読んだことを出す。自分の未読の印 ([人の一覧](#人の一覧)の青い点)とは別の仕組みで、こちらは相手に見える。

- 参加者ごとに、読んだ最後のメッセージの番号 `LastReadMessageId` を、DB の `MessageConversationMember` に持つ。列は [database.md](database.md) を見る。
- 読んだ位置を書くのは、会話を開いていて、画面が見えている間に、メッセージが画面に出たとき。
  - 画面が見えているかは、PC 版は [端末の控えと更新](#端末の控えと更新)のウィンドウが見えているかと同じ決め方。Web 版は、画面が前面にあるとき。
  - 一覧に出ただけのとき・通知ダイアログや通知に出ただけのとき・トレイに隠している間は、書かない。通知を受け取っただけで、読んだことにならないため。
  - 書く値は、画面に出ているメッセージの一番大きい番号。
  - 書くのは、今の値より大きくなるときだけ。複数の端末で読む人が、順序が前後して書いても、読んだ位置が戻らないため。
  - 書くときは、サーバー側が、書く人が会話の参加者であること、番号がその会話のメッセージであることを確かめる。守れなければ、Web 版は 400 を返す。
- 読んだ位置を書くときは、同じトランザクションで、同じ会話のほかの参加者の行の `UpdatedAt` も進める。
  - ほかの参加者が、差分の取得 (自分の参加者の行の `UpdatedAt` の変わり)で、読んだ位置が変わった会話を知るため。
  - 会話の要約は、自分以外の参加者の、人の番号と読んだ位置の一覧を持つ。差分で届いた会話の要約で、控えの値を置き換える。
- 自分が送ったメッセージのうち、ほかの参加者が読んだものすべてに「既読」を付ける。読んだとは、その参加者の読んだ位置が、メッセージの番号以上のこと。
  - 1 対 1 は「既読」。
  - グループは「既読 N」。N は、そのメッセージを読んだ人数で、送った人を含めない。押すと、読んだ人の名前の一覧を出す。
  - 自分との会話には付けない。
  - 小さく薄い色の文字で、自分のメッセージの時刻の隣に出す。
  - 「既読 N」を押すと、読んだ人の名前の一覧を出す。PC 版は小さなポップアップの Flyout、Web 版は下から出るシートにする。
  - 名前は、会話の要約の `Readers` が持つ。参加者の名前と読んだ位置を、組にして持つ。
- 読んだ位置を、相手に見せない設定を持たない。会話を開いて読んだら、必ず相手に見える。
- 参加者の行は、読んだ位置が 0 から始まる。その人が会話を初めて開いたとき、画面に出た一番大きい番号になる。
- 通知ダイアログと、受け取り先の通知 (ntfy・Discord・Web 版通知)は、既読と関係しない。通知を見ただけでは、既読にならない。

## 会話の読み方

- 会話の 50 件は、`Message` を `ConversationId` で絞り、`Id` の降順で読む。次の 50 件は、読んだ中で一番小さい `Id` より小さい行。
  - ページの番号や件数で区切らない (読んでいる間に新しい行が届いても、同じ行が重ならず、抜けないため)
- 読めるのは、その会話の参加者だけ。参加者かどうかを、サーバーが `MessageConversationMember` で確かめる。
- 並びと区切りは `Id` で決める。共通ヘッダーの `CreatedAt` は、条件や索引に使わない。
- 人の一覧は、自分の `MessageConversationMember` から会話を読み、会話ごとに最新の 1 通を読んで、新しい順に並べる
- 削除された人や送信先との、過去のやり取りも残る。受け取った記録・送った記録のため。

## 1 対 1 の会話の作り方

- 相手との 1 対 1 の会話は、`MessageConversationMember` から探す。自分と相手の両方が参加者で、種類が 1 対 1 の会話。
  - 自分との会話は、参加者が自分 1 人の 1 対 1 の会話
  - 自分と相手の参加者の一覧を比べるときは、会話の数が少ないほうの人から読む
- 見つからなければ、最初の送信のときに、会話を作る。作る処理は、同じ 2 人の組ごとに、DB の鍵 (`sp_getapplock`)で順番に処理する。同時に作っても、1 つだけにするため。
  - 鍵を取ったあとで、もう一度探し、あればそれを使う
  - 鍵は、MmmTool と Web 版が同じコード (`MmmTool.Data.SqlServer`の保存先)を通して使う
- グループには、この検査をしない。メンバーが同じで名前の違うグループを、いくつでも作れるため。

## 端末の控えと更新

サーバーを唯一の正とし、端末の控えは、いつでも作り直せるものにする。

- 会話を開くと、まず端末の控えを出し、そのあと、サーバーに前回からの変更を聞いて、描き直す
  - 新しい端末や、控えが消えた端末は、前回が無いので、サーバーから最新の分をまとめて取る
- Web 版と PC 版は、差分で受け取ったメッセージを、会話の控えへ足す。会話を開く前に、控えを最新にしておくため。
  - 足すのは、控えの最後のメッセージが、前回の要約の最後のメッセージと同じ会話だけ。前回の時点で控えが最新だった証拠が、これしかないため。控えの無い会話・取りこぼした会話は、足すと途中が抜けるので足さず、開いたときに読み直す。
  - 控えの先頭より古いメッセージは足さない。開いている会話は、会話の画面が持つので、一覧の処理では書かない。
  - 会話の控えの最新が、一覧の最後のメッセージと同じなら、読み込み中の表示を出さずに、すぐ表示する。サーバーからの読み直しは、そのあとも行う。
  - 会話を開くとき、入力欄の決まり・既読の書き込み・メッセージの読み出しは、表示を待たせず、並行して行う。入力欄の決まりは、別の会話に切り替わっていないと確かめてから取り込む。
  - ページを読み直して会話を直接開いたときは、一覧の控えだけを先に戻して、会話の控えを出す。一覧のサーバーからの読み込みは待たない。ログイン切れの判定だけが、一覧の読み込みの結果を待つ。
  - 会話を開く読み込みの途中に届いたメッセージは、控えの読み込みと最新の 1 ページの取り込みで消えないよう、取り込み直す。読み込みの途中は、控えを書かない。
- 控えは、ログインしている人ごとに分けて持つ。ログアウトとアカウントの変更で、その人の控えを消す。共有の端末で、前の人のメッセージが見えないようにするため。
- 控えは、会話ごとに新しい順の 200 件 (仮)までで、新しいほうから切れ目なく持つ
  - 上へスクロールして取った、それより古いメッセージは、表示するが保存しない
  - 控えは、全部をメモリに読み込まない
- 控えが消えることは、通常の出来事として扱う (iPhone は、ホーム画面のアプリのデータを消すことがあるため)
- 通信できないときは、控えを読むだけで表示し、「最新でない可能性があります」と添える
- 保存先
  - Web 版: ブラウザの IndexedDB。`BrowserClient` と `browser.js` を通す。関数は足すだけにする。
  - PC 版: SQLite の `Cache/MessageCache.db`。消しても作り直されるデータなので、`Cache` に置く。表は [storage.md](storage.md) を見る。
- 会話の要約の控えは、読んでいないメッセージの数 `UnreadCount` と、自分以外の参加者の読んだ位置 `Readers` も持つ。
  - 控えには、形の版の番号を持たせる。欄を足したときに、番号を上げる。
  - 番号が違う古い控えは、使わずに捨てて、DB から最初に読み直す。差分の取得は、変わった会話の要約しか返さず、古い控えを使い続けると、足した欄が空のまま直らないため。
- 前回からの変更は、更新日時 `UpdatedAt` を基準にして取る。仕組みは、作業管理の他の人の更新の反映と同じで、[work-items.md](work-items.md) の「他の人の更新の反映」にある。
  - 基準は、サーバーが返した最大の更新日時。次の確認では、基準から 10 秒 (仮)戻して読む。確定が遅れた書き込みの取りこぼしを避けるため。作業管理の 60 秒より短いのは、確認の間隔が数秒で、60 秒戻すと、毎回、読み直す行が増えすぎるため。メッセージの書き込みは短いので、10 秒で確定が間に合う。
  - 同じ行が何度届いても結果が変わらないよう、番号と更新日時で突き合わせる
  - 取るのは、次の 4 つ。会話の数に関係なく、それぞれ索引 1 回で読む。システムメッセージは、4 つ目で届く。
    - 自分宛のメッセージの新着と通知の状態の変わり: `MessageDelivery (UserId, UpdatedAt)`
    - 自分が送ったメッセージの変わり: `Message (SenderUserId, UpdatedAt)`
    - 自分が新しく入った会話と、読んだ位置が変わった会話: `MessageConversationMember (UserId, UpdatedAt)`
    - 自分が参加している会話のシステムメッセージ: `Message (SenderUserId, UpdatedAt)` の `SenderUserId = 0`
  - 読んだ位置が変わった会話は、会話の要約を、自分以外の参加者の読んだ位置の一覧つきで返す。[既読](#既読)を見る。
  - MmmBatch は、通知の状態を変えても、`Message.UpdatedAt` を更新しない。画面に通知の状態を出さないため。
  - 自分が抜けた会話は、削除済みの自分の参加者の行も差分で返し、会話の番号を「抜けた会話」として返す。端末は、その会話を控えと一覧から消す。同じ会話にまた追加されたときは、新しい参加者の行が返るので、抜けた扱いにしない。
- メッセージの画面を開いている間の自動更新。人の一覧の画面でも、会話の画面でも、更新の知らせを受ける
  - 新しいメッセージは、「更新」の操作なしで出る
  - Web 版: サーバーが、数秒おきに、更新された行を調べる。全員分を 1 つの問い合わせにして、更新されたメッセージと、更新された参加者の行 (読んだ位置の変わり)から、会話の番号だけを取る。会話を開いている端末に、その会話の更新があることだけを、Server-Sent Events で知らせ、端末は差分を取る。知らせが届かないときは、前面に戻ったときの読み直しで補う。
  - Web 版の間隔は 3 秒 (仮)で、サーバーが DB を調べる間隔
  - PC 版: サーバーを通さず、PC が DB を、場面ごとの間隔で読む。間隔はどれも仮。

    | 場面 | 間隔 |
    | --- | --- |
    | 会話を開いていて、ウィンドウが見えている | 2 秒 |
    | それ以外 (アプリが動いている間) | 10 秒 |

    - 読むのは、どの場面も同じ差分の取得。間隔だけを変える。人の一覧は、読んだ結果から、端末の控えで作り直す。
    - ウィンドウが見えるようになったときと、会話を開いたときは、すぐ読む。ウィンドウが見えているかは、トレイへ隠している間や最小化している間を除いて決める
  - PC 版は、新着を、通知ダイアログ (SDK の `INotificationDialogService`)で知らせる
    - 出すのは、他の人から届いた新着で、いま前面で開いている会話以外のもの。前面で見ている会話の新着は、ダイアログに出さない。
    - 節の送り元のキーは `message`、並びの値は、サイドバーの並びと同じ 5。項目は、送った人の名前と、本文の 1 行目。グループは、名前を「グループ名 / 送った人の名前」にする。押すと、その会話を開く。
    - 出すのは、アプリを起動してから届いた新着だけ。アプリを閉じている間に届いたものは、出さない。ダイアログに出したことは、DB に記録しない。
    - 受け取り先が ntfy や Discord の人も、PC のダイアログが出る。ダイアログは PC のアプリだけのもので、受け取り先とは関係しない。
    - 「メッセージの通知を受け取る」がオフの人には、ダイアログも出さない

## 送るときの動き

- 押すと、先に、自分と宛先の人の受け取り先があることを確かめる。無ければ、何も書かず、理由を結果に出す。
- あれば、次を 1 つのトランザクションで書く
  - 相手との 1 対 1 の会話 (なければ作る)に、`Message` の行。送った人は今のユーザー。本文は前後の空白を取る。
  - 送った人以外の参加者ごとに、`MessageDelivery` の行。状態は送信待ち・試した回数は 0。自分との会話は、自分に 1 行。
- 同じ内容を続けて送っても、別の行にする (一意制約を付けない)
  - 1 回の送信の操作が 1 通
- 押した直後にもう一度押されても、2 通送らない
- 書けたら、本文を空に戻す。会話の末尾に現れる。成功の帯は出さない。
- 通知が届いたかは、画面に出さない。失敗の理由は、MmmBatch のログで見る。
  - MmmBatch が長く止まっていたあとの起動でも、送信待ちの行は古さにかかわらず送る

## DB モードだけ

- `FeatureInfo.AvailableWhen` ([SDK の architecture.md](../../external/MmmSdk/docs/architecture.md))で、メッセージの保存先が使えない (`IsAvailable` が false = ローカルモード)ときは、機能そのものを無いものとして扱う。サイドバー・設定ページの「機能」の一覧のどれにも出ない。
- 機能のオン・オフは既定でオン
  - 設定ファイルに `Feature.Messages.Enabled` が残っていても、ローカルモードでは効かない
  - 詳細は [settings.md](settings.md)
- 設定ページの「送信先」(送信先の登録の画面を開く)も、DB モードのときだけ出す
