# リマインダー

リマインダー機能の仕様。

## 概要

- 指定した日時 (または曜日・時刻)に通知し、今日の分を一覧して対応状態 (未・スヌーズ・完了)を管理する
- データと監視、入力画面、一覧画面、メイン画面、設定 (スヌーズ間隔)からなる
- 場所は `src/Plugins/MmmTool.Reminders/` で、中は `Main/`・`Input/`・`BulkInput/`・`List/` に分けている。Core 側は `src/Plugins/MmmTool.Reminders.Core/`。

## データ

- `Data/Reminders.json` / `Data/ReminderStates.json`: どちらも `{ "items": [...] }`(ラッパー型は `Json/ReminderFile.cs`・`Json/ReminderStateFile.cs` の internal)
- `Reminder` は record (複製しやすいため)
  - `No`: 番号で、登録順の一意の連番 (状態の `BaseNo` が指すキーで、0 は未採番)
  - `IsDeleted`
  - `Date`: yyyyMMdd (曜日指定は `NoDate` = 99999999)
  - `Time`: HHmm
  - `Weekdays`
  - `Title`・`Note`・`Link`
  - `IsSpeak`: 通知のときに読み上げるか (この項目が無い既存の JSON は false)
  - `TargetUserId`: 宛先のユーザー番号 (0 は全員宛て)
    - DB モードだけで使い、ローカルモードでは常に 0
    - 0 のときは JSON に書かない (`Reminder` に `[JsonIgnore(WhenWritingDefault)]` を付けて、ローカルモードの既存の JSON を変えないようにする)
    - この項目が無い既存の JSON は 0 で読み込む
- 値は作ったあとに書き換えず、`with` で新しく作る (`init`)
- `ReminderState`: `Seq`・`BaseNo`・`Date`・`Status`
- `Weekdays` は `[Flags]` (月 = 1 … 日 = 64)
- `ReminderStatus` は None = 0 / Done = 1 / Snooze = 2
- Weekdays と ReminderStatus は、JSON には数値で入る
- 変換は `ReminderDates`(`DateOnly` / `TimeOnly` / `DayOfWeek` との相互変換、`ToJapanese` で「月火水」、`DescribeWeekdays` で画面に出す曜日の文字列＝曜日が 1 つも無ければ「毎日」)
- 発動の判定は `ReminderDates.OccursOn(Reminder, DateOnly)`
  - 発動日が今日、または曜日指定で今日の曜日を含む
  - 曜日が 1 つも無い曜日指定は毎日
  - 監視とメイン画面で共通に使う

## 保存先 (`IReminderRepository`)

- 1 件単位の操作で書く (一覧を丸ごと置き換えない)
  - 書き: `AddAsync`・`UpdateAsync`・`SetDeletedAsync`(論理削除の切り替え)・`PurgeAsync`(物理削除)・`SetStatesAsync`(対応状態のまとめ書き)
  - 読み: `GetRemindersAsync(includeDeleted)`・`GetStatesAsync`
- 番号 (`Reminder.No`)と対応状態の連番 (`ReminderState.Seq`)は、保存先が決める
  - `AddAsync` は `No` を無視し、番号つきの内容を返す
  - JSON は、ロックの中で「最大 + 1」を計算する
  - SQL Server は IDENTITY かトランザクション内の最大 + 1 (一意制約と再試行)
  - DynamoDB はカウンター項目の原子的な加算
  - 型は `int` のまま (人が登録する件数で、`int` の範囲を超えないため)
    - DB 側も `int` の IDENTITY で足りる
- `PurgeAsync` は対応状態も一緒に消す
  - 残すと、最大の番号を消したあとの新規作成で同じ番号が採番されたとき、前の状態を引き継ぐため
  - JSON は状態のファイルを先に書く (途中で失敗しても、状態が残るだけの側に倒す)
- 読み書きはスレッドセーフ。返す値は `init` の record なので、複製しない。
- 保存先は、次の 2 つを持つ
  - 今のユーザーの番号 (`CurrentUserId`): ローカルモードは 0
  - 完全削除ができるか (`CanPurge`): JSON は true、DB は false
    - false のとき `PurgeAsync` は `NotSupportedException` を投げ、画面は、完全削除の操作を出さない
- `ReminderService.GetTargetsAsync` (通知・今日の対象)は、宛先が 0 (全員宛て)か自分のものだけに絞る
- 一覧 (`GetRemindersAsync`)は、保存先が見せるものを、そのまま返す (DB は、自分が作成したほかの人宛てを含む)
- 保存先の外での変更 (ほかの PC など)は、`ExternalChanged` で知らせる
  - `ReminderService` が受けて、自分の書き込みと同じ `Changed` として画面・監視に伝える
  - JSON は 1 つの PC だけなので、発火しない
  - DB (SQL Server)の保存先の動きは [database.md](database.md) の「Repository の動き」
- JSON 実装 (`JsonReminderRepository`)
  - 最初のアクセスで両ファイルを読んでメモリに持ち、`SemaphoreSlim` で順番に読み書きする
  - 書き込みは、変更後のコピーをファイルに書き、成功してからメモリを差し替える (保存に失敗しても、メモリだけが新しい状態にならない)
- IO エラーで読めなかったときは、空として扱い `LoadError` に残す
  - 書き込みは `DataFileException`(元データを消さないため)
  - 読み込み結果は SDK の `LoadStatus` で持つ
  - ファイル固有の仕組みなので、保存先の中に閉じる。ファイルを使わない保存先は、`LoadError` / `RecoveryMessage` を常に null にする。

## サービス (`ReminderService`、Singleton)

- 保存先の 1 件単位の操作に、業務の決まりを載せる
  - 一覧は持たず、そのつど保存先から読む (排他・採番・読み込みの失敗の扱いは保存先の仕事)
- 保存: `No` が 0 なら追加 (`AddAsync`)
  - 既存は同じ `No` を更新し、削除フラグを解除する
  - 無い `No` は `ArgumentException`
- 論理削除は `DeleteAsync`、物理削除は `PurgeAsync`
- 状態は `BaseNo` ごとに 1 件で上書きする (`SetStateAsync`)
  - 複数件は `SetStatesAsync` で 1 回の書き込み
- 変更後に `Changed` を発火する (任意のスレッドから)
- `LoadError` / `RecoveryMessage` は保存先のものを返す (最初に読んだあとに分かる)
- 時刻 (`HHmm` の整数)が正しくないリマインダーは、「常に発動済み」のように誤って動かないよう、`GetTargetsAsync`(今日の対象・通知)から外す
  - 正しくない例は、手で編集した JSON の負の値・25 時など
  - 本体は消さない (一覧には出て、編集して直せる)
  - 読むたびに調べ、あれば番号を挙げた警告を `TimeWarning`(`RecoveryMessage` とは別)に持つ
  - 警告は、画面の InfoBar で、退避のメッセージと一緒に知らせる
- `GetTargetsAsync(now)`: ある日の対象 (その日に発生するリマインダー)と、その日の対応状態 (`ReminderTarget`)を、時刻 → `No` の順で返す
  - メイン画面と通知 (`ReminderMonitor`)の両方がこれを使うので、「今日の状態」の組み立てはここだけ

## 監視 (`ReminderMonitor`、Singleton)

- 役割分担
  - タイマーの管理は SDK の `MinuteScheduler`(毎分 00 秒の単発タイマーの掛け直し・同じ分に 2 回呼ばない)
  - 通知する項目の判定は `ReminderEvaluator`(時刻・タイマー・設定に依存しない純粋な判定)
  - `ReminderMonitor` はそれらをつなぎ、スヌーズの通知時刻を覚える
  - スヌーズ間隔は `ReminderSettingsService` から読む (設定ストアに直接触れない)
- 起動時の準備 `ReminderStartup`(`IStartupTask`)で `Start(コールバック)` を呼ぶ
  - コールバックは `DispatcherQueue` で UI スレッドへ移し、`INotificationDialogService.Show(節)` を呼ぶ
    - 節は、送り元 `Reminders`・並びの値 4 (ノートの 2 の下)の `NotificationSection`
    - 通知の窓は 1 枚で、ノートの節など、ほかの機能の節と同じ窓に並ぶ。リマインダーが通知しても、リマインダーの節だけが入れ替わる ([通知ダイアログ](../../external/MmmSdk/docs/notification-dialog.md))
  - Host の破棄で停止する
- `TimeProvider` の単発タイマー: 開始直後に 1 回、以後は毎分 00 秒に判定する
  - 次の 00 秒までの時間をその都度計算して掛け直す (早く来て同じ分になったら、判定せず掛け直すだけ)
- 対象は、発動する日で、時刻が来たもの (`GetTargetsAsync` の結果のうち、時刻が過ぎたもの)
  - 並びは時刻 → `No`
- 今日の日付の状態だけを見る (別の日の状態は None 扱い)
  - None: 毎分通知する
  - Done: 通知しない
  - Snooze: 「モニター全体で共有する前回のスヌーズ分の通知」から間隔以上たったら通知する
    - 前回の通知時刻は、メモリ上だけで持つ
    - 起動直後の 1 回目は前回が無いので通知する
- スヌーズ間隔は設定ストアの `Reminder.SnoozeIntervalMinutes` を毎回読む
  - 既定は 15、範囲は 5〜999
  - キー・定数・補正は `ReminderSettingsService` に集約している
- 1 回の判定の対象は 1 つの通知にまとめる
  - タイトルは「リマインダー」
  - 本文は 1 件ごとに、件名 (リンクがあればリンク先つき)と、その下に備考 (あれば、字下げして左に細い線を付け、小さく薄い字で、改行のまま)を出す
- 読み上げ: 通知する項目のうち `IsSpeak` が true のものを読む
  - 読む内容は「件名。備考。」(備考が無ければ「件名。」)で、2 件目からは前に「続いて。」をつなげる
  - 判定結果は `ReminderEvaluation.SpeechText` で、対象が無ければ null
  - 通知のたびに読む (未対応は毎分、スヌーズは間隔ごとで、通知の出方と同じ)
  - `ReminderStartup` が、コールバックで通知ダイアログを出した直後に、SDK の `ISpeechService.SpeakAsync` を呼ぶ (仕組みは [speech.md](../../external/MmmSdk/docs/speech.md))
  - 前の読み上げが続いていれば止めて、新しいほうを読む
  - 旧アプリ (MSchedule)の読み上げと同じ動き (ユーザーの決定)
  - リマインダーごとの `IsSpeak` で選べるのは、全体のオン・オフだと全部読むか全部読まないかになり、未対応を毎分読む動きがうるさくなるため
  - 通知のたびに読むのは、気づくまで繰り返す通知の目的に合わせ、通知ダイアログの出方と読み上げの回数をそろえるため
  - 備考を通知の本文にも出すのは、声で聞き逃した備考を画面で確かめられるようにするため
  - 備考を件名の横に「件名 (備考)」とつなげない (通知ダイアログは縦に余白があり、改行つきの備考が 1 行に潰れて読みにくいため)
- 読み上げは通知ダイアログの部品に混ぜず、SDK の別の部品 (`ISpeechService`)にし、通知を出すアプリ側が通知の隣で呼ぶ (声を通知以外の機能からも使えるようにするため)
  - 無音を流して音声機器が眠るのを防ぐ仕組みは別の機能なので、ここには入れない ([settings.md](settings.md)の「音声機器を起こしておく」)
- 判定中の想定外の例外は握りつぶさない (`async void` なので未処理例外になる)
- `SnoozeTriggeredAsync`: 発動済みで今日の状態が None のものを Snooze にし、モニターのスヌーズ間隔をその分から数え直す
  - 数え直さないと、次の分にすぐ再通知される
  - 対象の状態は、`SetStatesAsync` で 1 回の書き込みにまとめる
  - 通知をクリックしてメイン画面を開いたときに呼ぶ
  - 行で手動でスヌーズにしたときは数え直さない

## 擬似モーダル

- 一覧・入力画面・確認ダイアログは、開いている間、親を操作できない擬似モーダルにする
- WinUI 3 のウィンドウには標準のモーダル表示が無い
- `OverlappedPresenter.IsModal = true` は、親を操作できてしまうので使わない
- モーダルらしく見えて動けば、やり方は問わないので、SDK の `PseudoModal` で実現する
- SDK の `PseudoModal`(`MmmSdk.WinUI.Components.Windowing`)を使う
  - ウィンドウに付ける部品。詳細は SDK の `docs/dialogs.md`。
  - `SetOwner`(`GWLP_HWNDPARENT`)で親を設定し、表示したら `EnableWindow(親, false)` で親を操作不可にし、閉じる前に戻して親を前面に出す
  - コードから閉じるときは `PseudoModal.Close()` を `Close()` の前に呼ぶ
  - × / Alt+F4 は `AppWindow.Closing`、念のため `Closed` でも戻す。自分が消える前に戻さないと、別のアプリが前面に来る。
- 親の中央に出し、作業領域からはみ出す分は内側へ寄せる (`CenterOnOwner`)
  - 重ねてよい (メイン → 一覧 → 入力画面 / 確認)
- 親は SDK の `IDialogHost`(実装は `DialogService`)が決める
  - 最後にアクティブになったウィンドウを親にする
    - `TrackWindow` で覚えたメインウィンドウ・リマインダーのメイン画面と、開いているモーダルウィンドウが対象
    - 別のウィンドウでモーダルが開いていても、操作したほうの上に出る
  - まだアクティブになっていないときは、いちばん手前のモーダル
  - 確認ダイアログ (`ContentDialog`)・作業ディレクトリ変更ダイアログも同じ親の `XamlRoot` に出す

## 入力画面 (`ReminderInputWindow` ＋ `ReminderInputViewModel`)

- 開くのは `IReminderDialogService.ShowInputAsync(対象 or null, copySourceNo)`
  - 保存した内容 or null (キャンセル)を返す
  - `No` が 0 の内容を渡すと、それを初期値にした新規 (コピーして新規追加)になる
  - このとき `copySourceNo` にコピー元の連番を渡すと、その送信先を引き継ぐ
- 独立したウィンドウ (Mica・開くたびに DI から作る Transient)
  - 擬似モーダルで、`OverlappedPresenter.CreateForDialog()` を使う
- 幅 480 固定。高さは読み込み時に中身を測って固定する。
  - 日付指定・曜日指定の欄は高いほうの高さを確保し、件名のエラー行も場所を空けておく
  - 切り替えやエラーで下の欄・ボタンが動かないようにするため
- タイトル帯 (`SetTitleBar`)をドラッグして移動できる。× はキャンセルと同じで、確認なし。Esc / Enter のショートカットは付けない。
- タイトル: 新規は「リマインダー入力」、採番済みは「リマインダー編集」
- 初期値
  - 新規は曜日指定 (「日付を指定する」はオフ)・曜日は未選択・日付欄は今日・時刻は現在時刻・「通知を読み上げる」はオフ・ほかは空
  - 編集は対象の値 (曜日指定なら日付欄は今日)
- 曜日を 1 つも選ばない曜日指定は、毎日通知する
- 時刻は SDK の `MmmSdk.WinUI.Controls.TimeInputBox` (自作)で入力する
  - `TimePicker` は、ドラムの「適用」と画面の「OK」が両方目立って押し間違えやすく、ドラムでの操作も使いにくいので使わない
  - `NumberBox` を 2 つ並べると、▲▼ と ✕ でごちゃごちゃし、欄が 2 つに分かれて見た目もよくないので使わない
  - そのため、1 つの枠に「時 : 分」の 2 区画を持たせ、ボタンは置かない
  - 動き: 数字だけ・2 桁打つと分へ・←→ で区画移動・↑↓ / ホイールで ±1 (端で回る)・フォーカスで全選択と IME オフ・離れたときに確定 (空なら元の値・範囲外は最大値)・常に 2 桁表示
  - 区画は枠・消去ボタンを持たない最小テンプレートの `TextBox`
  - 外側の枠が、標準の入力欄の見た目 (ポインタ上・フォーカス中の背景とアクセントの下線)を受け持つ
- 日付は `CalendarDatePicker`(選択中の日付を押して空になったら元に戻す)
- 件名は前後の空白を除いて、空ならエラー (件名欄の下に赤字で出し、件名を変えたら消す)
- 文字数の上限は、件名 200・備考 1,000・リンク 2,000 (`ReminderLimits` が持ち、`TextBox.MaxLength` に使う)
  - 上限に達すると、それ以上は入力できない (メッセージは出さない)
  - 数え方は UTF-16 の 1 単位 (絵文字は 2)で、DB の列の長さ ([database.md](database.md))と同じ
  - 上限は、保存先 (JSON・DB)に関係なく付ける
- 保存の失敗 (読み込み失敗中・IO エラー・編集中に対象が完全削除)は、上部の InfoBar で知らせて閉じない
- 「宛先」の `ComboBox` を、「通知を読み上げる」の下に置く
  - 今のユーザーを特定済み (DB モード)のときだけ出し、ローカルモードでは出さない (宛先は 0 のまま)
  - 選択肢は「自分」(新規の既定)・「全員」・ほかの使えるユーザー
  - 編集は保存されている宛先
  - 詳細は [database.md](database.md) の「画面」
- 「送信先」のチェックのリストを、「宛先」の下に置く
  - 複数選べる。何も選ばなければ送信先なし。
  - 登録名と種類 (例: リマインダー (ntfy))で出す
  - 枠つきの一覧で、高さは 3 行ぶんで固定。4 個以上のときは、一覧の中だけスクロールする。
  - 一覧は `ReminderChannelPicker` で、まとめて追加と共有する
    - ウィンドウは固定サイズで、高さを送信先の数で変えない。外側にスクロールを付けない。
    - 送信先が増えても高さを伸ばさない (画面の高さが足りない PC で、OK ボタンが切れるため)
  - 1 つも無いときは、一覧の枠の中に「送信先が登録されていません。」を出す
  - DB モードで、送信先を読み込めたときだけ出す
  - 送信先を選んで保存するたびに、送信設定を書き直す (更新日時を保存した時刻にして、MmmBatch が、保存した時点で過ぎている今日の分を送らないようにする)
  - 選択肢は、自分が登録した送信先だけ
    - ほかの人の送信先は、出さず、保存でも足さず・外さない (全員宛てのリマインダーに、複数の人が送信先を付けても、お互いの設定が消えない)
  - 保存したあとに、送信設定を保存する (失敗したときは、画面を閉じずにエラーを出し、保存し直しても、リマインダーを重ねて作らない)
  - 送る処理は MmmTool に無い ([mmmbatch.md](mmmbatch.md))
- 「通知を読み上げる」の `ToggleSwitch` を、リンクの下に置く
  - 「日付を指定する」と同じ作り
  - 読み上げの内容と回数は、上の「監視」
- IME: 件名・備考はフォーカスでオン、リンクはオフ (SDK の `ImeControl.TurnOn/TurnOff`)
- 保存しても、今日の対応状態はそのまま

## まとめて追加 (`ReminderBulkInputWindow` ＋ `ReminderBulkInputViewModel`)

- 時刻の表でマスを選ぶだけで、その日の会議を、日付指定のリマインダーとして、まとめて登録する
  - 件数が増えても、手数が増えないため。1 件ずつ入力画面を開くと、件数に比例して手数が増え、「日付を指定する」を忘れると毎日鳴る。
  - 時刻を文字で打たせる形にしない (使う人は、会議の時刻を頭の中で知っているだけで、書き方を覚える手間が、そのまま負担になるため)
- 場所は `src/Plugins/MmmTool.Reminders/BulkInput/`
  - 開始時刻から、鳴らす時刻・件名・リマインダーを作る処理は、画面に依存しないので、Core の `ReminderDraft` に置く
  - Web 版のリマインダー画面でも使うため
- 開くのは `IReminderDialogService.ShowBulkInputAsync()`で、登録した件数を返す (キャンセルは 0)
  - メイン画面の操作の列と、一覧の操作の列に、「まとめて追加」を置く
  - 入力画面と同じ作りの、独立した擬似モーダルのウィンドウ
  - 大きさは 960×640 DIP で固定する (サイズ変更できないのは、ユーザーが選んだ)
    - 幅は、3 列を置き、右の行に時刻・件名・リンクの 3 つを並べるため
    - 高さは、時刻の表に 9 行ほどが見えるため
- 画面は、3 列と下の「登録」「キャンセル」
  - 左の列は、全部の会議に付ける設定を縦に積む。上から、日付・何分前に通知・通知を読み上げる・送信先。
    - 全部の会議に効く設定は、影響の範囲が広いので、先に見える左に置く
    - 常に見えるので、各行に「何分前に通知」の文は出さない
  - 中の列は時刻の表、右の列は選んだ会議の一覧
  - 日付の初期値は今日
- 左の時刻の表は、縦が 0〜23 時の 24 行、横が `:00` と `:30` の 2 列で、マスはチェックボックス
  - 30 分刻み、0〜23 時は、ユーザーが選んだ範囲と刻み
  - 見出しは固定で、行だけが縦にスクロールする。1 行は 32 DIP。
  - 開いたとき、今の時刻に一番近い 30 分刻みの時刻の時の行を、表の上端に置く
    - これから入れる会議は先の時刻なので、先の行が多く見えるようにするため
    - 位置を決めるのは、開いた最初の 1 回だけ。日付を変えても動かさない。
  - 今日の過ぎた時刻のマスも選べる。登録すると、すぐ通知が出る (ユーザーが決めた)
- 右の一覧は、マスを選ぶと 1 件増え、選びを外すと減る
  - マスを選んだ時点で、時刻の順になる位置に入る。時刻を直した行は、直している最中に動かないよう、その場に残す。
  - 各行で、時刻 (`TimeInputBox`)・件名・リンクを直せる。直さなければ、そのまま登録する。
  - 時刻を直しても、結びついたマスは変わらない。マスの選びを外すと、その行が消える。
  - 一覧の見出しは、追加する件数を出す
  - 行が増えたとき、件名には「会議」が入っている。空にしても、「会議」で登録する。
  - 件名は、開始時刻を足しても入るよう、188 文字まで (`ReminderDraft.TitleMaxLength`)
- 「何分前に通知」は、ちょうど・3 分前・5 分前・10 分前・15 分前で、初期値は 5 分前 (`ReminderBulkLead`)
  - 前に通知するときは、鳴らす時刻を前へずらし、件名の後ろに ` (10:00 開始)` を足す。DB の列を増やさないため、本当の開始時刻を件名に残す。
  - 0 時より前になるときは 0 時にする。前の日には回さない。
- 左の列の「通知を読み上げる」と「送信先」は、全部の会議に同じ内容を付ける
  - 「通知を読み上げる」は、入力画面と同じ `ToggleSwitch`
  - 「送信先」は、DB モードで、送信先を読み込めたときだけ出す。何も選ばなければ送信先なし。
    - どこへ送るかが開かなくても分かるよう、チェックの一覧を常に見せる。ボタンで開く枠にしない。ユーザーが「どこ送信か一目でわかるようにしたい」と決めた。
    - 一覧は、入力画面と同じ `ReminderChannelPicker` で、左の列の残りの高さいっぱいに伸びる。入れる数が増えても、一覧の中だけがスクロールする。
    - 選べるのは、入力画面と同じ、自分が登録した送信先だけ。選択肢は `ReminderChannelLoader` が作る。
    - 一覧の各行では選ばせない (毎回同じ送信先を、行ごとに選び直す手間になるため)
    - 送信設定は、リマインダーを 1 件登録するたびに書く。送る処理は MmmTool に無い ([mmmbatch.md](mmmbatch.md))
- 「何分前に通知」「通知を読み上げる」「送信先」は、選びを変えるたびに保存して、次に開いたときの初期値にする
  - 毎回選び直す手間を省くため
  - 登録しないで閉じても残る。登録のときだけ保存する形にしない。
  - 保存先とキーは [storage.md](storage.md) の「AppSettings.json のキー」。送信先の番号は、そのときの DB に無いものは、チェックを入れない。
  - 設定を保存できない状態でも、登録は止めない
- 同じ日付・時刻・件名のリマインダーが、すでにあるとき、一覧に同じものが重なるときは、その行を追加しない
  - 一覧の行の下に出す。登録の直前に、すでにあるリマインダーを読み直して調べる。
  - 途中で保存に失敗して押し直しても、登録済みの分を重ねないため
- 鳴らす時刻がすでに過ぎている行は、行の下に「すぐに通知する」と出す。登録は止めない。
- 登録するリマインダー
  - 日付指定で、読み上げは上の欄の選びのとおり
  - 宛先は自分 (ローカルモードは 0)
  - 備考は空
  - 時刻の順に登録する
- 登録の失敗は、上部の InfoBar で知らせて閉じない

## 一覧画面 (`ReminderListControl` ＋ `ReminderListViewModel`。置き場は `ReminderListPage` と `ReminderListWindow`)

- 一覧の中身 (操作行・見出しつきの一覧・エラー)は UserControl の `ReminderListControl`(`List/`)で、ページとウィンドウが共有する
  - タイトル・外側の余白・読み込みは、置く側が受け持つ
  - 最終形: リマインダーを単体のアプリにしたとき、サイドバーが無くても、ウィンドウで一覧を開ける (ユーザーの決定)
  - 分けるのは枠だけで、見た目は別にしない
- サイドバーの「リマインダー」(`ReminderListPage`)は、アプリの本体の画面
  - 常にオンの機能なのでキー無し・並び順の値 2・アイコン Segoe Fluent の Calendar `E787`
  - 見出し (`TitleTextBlockStyle`)と余白 (24,16,24,24)はリンクのページと同じ
  - ページは作ったあと使い回されるので、表示のたびに読み直す (`Loaded`)
  - 「過去の予定を表示」「削除済みを表示」の状態は、ページを切り替えても残る
  - 最初の読み込みが済むまで一覧を隠す
- ウィンドウ (`ReminderListWindow`)の開き方は次のとおり
  - 常にモーダル (2 枚目は開けない)
  - Transient で、閉じたら `Dispose` で `ReminderService.Changed` の購読をやめる
  - 開くたびに DI のスコープ (`IServiceScopeFactory`)を作り、そこから画面・ViewModel を解決して、閉じたらスコープごと破棄する
    - ルートから解決した `IDisposable` の Transient は、アプリの終了まで DI コンテナが保持し続けるため
    - メイン画面・入力画面も同じ
- Mica・タイトル帯でドラッグ。大きさは変えられる。
  - 最初は 760×560、最小は 560×360 DIP
  - 最大化・最小化なし
- 上に「新規追加」 (Accent)を置く
- 右に「過去の予定を表示」「削除済みを表示」の `ToggleSwitch` を置く
  - どちらも既定オフ
  - 状態は保存しない
  - 「過去の予定」をオフにすると、日付が昨日以前の日付指定を隠す
    - 今日の分は時刻が過ぎていても出す
    - 過去日が日付順で一番上に並んで邪魔になるため
    - 並び替えで下へ回す案は採らない
- 下にカード状の一覧を置く
  - 見出しは固定で、行だけスクロールする
  - 列は 日付 120 / 曜日 120 / 時刻 80 / 件名 / 備考
    - 件名と備考は、残りを 2 対 3 に分ける
    - どちらも、はみ出したら省略記号にする
  - 備考は、改行を空白にして 1 行で出す (行の高さを行ごとに変えないため)
    - カーソルを合わせると、ツールチップに備考の全文を、改行のまま出す
    - 備考が無い行は、備考の欄を隠す (空のツールチップを出さないため)
    - 件名の横のメモのアイコンは出さない (備考の列があり、重複するため)
  - 日付は `yyyy/MM/dd` か「－」
  - 曜日は「月火水」。日付指定の曜日は「－」。
  - 曜日を選んでいない曜日指定は「毎日」 (日付・曜日とも「－」だと区別できないため)
  - 並びは 日付 → 時刻 → 番号 (曜日指定は `NoDate` なので後ろ)
  - 削除済みは不透明度 0.5 + 取り消し線
- 行のダブルタップで編集
- 右クリック (メニューキー)は、その行を選択してからメニューを出す (リンクのツリーと同じく、`AddHandler(..., handledEventsToo: true)` で `RightTapped` と `ContextRequested` を受ける)
- 右クリックのメニュー
  - 削除済みでない行は「編集 / コピーして新規追加 / 削除」
  - 削除済みの行は「編集 / コピーして新規追加 / 完全削除」
  - 削除済みの行の編集は、「保存すると削除が取り消される」確認 (キャンセルが既定)をしてから開く
  - 論理削除・完全削除とも確認あり (メイン画面と同じ)
    - 確認の文は「「件名」を削除しますか？」
  - 「削除」は、見えるリマインダーすべてに出す (編集と同じで、確認ダイアログあり)
    - DB モードの条件は、[database.md](database.md) の「見え方」
  - 「完全削除」は、保存先が対応しているときだけ出す (`ReminderService.CanPurge`)
  - コピーして新規追加は、日付・時刻・曜日・件名・備考・リンク・読み上げの有無・宛先を引き継ぐ (番号・削除フラグは引き継がず、元は変えない)
    - DB モードで送信先の欄が出るときは、元に付いていた送信先のうち、自分が登録したものにチェックを入れて開く (ほかの人の送信先は出さないので引き継がない)
    - 引き継ぐ送信先は、`ShowInputAsync` の `copySourceNo` (元の連番)で読む
- メニュー項目は画面の外に出て DataContext が来ないので、行を `Tag="{x:Bind}"` で渡す
- 変更 (`Changed`)は、ViewModel を作ったスレッドの `SynchronizationContext` に戻して読み直し、変わった行だけ差し替える (全部作り直すとスクロールが先頭へ戻るため)
- エラー (読み込み失敗・壊れたファイルの退避・保存の失敗)は、一覧の上に重ねる InfoBar で知らせる (閉じたら消える)
- 空の一覧が一瞬見えないよう、読み込んでから表示する (ウィンドウは読み込んでから出し、ページは読み込みが済むまで隠す)

## メイン画面 (`ReminderMainWindow` ＋ `ReminderMainViewModel`)

- 開くのは `ReminderWindowService`(Singleton)
  - 1 枚だけ持ち、開いていれば前面に出す
  - 読み込み中の 2 回目の呼び出しは、表示し終わるのを待つ
  - 通知ダイアログからも、トレイのメニューからも、このサービスで開く
    - 前面に出すのは SDK の `BringToFront`
    - 別の仮想デスクトップ (Win+Tab のデスクトップ)に画面が残っていたら、いま見ているデスクトップへ移してから出す
    - 移さずに前面にすると、Windows が画面のあるデスクトップへ切り替えるため
  - いま見ているデスクトップは、レジストリ `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\VirtualDesktops` の `CurrentVirtualDesktop` (エクスプローラーが切り替えのたびに書く 16 バイトの GUID)で調べる
    - 前面のウィンドウで調べる方法は、補助にとどめる
    - トレイのメニューの直後に前面が非表示の内部ウィンドウになり、デスクトップを調べられないため
  - 読み込みの失敗 (ファイルを読めない等)は保存先が受けて `LoadError` に残す (空として続け、画面の InfoBar に出す)ので、ここまでは例外にならない
  - 画面を作る・表示するのが失敗したとき (バグ)は、作りかけの画面を閉じ、失敗した結果を残さず、例外はそのまま呼び出し元へ渡す
    - 失敗した結果を残さないのは、次の呼び出しで作り直せるようにするため
- トレイメニューの「リマインダー」 (`ReminderTrayMenuSource`)と、通知の本文クリックから開く
  - トレイメニューでの位置は、リンクより上、メッセージ送信より下
- モーダルではない普通のウィンドウ
  - × は普通に閉じる (トレイへの退避ではない)
  - Mica・タイトル帯でドラッグ
- 位置と大きさは変えられ、変更から 1 秒後に保存して、次に開くとき復元する
  - 保存には SDK の `WindowBoundsKeeper.Attach` を使い、キーは `ReminderMainWindow`
  - 保存が無い・画面外のときは、最初の大きさ (360×440 DIP で、DPI に合わせる)で、主モニターの作業領域の右下 (端から 16 DIP)に出す
  - 最小 360×320 DIP、最大化・最小化なし
  - 最小の大きさの倍率は、位置を復元してから `GetDpiForWindow` で求める
  - 位置を保存して復元するのは、トレイや通知から何度も開く常駐の画面で、開くたびに中央へ戻るより、置いた場所に出るほうが使いやすいため (メインウィンドウと同じ仕組みで、ユーザーの決定)
  - 初めての位置を右下にするのは、タスクトレイの近くに出て、トレイから開く画面に合い、通知ダイアログの初期位置ともそろうため (ユーザーの決定)
    - タスクトレイの近くに出るのは、Windows 11 のカレンダー・クイック設定と同じ
- 今日の対象を、時刻 → `No` の順に表示する
  - 未対応 (未・スヌーズ)を上、完了を下の `Expander` に出す
  - `Expander` は既定は閉じる。完了が 1 件以上のときだけ「完了 (件数)」として出す。
  - 0 件のときは「今日のリマインダーはありません。」
- 寸法 (余白・行の高さ・角丸など)は XAML を見る
- 状態の切り替えの各ボタンの暗黙スタイルには、`BasedOn` を付けない (ライブラリのキーを参照できない恐れがあるため)
- 行はカード
  - 状態の縦線 (幅 6・角丸 3)
    - 色は固定で、未 `#9E9E9E` / スヌーズ `#F59E0B` / 完了 `#16A34A`
    - 完了の緑は、濃い緑 (`#2E7D32` など)だとダークテーマで沈むため、明るいエメラルド系にしている
  - 時刻 (15 SemiBold)
  - 備考のアイコン: 備考があるときだけ、件名と状態の切り替えの間にメモのアイコン (`E70B`)を出す
    - カーソルを合わせると、ツールチップに備考の全文を、改行のまま出す
    - 件名のリンクを押す範囲 (`LinkArea`)の外に置く (アイコンを押してリンクが開かないようにするため)
    - 備考を行の下に常時出さない (行の高さが行ごとに変わり、一覧が長くなるため)
  - 件名 (13 SemiBold): SDK の `LinkArea`(`MmmSdk.WinUI.Controls` の Grid 派生)
    - リンクがあると手のカーソル + ホバー背景で、押すと開く
    - 完了は取り消し線 + 不透明度 0.5
  - 状態の切り替え: CommunityToolkit の `Segmented`(NuGet `CommunityToolkit.WinUI.Controls.Segmented`)を `StatusIndex` と双方向でつなぐ
    - ユーザーが変えたときだけ `SetStateAsync` を呼び、読み直しの反映では保存しない
- 右クリック: リンクを開く (リンクのある行だけ有効)/ 編集 / コピーして新規追加 / 削除
  - コピーして新規追加と削除は、一覧と同じ
  - 削除は論理削除で、確認あり
- 変更は差分更新する (`No` で同定・不足は挿入・余剰は削除・順番は `Move`)
  - 完了の欄の開閉を保つため
  - 行は `ReminderTodayItem`(読み直しでは `Apply` で中身だけを差し替える)
- 日付が変わったら新しい日に切り替える
  - 毎分、今の日付と、画面に出している一覧の日付を比べ、違っていたら読み直す
  - 「次の 0 時まであと何時間」の予約はしない (スタンバイや時計の変更でずれ、日付が変わったことに気づけないため)
  - メイン画面・一覧画面の共通の骨格 `ReminderViewModelBase` が、SDK の `DayChangeWatcher` で行う
  - 一覧を作るたびに `MarkShown` で日付を覚える。古い読み込みとして捨てた結果では覚えない
  - 一覧は、開いたまま日付をまたいでも、「過去の予定」の判定が古くならない
  - ViewModel は UI スレッドで作る (作れなければ例外)
- 通知との連携: 通知の本文クリックの `onClicked` から、`DispatcherQueue`(Low)でいったん後回しにして `ShowFromNotificationAsync` を呼ぶ (閉じかけの通知ウィンドウと、別のウィンドウの操作が重ならないように)
  - 開いてから `ReminderMonitor.SnoozeTriggeredAsync` を呼ぶ
- ダイアログの親: `IDialogHost.TrackWindow` で普通のウィンドウ (メインウィンドウ・この画面)を覚え、モーダルが無いときは最後にアクティブになったほうを親にする (この画面から開いた一覧・入力・確認が、この画面の上に出るように)
