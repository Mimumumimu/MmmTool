# ノート

ノート機能の仕様。

## 概要

- 開始日から終了日までの期間を決めて、タイトルと本文を書き、その日に有効なノートを日ごとに 1 枚の画面へ並べて読む機能
- 複数人では連絡事項、1 人ではナレッジの書き足しに使う
- サイドバーのページ「ノート」だけを持つ
- 場所は `src/Plugins/MmmTool.Notes/` で、Core 側は `src/Plugins/MmmTool.Notes.Core/`
- 他の機能 (作業管理の作業報告など)の日ごとの内容をカードの上に出す仕組みは、[notes-sources.md](notes-sources.md) にある。
- iPhone の Web 版は、この Core (`NoteService`・本文の整形)を使う。画面と API は [web.md](web.md) の「ノート (Web 版)」にある。

## 位置づけ

- 日付が主役の読み物
- 「今日出すべきものを全部、1 枚で読める」ことが目的で、1 件ずつ選んで読む画面にしない (一覧と本文の 2 列にしない)
- 保存先は、ローカルモードが SQLite、DB モードが SQL Server
  - 表は `Note` の 1 つ ([database.md](database.md))
- 検索は持たない
  - 探し方は、そのうち ([../todo.md](../todo.md))
- 返信 (スレッド形式)を持たない
  - 会話の機能は Teams などの役割で、ノートは「その日に有効なものを 1 枚で読む」ことに絞るため
  - ノートの履歴 (変更の記録)も持たない
- 外部への通信を持たない
  - 表示するページは、外部の資源を読み込まず、スクリプトを実行しない (MmmTool に外部送信の処理を入れない決まりのため)
- 画面の文言は仮 (「この日のノートはありません」・ボタンやチェックの名前など)

## データ

- 1 件のノートの持ち物は、書いた人・公開範囲・開始日・終了日・実施日・重要度・タイトル・本文
- 開始日は必須
- 終了日は空にできる (空は無期限で、`9999-12-31` で保存する)
  - 終了日が空のノートは、開始日以降の毎日出る
- 実施日は、1 つのノートに 1 日だけで、空にできる (空は未設定で、`9999-12-31` で保存する)
  - 新規の初期値は未設定
  - その日に、カードを目立たせ、ページの外にも知らせる ([実施日](#実施日))
  - 開始日から終了日の中の日だけを入れられる。外の日は保存できない。
    - 未設定は、期間と無関係
    - 終了日が空 (無期限)のときは、終了日の側は常に中
  - 複数の日や繰り返しは、持たない
- 重要度は 5 段階 (最低・低・中・高・最高)で、新規の初期値は「中」
  - 固定表示 (ピン留め)の 1 つの印にしない (最重要のものを、確実に上へ出す段階が要るため)
- 公開範囲は「全員」か「自分だけ」(DB モードだけで、ローカルモードは 1 人なので、画面に出さない)
  - 新規の初期値は「全員」
  - 変えられるのは書いた人だけ (ほかの人が、全員に見えるノートを、自分だけのものにして隠さないため)
- 本文は、書いたとおりの文字で保存する (表示のときだけ、整形・リンク化する)
  - 保存するときに、タグの除去も、リンクの変換もしない
- タイトルは 100 字まで (`NoteLimits` が持ち、DB の列の長さと同じで、UTF-16 の 1 単位で数える)
- 本文は、上限を決めない (DB の列の最大までで、SQL Server の `nvarchar(max)` は約 2 GB、SQLite の `TEXT` は約 1 GB)
  - 書く量を制限しないため
- 削除は論理削除 (`IsDeleted`)
  - 復元はいつでもできる
  - DB では行を消さない

## 画面

- 入口はサイドバーのページ「ノート」だけ
- 上のバーと、その下のカード一覧からなる

## 上のバー

| 部品 | 動き |
| --- | --- |
| 「新規」ボタン (見出しの右) | 入力のウィンドウを開く。表示を切り替える部品とは並べない |
| 前の日・日付の選択・次の日・「今日」 | 表示する日を決める。初期は今日。作業管理の入力日と同じ形。ページを外す・戻すときは、選んだ日の間だけ引き継ぐ (日をまたいだら今日) |
| 「タイトルだけ」のスイッチ | 全部のカードを同じ状態にする。オフが「全文」で、初期はオフ。ページを外す・戻すときは、選んだ状態を引き継ぐ。本文の長さでは変わらない。スイッチの文字は、オンでもオフでも「タイトルだけ」に固定する (入り切りで文字を替えると、広いほうの幅が常に確保されて、右の部品との間が空き、今の状態も分かりにくくなるため) |
| 「削除したものも表示」のチェック | 入れると、削除済みのノートも、同じ並びに混ぜて出す。初期はオフ。ページを外す・戻すときは、選んだ状態を引き継ぐ |
| 「表示する内容」のボタン | 他の機能 (作業報告など)の内容を、カードの上に出すかを選ぶ。詳細は [notes-sources.md](notes-sources.md) |

- 日付・切り替えを変えたときは、先頭から表示し直す

## カード一覧

- ページ全体 (見出し・操作の行・カード)は、同じ幅 (約 1000px)の 1 本の列にして、中央に置く
  - 複数の列に並べない (重要度の順に、上から下へ読むものなので、視線を横に動かさないため)
  - 広い画面でも、操作の行の右端とカードの右端が揃い、「編集」「削除」がタイトルから遠くならない
- 表示する日に有効なもの (開始日 ≤ その日 ≤ 終了日)を、全部、縦に並べる
  - ノートの数が多くても、一覧は 1 枚の続きの画面で、ページを分けない
- 並びは、実施日のカードが先頭で、そのあとは重要度の高い順
  - 実施日のカード (表示する日が実施日のもの)は、重要度に関係なく、ほかのカードより上に出す
  - 同じ重要度の中は、更新日時の新しい順 (同じなら番号の大きい順)
  - 実施日のカードの間も、同じ並び
- 一覧の部分は、WebView2 の 1 枚の HTML のページ (`NoteCardsView`)
  - カードごとに WebView2 を作らない (件数ぶんのブラウザープロセスができるため)
  - ライトモードとダークモードのどちらでも読める見た目にし、テーマが変わったら作り直す
  - ページは、仮想ホスト `notes.mmmtool.invalid` の `index.html` として、アプリが返す (文字列で渡す方式は、渡せる量に上限があり、本文は上限を決めないため)
  - 仮想ホスト以外へのリクエストは、すべて失敗で返し、ページに `Content-Security-Policy` を付けて、外部の資源を読み込ませない
  - ページのスクリプトは止める (アプリ側から実行する、読んでいる位置を取り出すスクリプトは動く)
  - ブラウザーとしての機能 (キー操作・ズーム・自動入力)も止める
  - 右クリックのメニューは、標準のものを出さず、カードの上では「編集」「削除」(削除済みなら「復元」)に差し替える
    - どのカードの上かは、アプリ側から実行するスクリプトで、右クリックした位置から調べる
    - 選んだ文字があるときは「コピー」を出す
    - メニューは、WebView2 の標準のものが項目の文字の幅しかなく押しにくいため、アプリ (WinUI)の `MenuFlyout` で出す
  - 「タイトルだけ」でカードを開く動きは `<details>` で行う
  - 「編集」「削除」「復元」は、仮想ホストの内部リンク (`https://notes.mmmtool.invalid/action/<操作>/<番号>`)で受ける
    - ページの移動を `NavigationStarting` で横取りして、アプリが処理する
    - `index.html` 以外への移動は、取り消す
  - 作り直すとき (切り替え・読み直し・保存)は、読んでいる位置と開いているカードを、作り直す前に取り出して、保つ (日付・切り替えを変えたときは、保たない)
  - WebView2 は、SDK のターミナルと同じ保存先 (`AppEnvironment.WebView2Directory`)・同じ設定 (`WebView2Setup`)で作る
    - 同じプロセスの WebView2 は、同じ保存先なら同じ設定が要るため
    - スクロールバーは、細い重なりの形 (`FluentOverlay`)にする。既定の形は、幅が広く上下に矢印が付き、ほかの画面と見た目が違うため。指定は `WebView2Setup` の1か所で、ターミナルも同じ。
    - 詳細は [SDK の terminal.md](../../external/MmmSdk/docs/terminal.md)
  - 初期化できないとき (WebView2 ランタイムが無い)は、一覧の場所に理由を文字で出す
- 1 枚のカードの上の行に出すもの
  - タイトル・期間 (終了日が空のときは「開始日 ～」)・実施日 (設定があり、表示する日より後のときだけ「実施 10/25」と小さく)・作成者・更新者 (どちらも DB モードだけ)・更新日時・印
  - 重要度は、帯で示す
  - 1 行目に、矢印・タイトル・印を左から並べ、期間・作成者・更新者・更新日時は、同じ行の右端 (「編集」「削除」の左)に寄せる
    - 縦スクロールを短くするため
    - 幅が足りないときだけ、右寄せのまま次の行へ折り返す
  - カードの上下の余白と、カードの間は、8px に詰めている
  - カードの枠は、全重要度で、四辺に 1px を引く。「高」「最高」だけ、左の枠を 4px の帯にし、中身の左端は、ほかのカードと揃える。
  - 印は、タイトルの右に出す
    - 印のために行を増やさない
    - タイトルの左に置くと、印の有無でタイトルの左端がカードごとにずれるため
  - 作成者は `AuthorUserId`、更新者は `UpdatedByUserId` から引く
    - 表示だけに使い、検索・結合・索引には使わない
    - 名前は、SQL で結合せず、必要な人だけを番号で引く (`IAppUserRepository.GetUsersByIdsAsync`)
    - 更新者が作成者と同じときは、更新者を省く (編集が誰でもできるので、ほかの人が直したことが分かるようにするため)
  - 更新日が今日のノートには、印を付ける (表示する日ではなく、実際の今日)
    - 人ごとの既読の記録は持たない (印のためだけに表を増やさないため)
  - 「自分だけ」のノートには、その印を付ける (DB モードだけ)
  - 削除済みには「削除済み」の印を付ける
  - 重要度は、カードの左端の細い帯で示す
    - 「最高」は赤、「高」は橙
    - 「中」「低」「最低」は帯を付けない (静かに保ち、目立たせたいものだけを目立たせるため)
- カードの本文は、「本文の表示」の決まりで整形して出す
  - 「タイトルだけ」のときは、本文を出さず、カードを押すと、そのカードだけが開く
  - 「全文」のときも、カードを押すと、そのカードだけが畳める
  - どちらも、本文の長さでは、開く・畳むを分けない (長さで見た目がそろわなくなるため)
  - 本文が空のカードだけは、開く先が無いので、開閉の矢印を出さない
- カードの操作は、上の行の右に置く
  - 「編集」(入力のウィンドウを開く)・「削除」(確認のダイアログを出して、論理削除する)
  - 削除済みのカードは、薄く出して、「編集」と「削除」の代わりに「復元」を置く (確認は出さない)
- 編集・削除・復元は、見える人なら誰でもできる (リマインダーと同じで、書いた人が削除したノートを、ほかの人も戻せるようにするため)
  - 見えないノート (ほかの人の「自分だけ」)は、そもそも出ない
  - ほかの人が先に変えて、操作しようとしたノートが無かったときは、失敗を InfoBar に出して、読み直す
- 表示する日にノートが無いときは、空の画面に、その日付と「この日のノートはありません」を出す
  - 文は中央寄せにして、日付を文の上の別の行に出す
    - Web 版と同じにする
    - 今の標準の、何も無い画面の見せ方に合わせるため
  - 文の上の余白は 16px (Web 版は 1rem)で、PC 版と Web 版でそろえる
    - 大きく空けない (数十px 空けると、利用者が「なぜこんなに空いているのか」と感じるため)
    - 画面の高さの中央にも置かない (上の操作の近くに出して、何が空かをすぐ分かるようにするため)
  - 左寄せで左端と上端の余白をそろえる形にしない (標準の見せ方ではなく、ノートがあるときと文字の始まりをそろえる利点も小さいため)
  - ページの余白は左 4px・右 20px と非対称なので、中央が窓の中央になるよう、この文だけ左に 16px の余白を足す
- 読み込み・操作に失敗したとき (`DataFileException`)は、上のバーの下に InfoBar で出す。今の表示は変えない。

## 実施日

目的は、実施日の当日に、そのノートの「今日がその日だ」とすぐ分かること。カードの見た目と、ノートのページの外の知らせの 2 つで行う。

### カードの見た目

- 表示する日が実施日のカードを、実施日のカードとして目立たせる
  - 実際の今日ではなく、表示する日で決める (その日のページとして読んだとき、同じ見え方になる)
  - 過ぎた日と、これから来る日のカードは、普通のカード
- 実施日のカードの見た目
  - 上端に帯を通す。帯の文言は、表示する日が実際の今日のとき「今日が実施日」、そうでないとき「この日が実施日」。
  - 背景に薄い色味を付け、枠を 2px にして、周りに光 (影)を出す
  - タイトルを、ほかのカードより 1 段大きくする
  - 色は、固定の紫系
    - 重要度の帯の赤・橙と区別するため
    - 警告に見える色 (赤・橙・黄)を、意味のない飾りに使わないため
    - アクセント色は、ユーザーの設定で変わり、区別に使えないため
    - ライトとダークのそれぞれで、背景に対する文字・枠のコントラスト比を計算して決める
  - ページを作り直したとき、光は 3 回だけ脈打って止まる (通知ダイアログの点滅と同じ回数)
    - 読んでいる間、動き続けない
    - 点滅は 1 秒に 3 回未満
    - 「視覚効果を減らす」の設定では動かさない
- 「タイトルだけ」のスイッチには、従う
  - 閉じていても、帯・色味・枠・光・大きなタイトルで目立つ
  - 本文は、カードを押したときに開く
- 光の動きは CSS だけで行う (ページのスクリプトは止めてあるため)
- Web 版のカードも、同じ見せ方にする ([web.md](web.md)の「ノート (Web 版)」)

### ページの外の知らせ

- 通知ダイアログ (SDK の `INotificationDialogService`)で、今日が実施日のノートを知らせる
  - 出すのは、アプリの起動時と、日付が変わったとき
  - 今日が実施日のノートが無いときは、節を出さない
  - 節は、見出し「今日が実施日のノート」と、ノートのタイトルの項目
  - 通知の窓は、アプリで 1 枚で、リマインダーの通知と同じ窓に、節として並ぶ ([通知ダイアログ](../../external/MmmSdk/docs/notification-dialog.md))
    - ノートの節は、送り元 `Notes`・並びの値 2 で、リマインダーの節 (4)の上に固定する
    - 起動直後に、ノートの通知もリマインダーの通知もあれば、両方を出す。片方だけなら、その節だけを出す
    - リマインダーが通知しても、ノートの節は消えない
    - 節をクリックしたら、その節だけを閉じる。ほかの節は残る
  - 対象は、実際の今日が実施日で、削除されていなくて、見えるノート
  - ノートの機能がオフのときは、出さない (起動時の準備と日付の監視に、ノートの機能のキーを渡す)
  - 読み込みに失敗したとき (DB に接続できないなど)は、起動を止めず、出さずに続ける
- 通知をクリックしたら、メインウィンドウのサイドバーでノートのページを選び、表示する日を今日にする
  - メインウィンドウがトレイに隠れているときは、先に表示する
  - ページを開く口は、ノート専用にせず、SDK に、どの機能からも「サイドバーの指定のページを選ぶ」と頼める形で置く
  - 通知ウィンドウが閉じている最中に別のウィンドウを操作しないよう、閉じ終わってから開く (リマインダーの通知と同じ)
  - 人ごとの既読の記録は持たない (印のためだけに表を増やさないため)
  - 同じ日に何度か起動すると、そのたびに出る
- サイドバーのバッジ・Web 版のホームの件数は、持たない (ユーザーの決定で、知らせは通知ダイアログだけ)
- iPhone への通知は、外部送信なので、MmmTool に入れない (方向は [../todo.md](../todo.md))

## 入力のウィンドウ

- 新規と編集で同じウィンドウ (`NoteEditWindow`)を使う
- 閉じたウィンドウは再表示できないので、開くたびに作る
- 親の上にモーダルで出る
- 大きさは変えられる (本文を広く書けるように)
- 最初の高さは DIP で 720。親のいるモニターの作業領域より高くなるときは、作業領域に収まる高さまで抑える (位置を寄せるだけでは、下が切れるため)。最小の高さも、その分下げる

| 項目 | 内容 |
| --- | --- |
| タイトル | 1 行。必須 |
| 本文 | 複数行。右クリックのメニュー (下の「右クリックの助け」)を持つ。ファイルのドロップを受ける。最低の高さは DIP で 120 で、ウィンドウの余った高さまで伸びる。長いときは、欄の中でスクロールする |
| 開始日 | 必須。新規の初期値は、ページが表示している日 |
| 終了日 | 新規の初期値は空で、無期限。あとから日を入れて終わらせる。「クリア」ボタンで空にでき、空は無期限 |
| 実施日 | 新規の初期値は空で、未設定。「クリア」ボタンで空にできる。空のときの薄い文字は「なし」。欄の下に、説明は出さない (ユーザーの決定) |
| 重要度 | 「最低」「低」「中」「高」「最高」の 5 つを横に並べた選択 |
| 公開範囲 | DB モードだけ。書いた人以外は、押せない。「自分だけに表示」のチェック (オフは全員に見える。2 択なのでチェックボックス) |

- 開始日を終了日より後にした、または終了日を開始日より前にしたときは、もう一方を同じ日に合わせる
- 実施日を入れたとき、期間の外ならば、開始日・終了日のほうを動かして合わせる
  - 開始日より前に入れたら、開始日を実施日まで早める
  - 終了日より後に入れたら、終了日を実施日まで伸ばす。終了日が空のときは、何もしない。
  - 動かしたときは、情報の InfoBar で知らせる (例: 「終了日を 2026/11/10 に伸ばしました。」)
- 開始日・終了日を動かして、実施日が期間の外に出たときは、実施日を動かさない
  - 日付の欄の下 (ボタンの上)に、エラーの InfoBar を出し続ける (例: 「実施日 (2026/11/05)が期間の外です。開始日・終了日か実施日を直してください。」)
    - 入力欄に重ねない (直すまで出続け、タイトルの入力を邪魔しないため)
  - 開始日・終了日・実施日の欄にも、エラーの印を付けて、原因の欄を分かるようにする
  - 期間の中に直すまで、「保存」を押せない
  - 実施日を動かさないのは、日付を動かした操作で、別の欄の日が意図せず変わらないようにするため
- 保存できるのは、タイトルがあり、開始日が入っていて、実施日が空か期間の中にあるとき
- 保存に失敗したとき (`DataFileException`・入力の誤り)は、ウィンドウを閉じず、理由を InfoBar で出す
- 保存したら、ページが表示している日にそのノートが入るかに関係なく、ページを読み直す
- タイトルと本文は、フォーカスが来たら IME をオンにする (日本語の入力が多いため)
- タイトルと本文の入力欄、カードの表示は、等幅のフォント (`BIZ UDGothic, MS Gothic, Consolas`)にする (作業報告・日報メモと同じ)
  - 全角 1 文字が半角 2 文字の幅に揃い、タグや字下げの桁が揃うため
  - 入力欄 (`TextBox`)には、行の高さの指定が無いので、行間は狭いまま (日報メモと同じ)
  - カードは、CSS の `line-height` で行間を広げる

## 右クリックの助け

- 本文の入力欄で右クリックすると、メニューを出す
- 選ぶと、本文に HTML のタグが入る
- タグを知らない人でも、書式を付けられるようにするため

| 項目 | 範囲を選んでいるとき | 範囲を選んでいないとき |
| --- | --- | --- |
| 色 | 押すと、選んだ文字の直下に、1 枚のパネルが開く。系統 (灰色・赤・橙など)を横に、段階 (濃い〜薄い)を縦に並べた格子から選ぶ。選んだ文字を色のタグで囲む。「標準」を選ぶと、選んだ文字の色を外す | 押せない |
| 太字・斜体・下線・取消線 | 選んだ文字を、対応するタグで囲む | 押せない |
| リンクを追加 | 選んだ文字をリンク名にして、リンク先を入力するダイアログを出す | リンク名とリンク先を入力するダイアログを出す |

- メニューには、切り取り・コピー・貼り付け・すべて選択も入れる (欄の標準のメニューを置き換えるため)
  - 並びは、3 つのまとまり
    - 文字の装飾 (色・太字・斜体・下線・取消線)
    - リンクを追加
    - クリップボードの操作
  - 色は、重要な連絡を目立たせるのに使うので先頭
- リンク先には、URL かファイルのパスを入力する。ファイルのパスは、`file:` の形に直して入れる。リンク名を省くと、リンク先を表示する。
- ファイルやフォルダーを本文の入力欄にドロップすると、カーソルの位置に、リンクが入る。リンク名はファイル (フォルダー)の名前で、複数をドロップしたときは、1 つずつ改行して並べる。右クリックの「リンクを追加」と、どちらでも入れられる。
- 色のパレット (`NoteColorPalette`)は、11 系統 × 4 段階の 44 色
  - 「黒」は置かず、「標準」を置く (ダークモードで見えなくなるため)
    - 「標準」はそのときのモードの標準の文字色
  - 各色は、カードの背景 (ライト `#FFFFFF`・ダーク `#2B2B2B`)に対して、ライト・ダークのそれぞれで、本文の文字として読める明るさ (コントラスト比 4.5 以上)になるよう、計算で決める
    - 段階は、濃いほど強い
    - ライトは 9.0・7.0・5.5・4.5、ダークは 4.8・6.5・8.5・11.0 の比
  - 色は、ライトモードで読める色の値 (`color:#RRGGBB` の形)で本文に入る
    - 表示のときに、ダークモードでは同じ系統の別の色へ差し替える
    - パレットに無い値を手で書いたときは、色を付けない (標準の色になる)

## 本文の表示

- 本文は、基本は普通の文章で、書いたとおりの改行で出す
- HTML のタグを書くと、許可したタグだけが反映される
- HTML を知らなくても使え、知っていれば工夫できる形にする
- Markdown は使わない (記法を覚えなくても使える形にするため)
- 整形 (`NoteBodyFormatter`)は、取り除く方式ではなく、組み立て直す方式
  - 本文の文字を、すべて HTML の文字に直して出し、許可したタグに当たる部分だけを、アプリが決まった形のタグ (属性も、アプリが決めた形だけ)で出す
  - 出力には、アプリが作ったタグしか入らない
  - HTML の除去用の部品 (AngleSharp を使うもの)を入れない (外部へ接続する型を含み、MmmTool に外部送信のコード・DLL を入れない決まりに反するため)

## 反映するタグ

| タグ | 反映すること |
| --- | --- |
| `b` `strong` / `i` `em` / `u` / `s` | 太字 / 斜体 / 下線 / 取消線 |
| `br` | 改行 |
| `ul` `ol` `li` | 箇条書き |
| `span` | `style="color:#RRGGBB"` の指定だけ (パレットの色だけで、ほかの指定は捨てる) |
| `a` | `href` だけ。`href` は `http` `https` `file` のものに限り、ほかは `a` ごと取り除く。仮想ホスト (`notes.mmmtool.invalid`)も取り除く (本文に書いた `<a>` が、カードの操作の内部リンクになりすまして、ほかの人のノートの削除などを呼ばないため) |

- 上にないタグと属性は、表示のときに取り除く
  - 取り除くのは、タグだけ (中の文字は残す)
  - `script` と `style` は、中身ごと取り除く
  - 注釈も取り除く
- 外部の画像などの資源を読み込むタグ (`img` `iframe` `link` など)は、反映しない
  - ほかの人が書いた本文を、安全に表示するため
- 閉じていないタグは最後に閉じる。対応しない閉じタグは捨てる。
- 箇条書きのタグのすぐ前後の改行は、空きにならないよう、出さない
- 本文のタグに見えない `<` (「1 < 2」など)は、文字として出す

## 自動リンク

- 本文の中の `http://` と `https://` で始まる文字を、表示のときに、リンクにする
- 保存した本文は変えない
- URL の終わりは、半角の URL に使える文字が続くところまで。全角の文字・空白・改行で切る。
- 末尾の `.` `,` `;` `:` `!` `?` `'` は、URL に含めない
  - `)` と `]` は、対応する開きが URL の中に無いときだけ含めない (`…/日本_(国)` の閉じ括弧は URL に含める)
- すでに `<a>` のタグで書いてあるものは、二重にしない
- ブラウザーのアドレスバーからコピーした日本語を含む URL は、日本語の部分が `%E6%97%A5…` の形に直って貼られる想定
  - この形は、最後までリンクになる
  - 日本語のまま書いた URL は、全角の文字の手前までしかリンクにならないので、右クリックの「リンクを追加」で入れる
- ファイルのパス (`C:\…` `\\server\…`)は、自動ではリンクにしない (誤判定が多いため)

## リンクを押したとき

- `file:` のリンクは、ページには、仮想ホストの内部リンク (`https://notes.mmmtool.invalid/open?u=<file: の URL>`)に包んで出す
  - 仮想ホストの https のページから `file:` へ移ろうとしても、WebView2 (Chromium)が、移動が始まる前に止めてしまい、アプリが横取りする `NavigationStarting` が来ないため
  - アプリが包みを解いて、ふつうのリンクと同じ判定に回す (下の、ページに出したリンクだけを開く決まりも同じ)
- ページの中では開かず、`IPathOpener` で開く
  - `file:` のリンクは、パスにして開く (フォルダーはエクスプローラーで開く)
  - 開けなかったときは、InfoBar に出す
- 開くのは、今のページに出したリンク (`NoteLinks.CollectHrefs` が集める)だけ
  - ファイルをページに落としたときなど、ページに出していない移動は、開かない (落としたファイルが、実行ファイルのとき、動いてしまうため)
- 開くのは `http` `https` `file` だけ
  - ほかの種類 (独自のスキームなど)は、押しても開かない (ほかの人が書いた本文のリンクを押すため)
  - この絞り込みは、上の整形の段階でも行う
- Ctrl+クリック・中クリックも、同じ判定に回す (新しいウィンドウは開かない)

## 読み込みと反映

- ページは、表示する日の分 (有効なもの・見えるもの)を読む。全部のノートは読まない。
- 見えるのは、公開範囲が「全員」のノートと、自分が書いた「自分だけ」のノート
  - 読み書きの SQL は、すべて、この条件を持つ (見えないノートを、番号だけで操作させないため)
- ほかの人の更新は、DB モードだけ、表示している日の分を 1 分ごとに読み直して反映する
  - ローカルモードは、ほかの人の更新が無いので、定期の読み直しをしない
  - 前回と内容が変わったときだけ、画面を作り直す
  - 自分の保存や削除のあとは、すぐ読み直す
- 他の機能の内容 (作業報告など)が変わったときは、その機能からの通知 (`IDayContentSource.Changed`)で、0.5 秒ほど待ってから、まとめて 1 回読み直す
  - 続けて通知が来たら、待ち直す。表のセルを続けて直しても、読み直しは 1 回
  - 見えている間だけ購読する。見えなくなったら解除する。ノートを別のウィンドウに出したまま、メインで作業管理を触っても、すぐ追従する
  - 機能のオン・オフが切り替わったときも、見えている間は、「表示する内容」の並びを合わせ直して読み直す
- **更新ボタン** (DB モードだけ): 見出しの行の右端に置くアイコンだけのボタン
  - ローカルモードは他の人の更新が無いので出さない
  - SDK の `RefreshButton` で、作業管理・スケジュールと同じ見た目
  - 押すと、1 分を待たずに、定期的な読み直しと同じ読み直し (読んでいる位置と開いているカードを保つ)を 1 回行い、次の自動の読み直しまでの間隔を数え直す (直後に自動の読み直しが重ならないため)
  - 読み直しの間は押せない
- 読み直しは、ページが見えている間だけ行う
  - ほかのページを見ている間 (`Unloaded`)と、メインウィンドウをトレイへ隠している間 (`XamlRoot.IsHostVisible` が false)は、DB に問い合わせない
  - 見えるようになったら、すぐ読み直す
- ローカルモードは、書いた人が常に 1 人 (`Id = 1`)
  - 公開範囲は使わない

## 保存

- ローカルモード: SQLite (`Data/MmmTool.db`)の `Note` 表 (`SqliteNoteRepository`)
- DB モード: SQL Server の `Note` 表 (`SqlServerNoteRepository`)
  - 表がまだ無いときは、`003_AddNote.sql` を流す手順を伝えるメッセージを出す
- 表の列・索引・型は [database.md](database.md) にある
  - DB の種類で変わる所は、その文書の「SQL Server の場合」「SQLite の場合」
- ホスト (`src/App/MmmTool`)に、ノートの名前を書いた保存先の登録を足さない
  - 設定でローカルか DB かを選ぶ処理は、共通の部品 `AddStorage` (`Features/Database`)に 1 か所だけあり、機能は 1 行で使う (機能を足すたびに、ホストへ機能名のファイルや、同じ処理のコピーが増えないようにするため)
  - ノートは、その 1 行 (`App.xaml.cs`)と、機能の登録 (`AddFeaturePlugin<NotesPlugin>`)だけで足している
