# クリップボード転送

ファイルをクリップボードのテキスト (JSON)に載せて別の PC へ渡し、受け取った側でファイルに戻す機能。クリップボードを共有できる環境 (リモートデスクトップなど)で、ファイルを運ぶために使う。サイドバーの CLI補助の下に出るページ 1 つ。`Features/ClipboardTransfer/`(Core 側は `MmmTool.Core/ClipboardTransfer/`)。設定ページでオン・オフできる ([settings.md](settings.md))。

## データ
- 保存するデータは無い (`Data/` にファイルを作らない)。ファイルの内容は、クリップボードのテキストにだけ載る
- 転送データは、JSON の配列。要素が 1 ファイル分 (`TransferFile`)

  | プロパティ | 型 | 内容 |
  | --- | --- | --- |
  | `FileName` | string | ファイル名 (フォルダーは含まない) |
  | `Base64Data` | string | ファイルの内容の Base64 文字列 |
  | `CreationTime` | 日時 | 作成日時 |
  | `LastWriteTime` | 日時 | 更新日時 |

  ```json
  [
    {
      "FileName": "example.txt",
      "Base64Data": "aGVsbG8=",
      "CreationTime": "2026-10-05T12:00:00+09:00",
      "LastWriteTime": "2026-10-05T12:30:00+09:00"
    }
  ]
  ```
- **形式は固定する。** プロパティ名は PascalCase のまま、シリアライザは .NET 標準の既定の設定 (`TransferJsonContext.Default`)で読み書きする。SDK の `ReadableJsonOptions` (キーが camelCase・インデントあり)は使わない。変えると、すでにクリップボードに載せた・書き出した JSON を読めなくなる
- 日時は ISO 8601 (時差つき)。`DateTimeOffset` で持つので、別のタイムゾーンの PC で復元しても、同じ時刻になる

## 処理 (`ClipboardTransferService`。Core。状態を持たない)
- **送信 (`EncodeAsync`)**: ファイルのパスの一覧を JSON にする。存在するファイルだけが対象で、フォルダー・存在しないパスは除く。送れるファイルが 1 つも無ければエラー
  - 同じ名前のファイルが 2 つ以上あれば (大文字小文字は区別しない)、名前を挙げてエラー (別のフォルダーのファイルを一緒に送ると、受け取る側で、あとの分が先の分を黙って上書きしてしまうため)
  - 1 ファイルあたり 160 MB までが上限 (`MaxFileBytes`)。Base64 にすると約 4/3 倍になり、文字列としてクリップボードに載るため。1 つでも超えるものがあれば、どれも読み込まずに、ファイル名を挙げてエラーにする
- **受信 (`DecodeAsync`)**: クリップボードの JSON を転送データの一覧に戻す。保存の前に、全件を確かめる (途中で壊れたファイルが混ざらないように)
  - JSON として読めない・空・配列ではない → 「転送データではありません」
  - ファイル名が空・`.`・`..`・フォルダーの区切りや使えない文字を含む → エラー (送られてきた名前をそのまま使うと、保存先のフォルダーの外 (`..\` など)に書けてしまうため)
  - Base64 が正しくない (`Base64.IsValid`) → エラー
  - 同じ名前のファイルが 2 つ以上 (大文字小文字は区別しない) → エラー (複数保存で、あとの分が先の分を黙って上書きするため。送信側と同じ確認)
- **保存 (`SaveAsync`)**: Base64 を戻して書き出し、作成日時・更新日時を元の値に戻す。日時が Windows のファイルの範囲 (1601 年)より前なら戻さない
- 読み込み・変換・書き込みはスレッドプールで行い、画面を止めない
- 予測できる失敗 (大きすぎる・JSON が正しくない)は例外にせず、結果の `Error` で返す。ファイルを読めない・書けない (ロック・権限など)は `IOException` / `UnauthorizedAccessException` で上げ、ViewModel が受けて InfoBar に出す

## 画面 (`Main/ClipboardTransferPage` ＋ `ClipboardTransferViewModel`)
- 余白 24・タイトル「クリップボード転送」。左に「送信」、右に「受信」のカード (3:2。リンクのページと同じカードの作り。高さは背の高いほうにそろえる。どちらも見出し・1 行の説明のあとに操作を置く)
- **送信のカード**: 破線で囲んだドロップ領域 (ファイルを重ねている間は、枠と地をアクセント色にする)と、その中の「ファイルを選択」ボタン。ドロップしても、ボタンで選んでも、クリップボードに載せる
  - ドロップしたもののうち、フォルダー・パスの無いもの (メールの添付など、ディスク上に無いもの)は送らず、除いた件数を結果に出す
- **受信のカード**: 「クリップボードから保存」ボタン (強調色)。主な操作はこのボタンなので、ここだけ強調する
- 結果は、ダイアログではなくページ上部の InfoBar に出す。成功は成功の InfoBar (見出し＋ファイル名 (5 件まで。多いときは「ほか N 件」)・合計の大きさ・保存先)、失敗はエラーの InfoBar。次の操作を始めると、前の分は消える
- 処理中は、ボタン・ドロップを受け付けない (`IsBusy`)。進行表示 (ページ上部の ProgressBar。`IsProcessing`)は、変換・読み書きの間だけ出す。ファイル選択・確認ダイアログでユーザーの入力を待っている間は出さない (大きなファイルは時間がかかるため)
- 複数の保存で、すべてスキップして 1 件も保存しなかったときは、見出しを「保存したファイルはありません」にする (「0 件を保存しました」にしない)

## 受信の保存先
- **1 件のとき**: 「名前を付けて保存」のダイアログ (`IFilePickerService.PickSaveFileAsync`。最初のファイル名は元の名前)。同じ名前のファイルがあるときの上書きの確認は、このダイアログが出す。キャンセルしたら何もしない
- **複数のとき**: フォルダー選択のダイアログ (`IFolderPickerService`)で、まとめて保存する。同じ名前のファイルがあれば、先に 1 回だけ「ファイルの置換またはスキップ」を出す (`IDialogService.AskFileConflictAsync`。Windows のファイルのコピーの確認と同じ形)
  - 「ファイルを置き換える」: 重複したものをすべて置き換える
  - 「置き換えずスキップする」: 重複したものをすべて飛ばす (重複しないものは保存する)
  - 「ファイルごとに決める」: 重複したものごとに、「ファイルを置き換える」「置き換えずスキップする」を聞く。「中止」でそこまでにして終える (保存済みのものは残る)
  - 「キャンセル」: 何も保存しない
  - ダイアログを開いたときのフォーカスは、取りやめるボタンに置く (Enter・Space 1 回で置き換えないため。[SDK の dialogs.md](../../external/MmmSdk/docs/dialogs.md))
- 保存できなかったファイルがあっても、残りは保存を続け、最後にまとめてエラーの InfoBar に出す (ファイル名と理由)

## SDK の部品
アプリ固有でない部分は SDK にある ([../../external/MmmSdk/docs/dialogs.md](../../external/MmmSdk/docs/dialogs.md))。
- `IClipboardService`(クリップボードのテキストの読み書き)
- `IFilePickerService.PickFilesAsync` / `PickSaveFileAsync`(複数選択・保存先の選択)
- `IDialogService.AskFileConflictAsync` と `FileConflictChoice`
