# 作業リスト

作業を木構造で管理し、日ごとの実績と備考を残す機能 (WBS の入力画面)。サイドバーのページ 1 つと、設定ページのオン・オフ ([settings.md](settings.md))。`src/Plugins/MmmTool.WorkItems/`(Core 側は `src/Plugins/MmmTool.WorkItems.Core/`)。フォルダ名を `Tasks` にしないのは、`System.Threading.Tasks` を隠すため。

この文書は設計 (案)。実装した部分から、確定した仕様に直す。カレンダー型の画面 (ガントチャート)は、この機能に含めない。別の画面として、別に設計する。

## 目的と使い方
- 案件・区分・作業を、段数に制限のない木構造で持つ。表の 1 列目が木構造、右の列が入力欄で、1 画面に収める
- 毎日の入力は、**入力日** (左上。既定は当日)の実績と日の備考。ほかの項目は、作ったときと変えたときだけ触る
- 気軽に入れられることを優先する。別画面を開かず、表のセルに直接入力する。必須の入力は、名前だけ

## 行の種類
| 種類 | 内容 |
| --- | --- |
| グループ | 子を持つ行 (案件・区分など)。入力するのは名前と備考だけ。日付・進捗度・予定時間・実績は、子の作業から計算して表示する |
| 作業 | 入力する行。子を持たない |

- 種類は、作ったときに決める (メニューの「グループを追加」「作業を追加」)。あとから変えない。作業の下に子が欲しくなったときは、新しいグループを作り、その作業を移動する
- グループの中身は、グループ・作業のどちらでもよい。段数に上限は無い
- 兄弟の並びは、保存した順 (`SortOrder`)。「上へ」「下へ」で入れ替える

## 項目
### 作業の項目 (作業ごとの共通の値)
| 項目 | 型 | 既定値 | 内容 |
| --- | --- | --- | --- |
| 名前 | 文字列 (200) | (入力) | 必須。グループと共通 |
| 優先度 | 高 / 中 / 低 | 中 | Backlog と同じ 3 段階 |
| 開始日・期限日 | 日付 | なし | 開始日 ≦ 期限日。逆のときは保存せず、理由を InfoBar に出す |
| 状態 | 未対応 / 処理中 / 処理済み / 完了 | 未対応 | Backlog 標準の 4 つ。名前をそろえて、連携で変換しないため |
| 進捗度 | 整数 (%) | 0 | マスターから選ぶ (下の「進捗度のマスター」)。保存するのは数値 (ラベルではない) |
| 予定時間 | 時間 (小数可) | なし | 作業ごとの共通の値。日ごとではない |
| 備考 | 文字列 (1000) | 空 | 作業ごとの共通の備考 (永続) |

### 日ごとの記録 (作業 × 日付)
| 項目 | 型 | 内容 |
| --- | --- | --- |
| 実績 | 時間 (小数可) | その日にかけた時間。0 以上 24 以下 |
| 日の備考 | 文字列 (1000) | その日の備考 |

- 1 つの作業の 1 日につき、1 件。同じ日に何度直しても、1 件のまま
- 実績と日の備考が両方とも空・0 になったら、その日の記録を消す (空の行を残さない)
- 作業の**実績 (累計)** は、その作業のすべての日の実績の合計。表示だけで、入力はできない (日ごとの実績を入れると変わる)

### グループの計算 (表示のみ)
グループの下にある**作業すべて** (段数を問わない)から計算する。入力はできない。
- 開始日: 子の開始日の最小 / 期限日: 子の期限日の最大 (入っている作業だけで求める。1 つも無ければ空)
- 予定時間: 合計
- 実績 (日): 入力日の実績の合計
- 実績 (累計): すべての日の実績の合計
- 進捗度: すべての作業に予定時間が入っているときは、予定時間で重みを付けた平均。そうでないときは、作業の件数の平均。作業が 1 つも無いグループは空
- 優先度・状態は、グループに出さない

### 履歴 (変更の記録)
作業の項目 (名前・優先度・開始日・期限日・状態・進捗度・予定時間・備考)を変えたとき、自動で 1 件記録する。内容は、日時・項目・変更前・変更後。日ごとの記録 (実績・日の備考)は、それ自体が日ごとの履歴なので、この記録には入れない。

## 進捗度のマスター
- 値は、0 から 100 までの 10 刻みで**固定**する (11 個。足したり消したり、値を変えたりしない)。マスターで持つのは、値ごとの**ラベル** (括弧の中身)を付けるか付けないか、だけ
- 初期のラベルは次のとおり。ほかは空 (数値だけ)

  | 値 | ラベル |
  | --- | --- |
  | 70 | 作成完了 |
  | 80 | 内部レビュー完了 |
  | 90 | 外部レビュー完了 |

  画面では、ラベルがあれば `70% (作成完了)`、なければ `60%` のように出す
- 作業に持たせるのは数値なので、ラベルを直しても、保存済みの作業は書き換わらない。Backlog のカスタム属性 (例: `80% (社内レビュー完了)`)との対応づけも、数値で行う
- 保存先は、ローカルモードでは JSON、DB モードでは DB の表 (全員共通)。どちらも、初めて開いたときに初期値を入れる
- **編集は、ローカルモードだけ画面から行う** (画面右上の「設定」ボタン → 「進捗度のラベル…」。11 個の値ごとに、ラベルの入力欄が並ぶダイアログ。空にするとラベルなし)。DB モードは全員に影響するので、気軽に触れる口を画面に出さない。直すときは、DB の表を SQL で直す (ユーザー・権限の区別がアプリに無いため)。DB モードでは、「設定」ボタン自体を出さない

## 画面 (`Main/WorkItemPage` ＋ `WorkItemViewModel`)
- 余白 24・タイトル「作業リスト」。リンク・クリップボード転送のページと同じ作り。結果・エラーは、ページ上部の InfoBar に出す
- 上のバー: 左端に **入力日**: 「◀」「▶」(前日・翌日)・日付 (`CalendarDatePicker`。既定は当日)・「今日」ボタン。右側に、「表示列」ボタンと、「設定」ボタン (ローカルモードだけ。進捗度のラベルの編集。上の「進捗度のマスター」)。行の追加はボタンにせず、右クリックのメニューだけで行う (下の「右クリックのメニュー」)。主な操作は、日々の入力 (表のセルへの入力)なので、強調色のボタンは置かない
- 表 (SDK の `TreeGridView`):
  - **左の固定部分** (横にスクロールしない): 名前 (木構造。字下げ・開閉ボタン) / 優先度 / 開始日 / 期限日 / 予定時間 / 実績 (累計)。あまり変えない項目と、積み上がった合計を、名前と一緒に見渡せるようにする
  - **右の列 (毎日入力する列)** (横にスクロールする): 状態 / 進捗度 / 実績 (日) / 備考 (日) / 備考。改行を含む長い文が入る備考を後ろに置く。最後の「備考」は作業ごとの共通の備考で、これも毎日入力する扱い
  - **毎日入力する列は、背景の色で区別する** (薄い緑。グループの行は、計算値なので、さらに薄い緑)。「どこに入れればよいか」を迷わないため。見出しに帯や説明の文言は付けない。選んだ行の背景 (青)は、緑より優先して見える。暗い表示では、暗い緑にする。色だけに頼らないよう、緑の列の並び (連続していること)でも分かるようにする
  - 列の見出しの「実績 (日)」「備考 (日)」は、入力日の分であることが分かる表記にする
  - 作業の行は、セルにそのまま入力する (文字: `TextBox`、状態・進捗度・優先度: `ComboBox`、日付: `CalendarDatePicker`、時間: `NumberBox`)。入力を確定したとき (フォーカスが外れたとき・Enter)に、その場で保存する。確認ボタンは無い
  - 実績 (累計) は、作業・グループとも入力できない (日ごとの実績の合計)。グループの行の計算列は、入力できず、2 次の文字色で出す
  - 備考・備考 (日)は、セルに先頭の 1 行を省略記号つきで出す (行の高さは固定)。編集を始めると、セルの下に複数行の入力欄を開き、フォーカスが外れたときに保存する。全文は右のペインでも読める
  - 行の高さは固定
- 右のペイン: 選んだ作業の日ごとの履歴 (日付・実績・日の備考の一覧。新しい日が上)と、変更の履歴。閉じたままでも使える
- 作業が 1 件も無いときは、一覧の位置に「右クリックして、グループまたは作業を追加します」と案内を出す (追加のボタンが無いため)

### 右クリックのメニュー
行の追加は、右クリックのメニューだけで行う。追加の位置は、右クリックした場所で決まる。
- **グループの行**: 「この中にグループを追加」「この中に作業を追加」(グループの子として末尾に足す)
- **作業の行**: 「同じ階層にグループを追加」「同じ階層に作業を追加」(その作業の下に足す。作業は子を持たない)
- **一覧の空いたところ**: 「グループを追加」「作業を追加」(最上位の末尾に足す)
- 行のメニューには、続けて次の項目を出す
  - 上へ / 下へ (兄弟の中で入れ替える。先頭・末尾では無効)
  - 移動 (移動先のグループを選ぶ。次の節)
  - 削除 (次の節)
- 追加した行は、名前が入力できる状態で出る
- キー操作 (Enter で行を追加する・Tab で字下げするなど)は設けない。メニューキーと Shift+F10 でメニューが開くのは、WinUI 標準の動き

### 移動
- 選んだ行 (グループなら、中身ごと)を、別のグループの下か、最上位へ移す。移動先は、木の一覧から選ぶ小さなダイアログ。ドラッグ & ドロップは設けない
- 自分自身と、自分の中のグループへは移せない (一覧に出さない)。移したあとは、移動先の末尾に置く

### 削除
- 確認ダイアログを出す。グループは、中身も一緒に消えるので、消える件数 (グループ・作業・日ごとの記録)を出す
- 論理削除 (`IsDeleted`)だけを行う。完全削除 (物理削除)は、ローカルモード・DB モードとも行わない (ユーザーの決定。[database.md](database.md))。削除した行は、画面に出さない

### 列の表示・非表示
- 設定ページまで行かず、この画面の中で切り替える。上のバーの「表示列」ボタンで、列の一覧 (チェック付き)を出す。名前の列は常に出す
- 非表示にした列の値は、消えない (見えないだけ。計算にも、そのまま使う)。保存先は設定ストア (`WorkItems.HiddenColumns`。この PC の設定。DB モードでも DB には置かない)
- 既定は、すべての列を出す

### グループの開閉
- 開いているか閉じているかは、設定ストア (`WorkItems.CollapsedItems`。この PC の設定)に持つ。再起動しても保つ

## データ
### 保存先 (`IWorkItemRepository`)
- 1 件単位の操作で書く (`AddAsync`・`UpdateAsync`・`MoveAsync`・`SetDeletedAsync`)。日ごとの記録は `SetRecordAsync`(同じ作業・日付があれば上書き、実績と日の備考が両方空なら消す)。読みは、自分の分だけ (`GetItemsAsync`・`GetRecordsAsync(日付)`・`GetRecordsAsync(作業)`・`GetChangesAsync(作業)`)
- 番号 (`Id`)は保存先が決める (`int`。リマインダーと同じ)。親は `ParentId` で指す (0 は最上位)
- 読み・書きはスレッドセーフ。変更後に `Changed` を発火する
- ローカルモード (JSON): `Data/WorkItems.json`・`Data/WorkRecords.json`・`Data/WorkItemChanges.json`・`Data/WorkProgressLevels.json`。どれも `{ "items": [...] }`。書き込みは、一時ファイル経由で置き換える
- DB モード: 次の表。表の決まり (共通ヘッダー・NULL を使わない・論理削除・外部キーなし)は [database.md](database.md) の「表の決まり」に従う。表の作成スクリプトは `src/Data/MmmTool.Data.SqlServer/Sql/` に番号つきで足す

### 表 (DB モード)
| 表 | 内容 |
| --- | --- |
| `dbo.WorkItem` | グループと作業。`ParentId`(0 は最上位)・`Kind`(グループ / 作業)・`SortOrder`・`Name`・`Note`・`Priority`・`StartDate`・`DueDate`(ない日は `9999-12-31`)・`Status`・`Progress`・`PlannedHours`(0 は予定なし) |
| `dbo.WorkRecord` | 日ごとの記録。`WorkItemId`・`Date`・`Hours`・`Note`。(`WorkItemId`, `Date`) は、削除されていない行の間だけ一意 |
| `dbo.WorkItemChange` | 変更の記録。`WorkItemId`・`ChangedAt`・`Field`・`OldValue`・`NewValue` |
| `dbo.WorkProgress` | 進捗度のマスター。`Value`・`Label` |

- 作業を作った人が、その作業の担当者 (`CreatedByUserId`)。担当者の列は、別に持たない
- **見えるのも編集できるのも、自分の分だけ**。取得の条件に、作成者が自分であることを入れる。他の人の分を見る画面は、ガントチャートなどの別の画面で作るときに設計する
- 同じ行を複数の人が同時に直すことは無いので、上書きの検出は要らない

## 部品 (SDK)
- `TreeGridView`: 木構造の列と、普通の入力列を持つ表。SDK の `MmmSdk.WinUI/Controls/` に置く (木構造の表は、どの機能にも属さない汎用の部品なので、機能の中に作らない)。見えている行を 1 つの一覧にならして持ち、各行が字下げの段と開閉の状態を持つ。行の高さは固定で、仮想化する。列の固定 (名前の列)と表示・非表示を受け付ける。仕様は SDK の `docs/controls.md` に書く
- 木構造・並べ替え・計算 (グループの日付・進捗度・予定時間・実績の集計)・マスターは、UI に依存しないので Core に置く

## 決定の理由
### WBS とガントチャートを別の画面にする
この画面は、入力して管理する表 (WBS)。ガントチャートは、日付を横に並べて見る別の表示で、操作も表示する内容も違う。1 つの画面に混ぜると、どちらの入力も遅くなる。ガントチャートは、この画面と同じデータを読む別の画面として作る。行の高さを固定にし、日付を行が持つ形にしてあるので、作るときにこの画面を直さなくてよい。

### 段数を固定しない
案件・区分・作業は、決まった 3 段ではなく、案件によって段数が変わる。固定にすると、段が足りない案件で作り直しになる。表の 1 列目を木構造にすれば、段数は自由なまま、1 画面で見える。

### グループと作業の 2 種類に分ける
作業に入力した値 (実績・進捗度など)があるまま、あとから子を足すと、その値を集計に混ぜるのか消すのか、決まりを作るたびに例外が増える。種類で分ければ、グループの値は常に子からの計算、作業の値は常に入力、と 1 通りで済む。種類の変更を設けないのも同じ理由 (変換のときの、実績の行き先の例外をなくす)。

### キー操作でなく、右クリックのメニューで階層を作る
Enter・Tab で行を足したり字下げしたりするのは、Excel のアウトラインの操作で、誤って階層が変わりやすい。メニューは、何が起こるかが文字で見え、行の種類 (グループ・作業)も同じ場所で選べる。追加した行をすぐ入力できる状態にして、追加後の手数を減らす。

### 予定時間は作業ごとの共通の値にする
日ごとに予定を持つと、実績 (日ごと)と意味が重なる。作業全体の見積りとして 1 つだけ持てば、実績の合計との比較と、グループの進捗度の重み付けに使える。

### 進捗度は数値で持つ
ラベルを直したときに、保存済みの作業を書き換えなくて済む。Backlog との対応づけも、数値で行える。

### 自分の分だけ見える
同時に同じ行を直すことが無くなり、上書きの検出を入れなくてよい ([database.md](database.md) の決定と合う)。他の人の分を見るのは、ガントチャートなど、見るための画面で設計する。

### 列の表示・非表示を、画面の中で切り替える
予定時間や進捗度は、入力が面倒になると使われなくなる。設定ページまで行く操作では、切り替えが続かない。画面の「表示列」ボタンなら、その場で切り替えられる。値は消さないので、戻したときに元に戻る。

### 状態と進捗度を連動させない
Backlog も独立している。「外部レビュー完了」(90)の次の 100 が、状態の完了と一致するとは限らない。連動させると、どちらかを直したときに、もう一方が意図せず変わる。

### 進捗度の値は固定し、マスターはラベルだけにする
値を自由にすると、作業が持つ数値とマスターがずれる。0 から 100 の 10 刻みに固定すれば、持つのは数値だけで済み、ラベルの付け外しだけがマスターの仕事になる。DB モードは全員に影響し、アプリにユーザーの権限の区別が無いので、画面に編集の口を出さない。

### 優先度・開始日・期限日・予定時間・実績 (累計)を左の固定部分に置く
あまり変えない項目 (優先度・日程・予定時間)と、積み上がった合計は、名前と並べて常に見えるほうが、全体の進み具合を見渡しやすい。毎日触る列 (状態・進捗度・実績 (日)・備考 (日)・備考)は、その右に、途切れずに並べる。

### 毎日入力する列を、背景の色で区別する
「どこに何を入れればよいか」で迷うと、入力が続かない。毎日入力する列だけを色で塗り、あまり変えない項目と区別する。優先度を左に置くのは、緑の列を 1 つの連続した帯にして、区別を分かりやすくするため。説明の文言は、画面を長くするので付けない。

### 完全削除をしない
削除は元に戻せる形 (論理削除)だけにする。ローカルモードも同じ。ファイルに残る削除済みの行が増えるが、作業の件数は人が手で入れる範囲なので、増え方は小さい。
