# CLI補助

CLI補助機能の仕様。

## 概要

- AI のコマンドラインツール (Claude Code・Kiro など)を使うときの補助画面
- ターミナルの下に送信欄を置き、定型コマンドの送信・送信履歴・添付を助ける
- 場所は `src/Plugins/MmmTool.CliAssist/` で、中は次のように分けている
  - `Main/`: 入口の画面
  - `WorkingDirectory/`: 作業ディレクトリ変更ダイアログ
  - `Setup/`: 初期設定ダイアログ
- Core 側は `src/Plugins/MmmTool.CliAssist.Core/`
- ターミナルとシェルの決定は SDK にある

## 画面

- 3 領域のレイアウト
  - 左に定型コマンドのツリー
  - 中央にターミナル
  - 下に送信欄
- ターミナルは SDK の `TerminalControl`(ConPTY + xterm.js (WebView2))
  - 入出力・リサイズに対応し、シェルが終了したあとは何かキーを押すと再起動する
  - セッション・画面・WebView2 の守り・出力の流量制御・シェルの決定 (PATH 上の pwsh.exe、無ければ Windows PowerShell)・シェル別の作業ディレクトリ変更コマンドは、SDK の `docs/terminal.md`(`external/MmmSdk/docs/terminal.md`)にある
  - アプリ側の使い方
    - `ITerminalSession`(SDK)を `PseudoConsoleSession` として DI に Transient で登録し、Host の破棄時に Dispose する (シェルも終了する)
    - 画面は `CliSessionView.xaml` (セッション 1 つ分の、ターミナルと送信欄の画面)の `TerminalControl` に `CliSessionViewModel.Terminal` を渡す
    - セッションは `CliSessionFactory` が作り、定型コマンド・環境・送信履歴を持つ `CliAssistViewModel` が持つ
  - ターミナルが起動していない (起動の直前・再起動の途中・WebView2 を初期化できなかった)ときと、シェルが終了しているときは、定型コマンド・入力欄の送信を捨てずに、InfoBar で知らせる (`CliSessionViewModel.TrySubmit`)
    - 送れなかったときは、入力欄・添付を残し、タブの切り替え・フォーカスの移動もしない
    - 作業ディレクトリ変更は、送れなくても、これから (再)起動するシェルの作業ディレクトリと履歴は更新する
  - 起動時の準備 (`CliAssistStartup`)で、既定のシェルの探索 (`ShellLocator.Default`)をバックグラウンドで済ませる
    - 探索は PATH の全項目へ触れる
    - UI スレッドで初めて探して止まらないようにするため
  - 補助スクリプトを動かすシェルは、ターミナルで使うシェルに合わせる (`ShellLocator.Default.FileName`)
    - シェルの中でシェル自身を呼ぶので、ファイル名だけを使う
  - 作業ディレクトリ変更は `ShellCommands.TryChangeDirectory(Terminal.Shell, …)` で行う
    - cmd でパスに `%` があると作れない (`false`)ので、移動せずにエラー表示する
  - xterm.js のファイル (`Assets/Terminal/`)は SDK の csproj が出力フォルダーへ配る。アプリの csproj には書かない。
- 作業ディレクトリ変更ダイアログ (最近使ったフォルダの履歴・フォルダ選択・存在確認)
  - 存在確認 (`Directory.Exists`)は、ネットワークパスで止まることがあるため、UI スレッドの外で行う
  - 入力欄の変更は少し待ってから確認する (SDK の `Debouncer` で、リンク編集のパスの種類の調べ方も同じ)
  - 起動時の作業ディレクトリ (`CliSettingsService.StartDirectory`)と、戻すタブ (`StartTabs`)も、読み込みの中でバックグラウンドで確認し、存在するときだけ使う
    - 戻すタブは、まとめて並行に確認する

## 複数のセッション (タブ)

- 中央のターミナルをタブにして、CLI を同時に複数動かせる
- 理由は、下の「複数のセッションをタブで持つ」
- 実装は次のとおり
  - `Main/` の `CliAssistViewModel`: タブの一覧・追加・閉じる
  - `CliSessionViewModel`: 1 タブ分
  - `CliSessionView`: 1 タブ分の画面
  - `CliSessionFactory`
  - Core の `SessionDirectory`: 同じフォルダの判定・タブ名
- 1 タブ = 1 セッション
  - シェル (ターミナル)・作業ディレクトリ・入力欄・添付 (一時保存先を含む)をタブごとに持つ
  - 入力欄はタブごとの下書きとして残る
  - 最初のタブは、前回のタブを戻す (下の「タブの復元」)
  - 戻せるタブが無いときは、前回の作業ディレクトリで始める
- 全タブで共通なのは、定型コマンドの内容・環境 (Windows / WSL)
  - 定型コマンドと送信は、選んでいるタブへ送る
- 送信履歴はタブごとに持つ (`SendHistory`を Transient で登録し、`CliSessionViewModel` が 1 つずつ持つ)
  - メモリ上だけで、タブを閉じる・アプリを終了すると消える
  - 履歴の Flyout には、選んでいるタブの履歴だけが出る
- 左ペインの「シェル / AI セッション」は、タブごとに持つ (`CliSessionViewModel.Category`)
  - そのタブのターミナルで、今シェルと AI セッションのどちらを動かしているかを表す
  - タブを切り替えると、左ペインがそのタブの値に変わる (ツリーは全部開いた状態に戻る)
  - 新しいタブはシェルから始める
  - シェルが終了したタブ (中の AI セッションも無くなる)と、「定型コマンドを初期化」のあとの全タブ (ターミナルを起動し直す)は、シェルへ戻す
  - タブの帯には、どちらかを示す印を出さない (左ペインで分かるため)
- 「定型コマンドを初期化」・環境の変更・機能のオフは、全タブに効く
  - 環境が変わったときは、全タブの添付を外し、全タブのターミナルを起動し直す
  - 機能をオフにするときの確認は、どれかのタブでターミナルが動いているときに出す
- 表示は、`TabView` をタブの帯だけに使う
  - 中身 (ターミナルと送信欄)は、帯の下の枠 (`SessionHost`)に、選んでいるタブの画面を入れる
  - 選択中のタブの枠線は、既定の薄いグラデーションでは背景と見分けにくいので、システムの「第 2 の枠線」の色 (`ControlStrokeColorSecondaryBrush`)に差し替える
  - 背景・文字・「×」の色は既定のまま
  - ライトとダークの辞書に書き、ハイコントラストは書かない
- 操作はマウスだけ (タブを開く・閉じる・切り替えるキーは足さない)
  - 「＋」: 作業ディレクトリ変更ダイアログ (題名「新しいタブ」・ボタン「開く」)を先に開き、選んだフォルダでタブを作って、そのタブを選ぶ
    - 選んだフォルダは、最近使ったフォルダの履歴と、次回の開始フォルダに記録する
    - 決定したパスは、末尾を `\` にそろえる
      - `D:` のままだと、シェルが「そのドライブで最後にいたフォルダ」と解釈して移動できないため
      - ドライブだけでなく、すべてのフォルダでそろえて、表記を統一する
    - フォルダボタンは、入力欄のフォルダでピッカーを開く
  - 「×」: 閉じる前に、いつも確認する
    - 題名「タブを閉じますか？」・ボタン「閉じる」「キャンセル」で、既定のボタンは置かない (SDK の確認ダイアログと同じ)
    - 閉じると、そのタブのシェルが終了し、一時保存した添付が消える (`CliSessionViewModel.Dispose`)
    - 選んでいたタブを閉じたときは、隣のタブを選ぶ
    - 最後の 1 タブには「×」を出さない
- タブ名はフォルダ名だけ
  - 同じ名前で場所が違うタブがあるときだけ、親フォルダ名を足す (`名前 (親)`)
  - それでも同じならパス全体 (`SessionDirectory.CreateTitles`)
  - 完全なパスはツールチップに出す
  - 長い名前は幅の上限で省略する (「…」)
- 同じフォルダのタブは、アプリが開く入口 (「＋」・作業ディレクトリ変更)で断る
  - ダイアログに「ほかのタブで開いているフォルダです」と出して、決定できなくする
  - パスの文字列だけで比べる (`SessionDirectory.IsSame`)
    - 区切り・末尾の区切り・大文字小文字は無視する
  - ターミナルの中で直接 `cd` して同じフォルダになっても、アプリは気づかず、止めない (ユーザーの決定)
    - アプリの外の操作で、別の PowerShell を自分で起動するのと同じ扱い
- タブの作業ディレクトリ (`CliSessionViewModel.WorkingDirectory`)は、アプリで選んだフォルダだけを反映する
  - タブ名・同じフォルダの判定・シェルの再起動時の開始位置に使う
  - 反映するのは、復元したタブ・最初のタブの開始フォルダ・「＋」・作業ディレクトリ変更
  - ターミナルの中で直接 `cd` しても、タブ名は変わらない (ユーザーの決定で、理由は下の「複数のセッションをタブで持つ」)
- タブの並べ替え: タブの帯の中でドラッグして動かす (`TabView` の `CanReorderTabs`)
  - ウィンドウの外へ出す切り離しはしない
  - ViewModel の一覧 (`Sessions`)をタブの並びに合わせる (`CliAssistViewModel.ReorderSessions`)
    - ドラッグ中はタブがいったん外れて選びが動くので、数がそろうまで反映せず、終わったら元の選びに戻す
- タブの復元: 開いているタブの作業ディレクトリ (並び順)と、選んでいたタブを `Data/CliSettings.json` に保存し、次回の起動で戻す
  - 保存するのは、追加・閉じる・並べ替え・作業ディレクトリ変更・選び直しのたび
  - 戻すのは構成だけで、各タブは空のシェルで始まる (CLI は自動では起動せず、続きは定型コマンドの「続きから再開」)
  - 入力欄の下書き・添付は戻さない
  - 存在しないフォルダのタブは戻さない (重複も除き、確認は読み込みの中でまとめて並行に行う)
  - 戻せるタブが無いときは、最後に作業ディレクトリを変えたタブのフォルダで 1 つ開く
- git worktree の管理はアプリに作り込まない (ユーザーの決定)
  - `claude --worktree` を定型コマンドに足せば足りる

## 初期設定 (使うツール・環境)

- 使う AI ツール (Claude Code / Kiro で、両方も可)と、動かす環境 (Windows (PowerShell)/ WSL)を選べる
- 理由は、下の「WSL でも動かす」 (環境)・「Claude Code と Kiro の選択」 (ツール)
- 選ぶのは、定型コマンドのファイル (`Data/CliCommands.json`)を作るとき (無い・壊れている)と、初期化するときだけ
  - 初期設定ダイアログ (`Setup/CliSetupDialog`)で選ぶ
    - ツールはチェックボックス、環境はラジオボタン
    - ツールを 1 つも選ばないと決定できない
  - 初回 (CLI補助のページを開いたとき): 題名「CLI補助の初期設定」・ボタン「作成」だけ
    - キャンセルは無く、Esc でも閉じない (ファイルを作るのに、選んだ内容が要るため)
    - 最初は Claude Code・Windows を選んだ状態
  - 選んだツールは、定型コマンドのフォルダとして作る (下の「定型コマンド」)
    - ツールは別には保存しない (フォルダの中身そのものなので)
    - 環境は、ファイルの `"environment": "windows" | "wsl"` に書く
    - 省略・この項目が無い古いファイルは Windows。知らない値は Windows として動かし、InfoBar で知らせる。
  - 変えるときは、左ペインの「⋯」 (その他)メニューの「定型コマンドを初期化…」を選ぶ (`CliAssistViewModel.ResetCommandsAsync`)
    - めったに使わない・取り消せない操作なので、常に見えるボタンにせず、メニューに入れる
    - 初期設定ダイアログが、題名「定型コマンドを初期化」・ボタン「初期化」「キャンセル」で開く
    - 既定のボタンは置かない (取り消せない操作なので Enter で実行させず、キャンセルを既定にして強調色にすると主な操作に見えるため)
      - SDK の確認ダイアログと同じ
    - 消えるもの・終了するものの警告 (InfoBar)を出す (確認のダイアログを別に重ねず、1 つで済ませる)
    - あとで変える方法の案内は、初回だけ出す (初期化のときは、今まさにその方法で開いているため)
    - 環境とツールは、今の値を選んだ状態から始める
      - ツールは、最上位のツールのフォルダの表示名から読む (`CliCommandSet.GetTools`)
      - 読み取れなければ Claude Code だけ
    - 決定すると、その既定で `CliCommands.json` を上書きする (Repository の `SaveAsync`)
      - 今の内容は引き継がず、退避もしない (ユーザーの決定)
    - ターミナルは、環境が変わらなくても、いつも起動し直す (ユーザーの決定)
      - SDK の `TerminalControl.RestartSessionAsync` を使う
      - 起動し直すには端末の大きさが要るので、`CliSessionViewModel` は `TerminalRestartRequested` で View に頼む
      - タブはシェル側に戻す
    - 環境が変わったときは、添付をすべて外す (パスの形・一時保存先が環境ごとに違うため)
      - 一時保存した添付は、切り替える前の環境の保存先から消す
      - 入力欄の本文は残す
  - アプリを終了してから `Data/CliCommands.json` を消しても、次に開いたときに選び直せる
- 環境で決まるもの
  - ターミナルで起動するシェル
    - Windows は既定のシェル (`ShellLocator.Default`)
    - WSL は `wsl.exe`(`ShellLocator.Wsl`)で、既定のディストリビューションの既定のシェル
    - 定型コマンドを読み込んでから決めるので、ターミナルは読み込み (`CliAssistViewModel.InitializeAsync`)が済んでから画面につなぐ
    - つなぐのは `CliAssistPage.OnLoaded` が `CliSessionView.ConnectTerminal` を呼ぶときで、つないだときに起動する
  - 既定の定型コマンド: 違うのは Claude Code の「会話履歴の削除」の補助スクリプトだけ ([cli-history-cleanup.md](cli-history-cleanup.md))
  - 貼り付けた画像の一時保存先 (下の「添付」)
- 設定でオフにできる ([settings.md](settings.md) の「機能のオン・オフ」)
  - オフにすると、ページ (ターミナルのセッション・入力欄・添付の一覧)を捨てて、シェルとその中の CLI を終了する
  - オンに戻すと、ページとセッションを新しく作る
    - 入力中の内容・添付は引き継がない
    - 一時保存した添付は、ページと一緒に消える
  - 起動時にオフなら、CLI補助の準備 (利用状態の読み込み・シェルの探索)も行わない
- 今どちらの環境で動いているかは、ターミナルのシェルの種類 (`Terminal.Shell.Kind`)1 か所で見る
- WSL では、シェルへ渡すパスを Linux の形にする (SDK の `ShellCommands.TryConvertPath`・`WslPath`)
  - 例: `D:\work` → `/mnt/d/work`、`\\wsl.localhost\Ubuntu\tmp\a.jpg` → `/tmp/a.jpg`
  - 画面 (作業ディレクトリ変更ダイアログ・添付の一覧・履歴)は Windows のパスのまま扱い、送るときだけ変換する
  - 作業ディレクトリ変更は `cd -- '/mnt/d/...'`(SDK の `ShellCommands.TryChangeDirectory`)で行う
    - WSL から開けないフォルダー (`\\server\share` などのネットワークのフォルダー)は、移動せずにエラー表示する
    - シェルの再起動時の開始位置 (`Terminal.WorkingDirectory`)は Windows のパスのまま (wsl.exe が変換する)
  - 添付は、送るときに変換する
    - WSL から開けない場所のファイルは、添付するときに断ってエラー表示する (送ってから読めないと分かるより、先に分かるほうがよいため)
  - 定型コマンドの `{AppDir}` は、WSL では `/mnt/d/...` に展開する

## 定型コマンド

- 「シェル」と「AI セッション」の 2 タブ固定
  - 「ターミナル」は中央のペインの名前で、タブとは別
  - ターミナルは「シェルのタブ」「AI セッションのタブ」のどちらのコマンドも受け取る
  - 最初は全部開いた状態 (開閉は自由で、タブを切り替えると開いた状態に戻る)
- 左ペインは幅 280px
- 長い名前は横スクロール (TreeView 内の ScrollViewer に Loaded で設定する)
- JSON は `shell` / `session`(列挙型は `CommandCategory.Shell` / `Session`)
  - どちらのタブも、初期設定で選んだツールごと (Claude Code・Kiro)にフォルダで分ける
  - 並びは Claude Code → Kiro
  - 作業ディレクトリ変更はシェル側の先頭
- 既定のコマンドは `CliCommandDefaults` で定義する
  - ツールどうしで、同じ働きのコマンドは同じ表示名・同じ順にそろえる
  - Kiro のコマンドは公式ドキュメント (kiro.dev の CLI commands・Slash commands)で確かめた

  | 表示名 | Claude Code | Kiro | 備考 |
  | --- | --- | --- | --- |
  | 起動 | `claude` | `kiro-cli chat` | |
  | 続きから再開 | `claude --continue` | `kiro-cli chat --resume` | |
  | 履歴から選んで再開 | `claude --resume` | `kiro-cli chat --resume-picker` | 会話の一覧から矢印キーで選ぶ画面が開く。引数なしの `--resume` / `--resume-picker` を使う。選ぶ操作のため、送信後はターミナルへフォーカスを移す。Kiro の `--list-sessions` は一覧を表示するだけで選べないので使わない |
  | 最新化 | `claude update` | `kiro-cli update` | |
  | 会話履歴の削除 | 補助スクリプト `Remove-ClaudeSession` ([cli-history-cleanup.md](cli-history-cleanup.md)) | 補助スクリプト `Remove-KiroSession` ([cli-history-cleanup.md](cli-history-cleanup.md)) | Kiro は履歴を 1 つの SQLite (`~/.kiro/`)に持つので、ごみ箱へは送らず、公式コマンドで消す (戻せない) |
  | 新規チャット | `/clear` | `/chat new` | Kiro の `/clear` は同じ会話のまま中身を消すだけなので使わない |
  | 読み込みファイル一覧 | `/context` | `/context` | |
  | 会話要約 (コンテキスト圧縮) | `/compact` | `/compact` | |
  | CLAUDE.md を作成 / steering を作成 | `/init` | 作成を頼む文 | Kiro の CLI に `/init` は無いので、`.kiro/steering/` に product.md・tech.md・structure.md (Kiro の IDE の「Generate Steering Docs」と同じ 3 つ)を作るよう頼む文を送る (ユーザーの決定) |
  | モデル切替 | `/model` | `/model` | |
  | 会話履歴と再開 | `/resume` | `/chat` | |
  | コスト確認 / 使用量の確認 | `/cost` | `/usage` | Kiro は料金・残りクレジットを出す |
  | 終了 | `/exit` | `/quit` | |

- 葉のコマンドの設定は、値を列挙型 `CommandCategory` / `FocusTarget`(Core)に変換する (`CliCommandNode.GetSwitchTo()` / `GetFocus()`)
  - 手で編集した JSON なので、大文字小文字は区別せず、知らない値は読み込みでは無視する
  - ただし、書き間違いに気づけるよう、読み込んだあとに `CliCommandSet.Validate()` で調べ、誤りを画面の警告 (InfoBar)に出す
  - `"switchTo": "shell" | "session"`: 送信後にそのタブへ切り替える
    - 既定では「起動」「続きから再開」「履歴から選んで再開」→ AI セッション、「終了」→ シェル
  - `"focus": "terminal" | "input"`: 送信後のフォーカスの移動先 (input = 送信欄)
    - 既定では、起動・新規チャット → input
    - 履歴から選んで再開・モデル切替・会話履歴と再開 → terminal (一覧から選ぶ操作でキーを使うため)
- 文字列中の `{AppDir}` は、送信時に EXE のフォルダへ展開する (`CommandPlaceholders`)
- 既定のコマンドを増やしても、生成済みの `Data/CliCommands.json` には反映されない (無いときだけ生成)
  - 反映するには「定型コマンドを初期化…」を選ぶ (上の「初期設定 (使うツール・環境)」)
- 既定のコマンドの定義は Core にある (`src/Plugins/MmmTool.CliAssist.Core/CliCommandDefaults`)
  - 画面に依存しない
  - Windows 専用の `ShellLocator` を使うので `[SupportedOSPlatform("windows")]` を付ける
    - BCL だけで書ける処理は Windows 専用でも Core に置く決まり (SDK の `Paths`・`Shells` と同じ)
  - 環境・ツールを読む `CliCommandSet.GetEnvironment` / `GetTools` と同じ場所にそろえる
  - Core の `JsonCliCommandRepository` には「既定を作る処理」を DI で渡す
    - 初回の初期設定ダイアログを開いてから、その既定を作る (非同期)
    - Core が画面を知らないようにするため
    - 補助スクリプトの置き場は、プラグインのプロジェクトが `Assets/Tools` へ配る
  - Windows では、補助スクリプトを動かすシェルを、ターミナルで使うシェル (`ShellLocator.Default`)に合わせる (pwsh が無い環境でも動く)

## 送信

- 送信は Ctrl+Enter
  - `ITerminalSession.Submit` → xterm.js の `term.paste`(ブラケットペースト)で貼り付け、そのあと Enter で確定する
  - 複数行でも CLI がひとまとまりで受け取る
- Enter を送るタイミングは、貼り付け後に一度出力があり、それが 200ms 途切れたとき (最低 150ms・最長 2 秒)
  - 理由は、下の「送信の Enter のタイミング」
- 送信履歴は、Flyout に最大 50 件・絞り込み付きで出す
  - 保存せず、メモリ上だけに持つ (Core の `SendHistory`)
  - 空白のみは無視し、同じ本文は先頭へ移す
  - 絞り込みは前後の空白を無視し、大文字小文字を区別しない

## 送信欄

- 入力欄は 3 行分の高さで固定する (超えた分は欄内スクロール)
  - 入力で伸びるとターミナルが縮み、CLI が全画面を描き直してちらつくため
  - 固定値だとフォントによって下だけ余る・欠けるので、読み込み時に「1 行の実測の高さ × 3 行 + 余白・枠」で決める (`FitInputBoxToThreeLines` で、XAML の 64px は初期値)
- 入力欄にフォーカスが来たら IME をオンにする (SDK の `ImeControl.TurnOn` で、日本語をすぐ打てるように)
- 入力欄は高さが固定なので、キャレットが表示の外に出てもスクロールされないことが、まれにある
  - `InputBox.KeepCaretVisible()` (SDK の `TextBoxExtensions`)で、外に出たときだけ見える位置までスクロールする
  - `CliSessionView` のコンストラクターで 1 回呼ぶ
  - 仕組みは SDK の `docs/controls.md`
- 添付の行 (高さ 48px)は、添付があるときだけ出す (高さが変わるのは最初の添付時と送信時だけ)
- 操作の説明はプレースホルダーに入れる
- エラーの InfoBar は、レイアウトに場所を取らず、ターミナルの上部に重ねて表示する

## よく使う文

- 入力欄が空のときだけ、入力欄の中の下端に、編集の鉛筆ボタンと、小さなチップ (角の丸いボタンで、強調色なし)を横に並べる (`Main/QuickMessageBar`)
  - 鉛筆ボタンが先頭で、チップが多くても、先頭の位置から動かない。文が 0 件でも出す
  - 文字を打ち始める・文を入れると消える
  - 入力欄の高さは変えない
  - 出す条件は入力欄のテキストが空かどうかだけなので、添付があってもテキストが空なら出る (`CliSessionViewModel.ShowQuickMessages`)
  - 鉛筆ボタンを送信欄の右のボタンの列に置かない (編集する文のチップの隣に置くと、何のボタンかが分かり、送信の上は履歴だけになるため)
- チップは、幅に収まる分だけを並べ、収まらない分は右端の「⋯」 (ツールチップ「その他のよく使う文」)の一覧に出す
  - 収まらないときだけ「⋯」を出し、チップの並びは右に「⋯」の分を空ける
  - 配置は SDK の `OverflowRowLayout` (`external/MmmSdk/docs/controls.md`)
  - 横にスクロールさせない (スクロールバーを隠した行は、マウスのホイールで動かず、右の文の存在に気づけないため)
  - 「⋯」の一覧に出るのは、隠れたチップだけ。グループは、中の文のサブメニューを持つ項目として出る。
- グループのチップ (名前の右に「▾」)を押すと、中の文の一覧が開く。グループは 1 段だけで、グループの中にグループは入れない。
  - 一覧の項目を押すと、文のチップと同じに入力欄へ入る
  - 文が 0 件のグループは、チップに出さない。押しても何も開かないため。編集画面には残る。
- 文のチップを押すと、その文が入力欄に入る (送信はしない)
  - 入力欄にフォーカスを移し、カーソルを末尾に置く
  - ツールチップに全文を出す
- 文とグループは `Data/CliQuickMessages.json` に持つ。編集画面 (下)で書くか、手で書く。
  - ファイルが無いときは何も出さず、ファイルは、編集画面で保存したときに作る
  - 手で直したあとは、アプリの再起動で反映する (読み込みは起動時の 1 回で、編集画面は、開くとき、メモリの内容から作る)

  ```json
  [
    { "label": "コミット・PR", "text": "OKです。コミット・push・PRマージしてください" },
    { "text": "続けてください" },
    {
      "label": "レビュー",
      "items": [
        { "label": "コードレビュー", "text": "コードレビューしてください" },
        { "text": "指摘に対応してください" }
      ]
    }
  ]
  ```

  - `text`: 入力欄に入れる文 (文は必須で、複数行は `\n`)
    - 空の文は出さない
  - `label`: チップの表示名
    - 文は省略可で、省略すると `text` の 1 行目
    - グループはグループ名
  - `items`: グループの中の文 (`{ label?, text }` の配列)
    - `items` があれば、`text` があってもグループとして読む
    - 空の配列は、文が 0 件のグループ
    - グループの中の `items` は読まない。中の項目は、`text` があれば文として読む。
    - 名前の無いグループは、チップに「(未入力)」と出す
  - JSON として読めないファイルは、SDK の `JsonFileStore` が別の名前へ退避する (元の名前のファイルは無くなり、作り直さない)
    - 空の一覧で動き、InfoBar で「直して名前を戻し、再起動する」案内を出す
    - 退避した名前は、SDK のメッセージに含まれる
- 全タブで共通で、シェル・AI セッションのどちらのタブでも出す (`CliQuickMessageService`)
- 編集画面 (`QuickMessages/QuickMessageWindow` で、題名「よく使う文の編集」)は、チップの行の先頭の鉛筆ボタン (ツールチップ「よく使う文を編集」)で開く
  - 文が 0 件でも開ける
  - 大きさを変えられるウィンドウで、親ウィンドウの上にモーダルで出す (`QuickMessageDialogService`が `IDialogHost.ShowModalAsync` で開く)
    - ContentDialog にしない (大きさを変えられず、項目が増えると、ツリーがスクロールして、ドラッグ中の端の自動スクロールで狙った行へ落とせないため)
    - 開くときは、幅 800 × 高さ 500 DIP の黄金比の横長にする (ただし、高さは親のいるモニターの作業領域に収める)
      - アプリの高さに合わせて縦長にしない (縦に伸びる形は、画面の決まりに反し、アプリが大きいほどウィンドウが大きくなりすぎるため)
      - 項目が多いときは、利用者が縁をドラッグして広げる
    - 最小は 560 × 400 DIP。最大化・最小化はできない。
    - 左のツリーと右の入力欄は、ウィンドウの大きさに合わせて伸びる。文の入力欄は、残りの高さいっぱいに伸びる。
    - 大きさは保存せず、開くたびに同じ大きさで開く (保存すると、広げた大きさが次回の開き方を決めてしまうため)
    - × で閉じたときは、「キャンセル」と同じ (変更を捨てる)
  - 左にツリー (`TreeView`)と、その下に「文を追加」「グループを追加」「削除」のボタンを置く
    - 行の名前は、表示名で、無ければ文の 1 行目、どちらも無ければ「(未入力)」
    - 作りは MmmTool.Links の編集画面と同じで、`ItemsSource` に `ObservableCollection`・`CanDragItems`・`CanReorderItems`を使い、グループの行だけ `AllowDrop` にする
    - 選択の取り出しは SDK の `TreeViewExtensions`
    - 追加する場所は、「文を追加」が選んだグループの中の末尾か、選んだ文の直後で、未選択なら末尾。「グループを追加」は、選んだグループ (文なら、それが入っているグループ)の直後で、未選択なら末尾。
    - 追加したら、その項目を選び、右の入力欄 (グループは「グループ名」、文は「文」)にフォーカスを移す
    - 行を右クリックすると、その行を選んで、メニューを出す
      - 項目は、「文を追加」「グループを追加」、区切り線、「削除」。グループの行も、文の行も、同じ。
      - 追加と削除は、左下のボタンと同じ動きで、追加する場所も同じ
      - 何も無い所では、メニューを出さない。追加は、左下のボタンで行う。
      - 「削除」の確認の吹き出しは、右クリックした行のそばに出す
      - 「上へ」「下へ」と名前の変更は入れない。並べ替えはドラッグで、名前の変更は右の入力欄で行うため。
      - 作りは MmmTool.Links の編集画面と同じで、右クリックの処理は、行の中身が処理済みにするので、処理済みでも受け取る (`handledEventsToo`)
    - 「削除」は、グループなら中の文もまとめて削除する
      - 中に文があるグループだけ、確認を出す。空のグループと、文の削除には出さない。
      - 確認は、「削除」ボタンの上に出る吹き出し (`Flyout`)で、題名「○○を削除しますか？」、本文「中の ○ 件の文もまとめて削除されます。」、ボタン「削除」「キャンセル」
      - ダイアログを重ねない。ContentDialog の上には、別のダイアログを開けないため。
      - 保存するまでは、ダイアログの「キャンセル」で戻せる
  - 行をドラッグして、並べ替えと、グループへの出し入れをする
    - 上へ・下へのボタンは、置き場所がわかりにくいので作らない
    - グループの中にグループは入れない
      - グループをドラッグしている間は、グループの行の `AllowDrop` を外す
        - `DragItemsStarting` のたびに決め直し、文をドラッグするときは戻す
      - グループの中の文の間へ落ちたグループは、`AllowDrop` では防げない。ドロップの処理が終わってから、入った先のグループの直後へ出す (`QuickMessageWindowViewModel.MoveNestedGroupsOut`)
      - ドラッグの終わりの通知 (`DragItemsCompleted`)で戻す作りにしない。設定の機能の一覧 (`ListView`)で届かなかったため、`TreeView` でも当てにしない。
  - 右に、選んだ項目の入力欄を置く
    - 文は「表示名 (省略可)」と「文」(複数行)
    - グループは「グループ名」
  - 下に「保存」(強調色)・「キャンセル」を置く。キャンセルは変更を捨てる。
  - 「保存」で、ファイルに書き、全タブのチップにすぐ反映する (`CliQuickMessageService.Changed`)
    - 文が空の項目があるときは、その項目を選び、「文が空の項目があります。入力するか、削除してください」を出して、閉じない
    - グループ名が空のグループがあるときも、そのグループを選び、「グループ名が空の項目があります。入力するか、削除してください」を出して、閉じない
    - 確かめる順は、画面に出る順 (グループ、その中の文、次のグループ)で、最初に見つけた 1 件だけを出す
    - 保存に失敗したときも、閉じずにエラーを出す
  - 読み込みに失敗している (ファイルを読めなかった)ときは、読めなかったファイルを上書きしないよう、画面を開かずに、理由を InfoBar で知らせる
  - 手で書いたファイルは、保存すると、整った形に書き直される

## 通知する文字列

- ターミナルの出力に、利用者が決めた文字列が出たら、タブとサイドバーで知らせる。知らせ方は、下の「移す条件」の、選んでいないタブの黄色とサイドバーの丸と同じ。文字列ごとの「ターミナルへ移る」がオンのときは、ターミナルへフォーカスも移す
  - CLI の確認 (許可の確認など)に、矢印キーや Enter で答えるときに、入力欄からターミナルへ移る手間を省くため
  - 「ターミナルへ移る」がオフの文字列は、知らせるだけで、フォーカスを移さない。表示していなかったタブを選んだときも移さず、黄色だけ消す。
  - 見張りは、オンの文字列とオフの文字列で 2 つに分ける。分けるのは `CliSessionViewModel`。見張りは最初に見つけた 1 つで止まるので、混ぜると、オフの文字列が先に出たとき、オンの確認を逃す。
  - 同じ文字列がオンとオフの両方にあるときは、移すほうが勝つ
  - 選んでいないタブで、オフの文字列がオンの文字列のあとに続けて出ても、移す指定は取り消さない
  - 表示中のタブでは、オフの文字列に対して何も起きない。知らせは、選んでいないタブとほかのページを開いている間だけ。
  - 文字列は `Data/CliFocusTriggers.json` に持つ。編集画面 (下)で書くか、手で書く。
  - ファイルが無いときは何もせず、ファイルは、編集画面で保存したときに作る
  - 初期の文字列は入れない (CLI の文言は版で変わり、確かめていない文言を入れると、合わないときに動かない理由が分からなくなるため)
  - 手で直したあとは、アプリの再起動で反映する (読み込みは起動時の 1 回で、編集画面は、開くとき、メモリの内容から作る)
- ファイルの形は `{ text, moveToTerminal }` の配列
  - `{ label?, text }` のよく使う文のファイルと同じく、後から項目を足しても、書いたファイルが読めなくなる形にする
  - `moveToTerminal` は省いてよく、省くと `true` (移す)
  - 空の項目は使わない
  - 読めなかったときと壊れていたときの扱いは、よく使う文のファイルと同じ (`CliListFileService`)
  - 壊れていたときは退避し、使われないことを InfoBar で知らせる

  ```json
  [
    { "text": "Do you want to proceed?", "moveToTerminal": true },
    { "text": "Allow this action", "moveToTerminal": false }
  ]
  ```

- 編集画面 (`FocusTriggers/FocusTriggerDialog` で、題名「通知する文字列の編集」)は、左ペインの「⋯」 (その他)メニューの「通知する文字列…」で開く
  - 画面に何も出ない設定で、めったに使わないので、常に見えるボタンにせず、メニューに入れる (ユーザーの決定)
  - 1 行に 1 つの文字列を、入力欄・「ターミナルへ移る」のチェック (初期はオン)・「削除」のボタンの順で並べ、下に「追加」を置く
    - 文字列の並びに意味は無いので、並べ替えは付けない
    - 「追加」で足した行の入力欄に、フォーカスを移す
    - 一覧は高さを固定した枠の中でスクロールし、項目の数でダイアログの大きさを変えない
  - 上に、何をする文字列かを 1 行で説明する
  - 下に「保存」(強調色)・「キャンセル」を置く。キャンセルは変更を捨てる。
  - 「保存」で、ファイルに書き、全タブの見張りの文字列にすぐ反映する (`CliFocusTriggerService.Changed`)
    - 文字列が空の項目があるときは、その項目の入力欄にフォーカスを移し、「文字列が空の項目があります。入力するか、削除してください」を出して、閉じない
    - 保存に失敗したときも、閉じずにエラーを出す
  - 読み込みに失敗している (ファイルを読めなかった)ときは、読めなかったファイルを上書きしないよう、画面を開かずに、理由を InfoBar で知らせる
  - 手で書いたファイルは、保存すると、整った形に書き直される
- よく使う文と同じ、手で書いてもよい一覧のファイルの読み書きは、`CliListFileService` と `JsonCliListFileRepository` で共通にする (一覧のファイルが増えても、読み込みの失敗・退避・保存の処理を写さないため)
  - ContentDialog の編集画面を開く処理は、`CliEditDialogService` で共通にする (通知する文字列の編集)
  - ウィンドウの編集画面 (よく使う文の編集)は、`CliEditDialogService` を使わず、`QuickMessageDialogService` が開く

- 探し方は SDK の `TerminalOutputWatcher`(`external/MmmSdk/docs/terminal.md`)
  - 制御文字と空白を除き、大文字小文字を区別せずに探す。書く文字列のほうも、空白を除いて比べる。
  - 文字列を探す処理は SDK に置く (制御文字を除く処理が SDK にあり、アプリに写さないため)
  - 持つのは文字列の一覧だけで、アプリ側 (`CliSessionViewModel`)に置く。CLI ごとの文言は、SDK に書かない。
- 移す条件
  - 入力欄が空のとき (打ちかけの文字が、ターミナルへ入ってしまわないようにするため)
    - 添付があっても、テキストが空なら移す
  - 画面に出ているタブで、CLI補助のページを開いていて、ウィンドウが見えているとき (`CliSessionView.IsLoaded` と `XamlRoot.IsHostVisible`)
    - 選んでいないタブと、ほかのページを開いている間は、その場では移さない。見えていないタブやページを、勝手に切り替えて見せないため。
    - その間に文字列が出たタブは、確認待ちとして覚える (`CliSessionViewModel.IsAwaitingInput`)
      - そのタブへの通知として、タブの背景を 3 回明滅させたあと、黄色のまま残す。実装は `AwaitingTabHighlight`。3 つのタブを並行して動かすとき、どのタブが待っているかを分かるようにするため (ユーザーが選んだ)
        - 色は、ライトとダークそれぞれの固定の黄色にする。OS のアクセント色に連動させない (設定次第で暗い色になり、見分けにくくなるため)
        - 入力欄に下書きがあるタブにも、黄色は付ける。下書きがあっても、待っていることは知らせたいため
      - そのタブの画面が出たとき (タブを選んだとき・CLI補助のページに戻ったとき)に、黄色を消して、ターミナルへフォーカスを移す (`CliSessionView.OnLoaded`)
        - 入力欄が空で、ダイアログを開いていないときだけ移す。移さなかったときも、黄色は消す。入力欄に下書きがあるタブを選んだときは、入力欄にフォーカスが残る。
        - 表示したときのフォーカスは入力欄が基本 (下の「複数のセッションをタブで持つ」)だが、確認待ちのタブだけはターミナルにする
      - サイドバーの「CLI補助」の項目の右端にも、どれかのタブが待っている間だけ、知らせの丸を出す。出し入れは `INavigationService.SetBadge` で行う。ほかのページを見ていて、タブの黄色が目に入らないため。
        - CLI補助のページを開いている間は、丸を出さない。待っているタブの黄色が見えているため。
        - 待っているタブが無くなったとき、タブを閉じたとき、機能をオフにしたときに消す。
      - シェルの終了・起動し直し・通知する文字列の保存では、待っている印を解く。確認が、もう出ていない恐れがあるため。
    - トレイに隠れているときと最小化しているときは、移さず、覚えもしない。ページは画面の木に残るので、`IsLoaded` だけでは見分けられないため。
  - ダイアログを開いていないとき (`VisualTreeHelper.GetOpenPopupsForXamlRoot` の中に ContentDialog が無いとき)
    - 開いている間に移すと、入力欄に打っている途中の文字が、後ろの CLI に入って、確認に答えてしまうため
  - ウィンドウを前面に出さない (ウィンドウの中のフォーカスを移すだけ)
- 一度移したら、ターミナルに利用者の入力が送られるまで、探すのを止める (ユーザーの決定)
  - Claude Code は同じ確認の枠を何度も描き直すので、止めないと、入力欄をクリックしても、描き直しのたびにターミナルへ戻されるため
  - 移さなかったとき (入力欄に文字があった・画面に出ていなかった)も、止める
    - 探しつづけると、あとで入力欄が空になった途端に、描き直しで急に移るため
  - 入力は `ITerminalSession.InputWritten` で知る。キー入力と入力欄からの送信が当たる。
    - xterm.js が自動で返す報告 (フォーカスの出入り・マウス・端末の問い合わせへの返事)は含めない
    - 含めると、入力欄をクリックしたときのフォーカスの報告が「入力」と数えられ、探しが再開して、ターミナルへ戻されるため
- 入力のあとの描き直しでは、探さない (ユーザーの決定)
  - 入力の直後は、CLI が画面全体を描き直し、前の会話に出た文字も出力に出る。これを探すと、確認でもない文字で、入力欄からターミナルへ戻されるため
  - 入力のあと、出力が 150 ミリ秒途切れるまで探さない。出力が途切れなくても、入力から 500 ミリ秒で探し始める (考え中のスピナーなどで、本物の確認を逃さないため)
  - 詳細は SDK の `docs/terminal.md` の「出力の監視」
- 書いた文字列で、意図せずフォーカスが移ることは、利用者の責任 (ユーザーの決定)
- 文字列を保存したら、全タブで探しが最初からやり直しになる。確認が出たままの画面で保存すると、閉じた直後にターミナルへ移ることがある。

## 添付

- 画像は Ctrl+V で貼り付け (JPEG に変換)
- ファイルはドラッグ＆ドロップまたは貼り付け (エクスプローラーでコピーしたもの)
- フォルダーは添付しない
  - フォルダーを送信欄にドロップしたときは、添付の代わりに、そのパスを入力欄の選択範囲へ入れる (選択範囲があれば置き換え、入れた文字の後ろにカーソルを置く)
    - 処理は `CliSessionView.PasteFolderPaths` と `CliSessionViewModel.CreateFolderPathText`
    - パスは、シェルから見た形に変換して、`"` で囲み、複数は空白で区切る
      - WSL では、`D:\work` が `/mnt/d/work` になる
      - 入力欄の文字は、送るときに変換できないので、入れる時点で変換する
      - 空白の有無で形が変わらないよう、すべて囲む (ユーザーの決定)
      - 区切りは、改行にしない。シェルのタブで送ると、フォルダーごとに別のコマンドとして実行されるため
    - WSL から開けない場所 (`\\server\share` などのネットワークのフォルダー)は、入れずにエラー表示する。添付・作業ディレクトリ変更と同じ扱い
    - ファイルとフォルダーを一緒にドロップしたときは、ファイルは添付し、フォルダーはパスを入れる
    - ドラッグ中の案内は、フォルダーだけなら「パスを貼り付ける」、ファイルを含むなら「添付する」
      - 中身の種類は、ドラッグが入ったとき 1 回だけ、`OnComposerDragEnter` で調べる
      - ドラッグ中に何度も呼ばれる `OnComposerDragOver` では調べない
    - Ctrl+V のフォルダーの貼り付けは、今までどおり何もしない (ドロップだけが対象)
- 入力欄の貼り付けのイベント (`OnInputPaste`)の中で、`Clipboard.GetContent()` などのクリップボードの取り出しをしない (コピー元の返事を待つ間に画面の操作が割り込み、WinUI が内部で失敗して、固まったあとに落ちるため)
  - ファイルか・画像だけかは、SDK の `ClipboardFormats` で決め、添付するときだけ、イベントのあとに中身を読む
  - テキストは入力欄の標準の貼り付けに任せる
- 元がディスク上のファイルかどうかで扱いを分ける (`AttachmentItem.IsTemporary`)
  - **ディスク上のファイル**(ドロップ・貼り付けしたファイル): コピーせず、元のパスをそのまま送る (`CliSessionViewModel.AddAttachmentFile`)
    - ローカルで動く CLI は元の場所のファイルを直接読めるので、置き場所 (どのプロジェクトのファイルか・隣のファイル)も AI の手がかりになる
    - 今どきのローカルの AI ツール (VS Code の Copilot Chat など)と同じ形
    - 取り除く (× ボタン)ときは一覧から外すだけで、元のファイルは決して消さない
  - **ファイルではないもの**(クリップボードの画像)と、**パスの無いファイル**(メールの添付ファイルなど、ディスク上に無いもので、`StorageFile.Path` が空)は、一時保存して、そのパスを送る
    - 処理は `AddAttachmentImageAsync` / `AddAttachmentContentAsync`
- WSL の環境では、一時保存先を WSL の /tmp にする
  - 場所は `\\wsl.localhost\<既定のディストリビューション名>\tmp\MmmTool\session_日時\` で、CLI へは `/tmp/MmmTool/...` で渡す
  - SDK の `AttachmentStore.ForWsl` を使う
    - DI は環境ごとのキー付きの Transient で、タブごとに 1 つずつ作り、タブ (`CliSessionViewModel`)が今の環境のほうを使う
  - 終了時の削除・古いものの掃除はしない (ユーザーの決定で、WSL の /tmp は、systemd が有効なら WSL の起動のたびに空になる)
  - 送信前に × で取り除いたものは、すぐ削除する
  - ディストリビューションが見つからない (WSL が入っていない)ときは、添付が失敗して InfoBar に出る
- Windows の環境では、一時保存は `%TEMP%\MmmTool\session_日時\` に連番で保存する
  - SDK の `AttachmentStore` を使い、フォルダ名はアプリ側が `"MmmTool"` を渡す
  - 送信前に取り除いたものはすぐ削除する
  - 送信後は一覧だけ空にし、ファイルはタブを閉じるとき・機能をオフにするとき・終了時に削除する (`AttachmentStore.Dispose`)
  - 1 日より古い残りは、次回の初回添付時に削除する
  - フォルダは Debug / Release など別の場所の EXE と共有するので、同時に動いている別ビルドの 1 日より古いセッションも消える
    - これは想定内 (ユーザーの決定で、理由は SDK の `docs/controls.md`)
- 送信時は、本文のあとに指示文と各ファイルの絶対パス (1 行ずつ)を付ける (Core の `SendText.Compose`)
  - 指示文は `次のファイルも参照してください (バイナリでも読めるものは読む)。これらのファイルを変更するのは、上記の指示で求められたときだけにしてください`
  - 元の場所のファイルを渡すので、AI が頼まれていないのに書き換えないようにする
  - ただし「このファイルを直して」のように頼んだときは直してほしいので、一律には禁じず、本文の指示に従わせる
  - 本文が無い (空白だけ)ときは、指す先の「上記の指示」が無いので、「上記の指示に関連して」「上記の」を外した言い回しにする
- サムネイルは SDK の `ThumbnailImage.FromFile`(ファイルを開いたままにしない＝削除できなくならないよう、中身をメモリに読み込んでから表示する)
- JPEG への変換も SDK の `IImageConverter`(詳細は SDK の `docs/controls.md`)

## 保存データ

- `Data/CliCommands.json`: 定型コマンド
- `Data/CliSettings.json`: 次を持つ
  - 最終ディレクトリ `lastDirectory`
  - 履歴 20 件 `directoryHistory`
  - 開いているタブ `tabs` (作業ディレクトリの文字列の配列で、並び順)
  - 選んでいたタブ `selectedTab` (作業ディレクトリの文字列)
- どちらもローカル専用で、読み込みに失敗したときは上書きせず InfoBar で知らせる
- 詳細は [storage.md](storage.md)
- `Data/CliQuickMessages.json`(よく使う文)は、編集画面で書くか、手で書くファイル (上の「よく使う文」)
- `Data/CliFocusTriggers.json`(通知する文字列)は、編集画面で書くか、手で書くファイル (上の「通知する文字列」)

## よく使う文のファイル (`CliQuickMessages.json`)

- `CliSettings.json` には置かない
  - アプリが作業中に、メモリの内容で丸ごと書き戻すファイル (タブを足す・作業ディレクトリを変えるたび)なので、起動したまま手で直した文が、次の書き込みで消えるため
- `CliCommands.json` にも混ぜない
  - 定型コマンドは、既定から作って「初期化」で戻せるもの
  - よく使う文は、利用者が書くだけで、アプリが作らず戻さないもの
  - 持ち主が違うので、初期化の処理に手を入れずに済むよう、ファイルを分ける (最終形でも、手で書くファイルを、アプリが作るものと分けておく)
- 形式は `{ label?, text }` の配列にし、グループは `{ label, items }` で、同じ配列に並べる
  - 文字列だけの配列だと、長い文や複数行の文がチップの名前になって読みにくいため
  - 後から形を変えると、利用者が書いたファイルが読めなくなるので、最初からこの形にする
  - `items` を足しても、`items` の無い平らなファイルは、そのまま読める
- アプリはこのファイルに書き込む
  - 書くのは編集画面だけで、タブの操作では書かない
  - 保存すると全タブへすぐ反映する
  - 起動したまま手で直した内容は、編集画面を開く前に再起動しないと、画面の保存で上書きされる
  - 手で直すときは、アプリを閉じて直す
- 押したら入力欄に入れるだけで、送信しない (履歴の項目と同じ動き)
  - 足したい一言を書き足せ、誤送信もしない

## 送信の Enter のタイミング

- 貼り付けの 50ms 後に Enter を送る方式は採らない (CLI が Enter を本文の改行として扱い、送信されないため)
- 出力を待たず一定時間で Enter を送る方式は採らない
  - 数行以上を貼り付けると、CLI が「[Pasted text …]」にまとめることがあり、まとめの描画より先に Enter が届くと確定されないため
- 貼り付けのあとに一度出力があり、それが 200ms 途切れたら Enter を送る (最低 150ms・最長 2 秒)
  - CLI が貼り付けを受け取り終えたことを、出力の途切れで判断するほうが、固定の待ち時間より確実なため
  - 送信までに最低 150ms かかる
  - CLI の描画が長く続く状況では、最長 2 秒で打ち切って Enter を送る
- 複数行の送信だけ、アプリが合図の文字列 (`[Pasted text`)を `Submit(text, readyMarker)` で渡し、`terminal.js` は、その文字列が出力に出るまで Enter を待つ
  - 出さないと、CLI が貼り付けを取り込み終える前に Enter が届いて捨てられ、`[Pasted text #N +M lines]` のまま入力欄に残ることがある (添付つきの長い送信で起きる)
  - 合図の文字列は CLI 固有なので、アプリ側 (`CliSessionViewModel`)に置き、SDK には書かない
  - 合図は、貼り付け後の出力をつなげ、制御文字 (エスケープシーケンス)と空白を除いて探す (文字の途中に制御文字が入る・出力のかたまりの境目で分かれる場合の取りこぼしを防ぐため)
  - 合図がまだ出ていない間の上限は 1 秒 (出たあとは最長 2 秒)
  - 合図を待たずに 2 秒まで遅れる送信が多いため、この形にする
- 1 行の送信は合図を待たず、約 0.24 秒で Enter を送る
- 待ち時間 (`QUIET_MS` など)を延ばさない (延ばしても、出力が途切れた時間の長さでは、失敗と成功を分けられないため)
- Enter をもう一度送らない (許可の確認などで誤って選ぶ恐れがあるため)

## 「ターミナル」「シェル」「AI セッション」の呼び分け

- 「Terminal」が同じ CLI補助の中で 4 つの意味に使われると、JSON の `"terminal"`(定型コマンドのタブ)と `"focus": "terminal"`(ペイン)が紛らわしい
  - タブとペインで同じ語を使うと、`switchTo` と `focus` の値が読み間違いやすい
- **ターミナル**: 中央のペインと、その実体 (ConPTY・xterm.js)だけを指す
  - `MmmSdk.WinUI.Components.Terminal`・`TerminalControl`・`ITerminalSession`・`FocusTarget.Terminal`(`"focus": "terminal"`)はこの意味
- **シェル**: 定型コマンドの左のタブのうち、シェルで打つコマンド (AI エージェント起動前)
  - `CommandCategory.Shell`・`CliCommandSet.Shell`・JSON の `"shell"` と `"switchTo": "shell"`・画面の表記「シェル」
- **AI セッション**: もう一方のタブ (`CommandCategory.Session`・`"session"`)
- 定型コマンドの JSON のキーは `shell` / `session`
  - 古いキー (`terminal`)は読まない (既定から作り直せるため、互換のための読み替えは持たない)
  - 作り直すには、アプリを閉じて `Data/CliCommands.json` を削除する

## WSL でも動かす (シェル自体を WSL にする)

- WSL の中の CLI には、Windows のパス (`D:\work\a.txt`)を渡しても読めないので、作業ディレクトリの移動・添付のパスを、WSL から見たパス (`/mnt/d/work/a.txt`)にして渡す必要がある
- 今どちらの環境で動いているかを、1 か所で決めて持つ必要がある
- ターミナルのシェル自体を WSL (`wsl.exe`)にする (ユーザーの決定)
  - PowerShell のまま `wsl claude` で起動する形にはしない
  - シェルのコマンド (cd・`claude update` など)も、すべて Linux 側で動き、どちらで動いているかはシェルの種類 (`ShellKind.Wsl`)で決まって、途中で混ざらない
  - PowerShell の中で `wsl claude` を起動する形だと、起動したものが WSL かどうかを、コマンドごとに覚えておく仕組みが要る
  - 起動時の作業ディレクトリは、Windows のパスのまま渡せば wsl.exe が変換する
- 環境は、定型コマンドのファイルの `environment` に持つ (ユーザーの決定)
  - 定型コマンドは、その環境向けに書かれたものなので、まとめて持つ
  - 変えるときは、既定の内容に作り直して選び直す (ユーザーの決定)
    - 今の内容は引き継がない
    - ターミナルはいつも起動し直す
- パスの変換は、文字列だけで行い、`wslpath` は呼ばない (パスごとに WSL のプロセスを起動すると遅いため)
  - UI は Windows のパスのまま扱い、シェルへ渡すときだけ変換する
- 貼り付けた画像の一時保存先は、WSL の /tmp にする (ユーザーの決定)
  - 終了時の削除・古いものの掃除はしない (ユーザーの決定で、systemd が有効なら、WSL の起動のたびに /tmp は空になるため)
  - 送信前に × で取り除いたものは、それ以降使わないことがはっきりしているので、Windows と同じくすぐ消す
- 会話履歴の削除の補助スクリプトは、WSL 用を Python 3 で別に作る (ユーザーの依頼で、理由は [cli-history-cleanup.md](cli-history-cleanup.md))
  - Python 3 にしたのは、Ubuntu に標準で入っていて、JSON の読み込みとキー入力の処理を、追加の道具 (jq など)なしで書けるため
  - bash だけでは JSON を確実に読めない

## Claude Code と Kiro の選択 (初期設定で選ぶ)

- Kiro (`kiro-cli`)の CLI は、Windows でもそのまま動き、WSL でも動くので、環境とは別に選べる
  - Windows で動くのは CLI 2.0 から
- 使うツール (両方も可)を、環境と一緒に「初期設定」のダイアログで選び、選んだツールのフォルダだけを、定型コマンドの「シェル」「AI セッション」の両方のタブに作る
  - 片方しか使わない人は一覧が短くなり、両方使う人にも対応できる
  - 「いつも両方のフォルダを入れる」形は採らない (使わないほうが常に並ぶため)
- ツールは別に保存しない (作ったフォルダの中身そのものなので、手で直せて、別に持つと食い違うため)
  - 初期化のときは、フォルダの表示名から今のツールを読み取って選んだ状態から始める (選び直す手間を省くため)
  - 手で表示名を変えたフォルダは読み取れないので、そのときは Claude Code だけから始まる (ユーザーの決定)
- 初期化は、確認のダイアログを別に重ねず、初期設定のダイアログ 1 つに警告 (InfoBar)を付けて確認を兼ねる
  - 既定のボタンは置かない (取り消せない操作なので Enter で実行させず、キャンセルを既定にすると、キャンセルが強調色になって主な操作に見えるため、どちらも強調しない)
    - SDK の確認ダイアログも同じ
  - 初回は、選ばずには閉じられない
- Kiro のコマンドは、Claude Code と同じ働きのものを、公式ドキュメント (kiro.dev)で確かめて当てる
  - 同じ働きのコマンドは、同じ表示名・同じ順にそろえる
  - 新規チャットは `/chat new`(Kiro の `/clear` は、同じ会話のまま中身を消すだけで、Claude Code の `/clear` とは働きが違う)
  - CLAUDE.md の作成 (`/init`)にあたるコマンドは Kiro の CLI に無いので、「steering を作成」として、`.kiro/steering/` に product.md・tech.md・structure.md を作るよう頼む文を送る (ユーザーの決定)
    - Kiro の IDE の「Generate Steering Docs」と同じ 3 つのファイルで、`/init` と同じ目的を果たす
  - 会話履歴の削除は、Claude Code と同じ操作の補助スクリプト (`Remove-KiroSession`)にする (ユーザーの決定)
    - 詳細は [cli-history-cleanup.md](cli-history-cleanup.md)
    - Kiro 自身の一覧 (`--resume-picker`)は、いまのフォルダの履歴しか出ず、Ctrl+D で 1 件ずつ消すので、全フォルダの履歴をまとめて選んで消せない
    - Claude Code と同じ操作にそろえると、ツールを替えても迷わない
    - Kiro は履歴を 1 つの SQLite (`~/.kiro/`)に持つので、ファイルをごみ箱へ送る方式は使えない
    - 一覧の出力の形が変わると壊れる弱点はあるが、操作をそろえる利点のほうを取る
    - 壊れる範囲を狭めるため、ファイル (SQLite・`.history`)の中身は読まず、公式コマンド (`--list-sessions --all-cwds --format json` と `--delete-session`)だけを使う
    - 依存は `--format json` の出力の形 (作業フォルダごとの配列で、`cwd` と `sessions` を持つ)に残るので、変わったら直す
    - Kiro での削除は戻せない

## 複数のセッションをタブで持つ

- 別のフォルダなら、Claude Code・Kiro は並行で動かせる
  - MmmTool 自体は同じ EXE を 2 つ起動できないので、送信欄・定型コマンドを使いながら複数の CLI を動かすには、アプリの中で持つ必要がある
- 1 タブ = 1 セッションのタブ (Windows Terminal・VS Code と同じ形)にする
  - 名前はフォルダ名にして、同じフォルダを同時に触ると衝突することに、タブを見るだけで気づけるようにする
- 入力欄と添付はタブごとにする (ユーザーの決定で、書きかけの文を、ほかのタブを触っても失わないため)
  - 定型コマンド・送信履歴・環境は共通のまま
- 左ペインの「シェル / AI セッション」は、タブごとに内部で持ち、タブの切り替えに左ペインが追従する形にする (ユーザーの決定)
  - 「シェル / AI セッション」は、そのターミナルで今何を動かしているかを表す状態で、送信後の `switchTo` もその切り替えなので、状態をタブごとに持てば、画面に項目を足さずに済む
  - タブごとに表示や選択肢を足す案は採らない (タブの帯が窮屈になり、決めていない項目も増えるため)
  - シェルの終了でシェル側へ戻すのは、中の AI セッションが無くなるため
- タブの操作はマウスだけ・閉じるときは確認する・同じフォルダは入口で断る (ユーザーの決定)
- タブは次回の起動で戻し、ドラッグで並べ替えられるようにする
  - 戻すのは構成 (フォルダ・並び・選び)だけで、CLI の自動起動はしない (ユーザーの決定で、勝手に複数の AI が一斉に動くのを避け、続きは既存の「続きから再開」に任せる)
  - 選んでいたタブはパスで持つ (存在しないフォルダを飛ばしても、位置がずれないため)
- 今のフォルダは、アプリで選んだフォルダだけを信じる (ユーザーの決定)
  - シェル統合は採らない
    - シェル統合とは、プロンプトのたびに、シェルが今のフォルダを信号 (OSC)で知らせる方式で、Windows Terminal・VS Code と同じ
  - 同じフォルダを避けたい目的は、アプリが開く入口 (「＋」・作業ディレクトリ変更)で断ることで果たせる
  - シェル統合を入れても、直接 `cd` を止めることはできない (気づかせるだけ)
  - タブを使わずに自分で PowerShell を起動する場合も同じで、アプリの手が届かない
  - シェル統合が効くのは、手で `cd` したあとのタブ名だけ
  - その一方で、SDK のシェルの起動引数・xterm.js・WSL の bash 固定 (zsh などは使えなくなる)・cmd の対象外といった変更が要る
  - 手で `cd` したときにタブ名がずれるのは、アプリの外の操作として受け入れる
- 中身を `TabView` に入れず、自分の枠に入れる
  - `TabView` の中身の枠 (`TabContentPresenter`)は、既定で左上に寄せて、内容の大きさのまま表示するため、ターミナルの高さが 0 になり、表示もシェルの起動もされない
  - 枠の配置を広げる直し方では直らない
- タブの色は、既定の色のまま、選択中の枠線だけを濃くする (ユーザーの決定)
  - 選んでいないタブに背景を付ける・選択中を黒 (ターミナルと同じ色)や白にするなどは採らない (選択中との差が小さくなる・ライトで文字と「×」が読めなくなるなどのため)
- 添付の一時保存先 (`AttachmentStore`)もタブごとに持つ
  - 共有すると、タブ A の送信 (`CloseSession`)で、タブ B の送信前の添付が「今のセッションフォルダの外」になり、B が × で取り除くと `Remove` が例外になるため
- 影響: タブごとに WebView2 の描画プロセスが増え、重くなる
  - 選ばれていないタブは画面から外れるが、`TerminalControl` は再表示のときに作り直さない (サイドバーのページ切り替えと同じ)ので、そのまま使える
  - ページ・タブを表示したときと、ターミナルの準備ができたときのフォーカスは、ターミナルではなく入力欄に置く (`TerminalControl.AutoFocus` を false にして、`CliSessionView` が入力欄へ移す)
    - ターミナル (WebView2)にフォーカスがあると、Alt+←・Alt+→ のページ移動が効かないため
    - フォーカスの位置は覚えない。送信後にターミナルへ移す設定 (`focus: terminal`)と、ターミナルのクリックは、今までどおり
    - 例外は、選んでいない間に確認が出たタブ。選んだときにターミナルへ移す ([通知する文字列](#通知する文字列)の「移す条件」)

## 画像の添付と添付ファイルの大きさに上限を設けない (意図した仕様)

  - Base64 の文字列としてクリップボードに載るため
  - 詳細は [clipboard-transfer.md](clipboard-transfer.md)
