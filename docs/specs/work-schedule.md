# スケジュール (作業の予定と実績を日付の上で見る画面)

作業管理 ([work-items.md](work-items.md))のデータを、日付を横に並べて見る画面。作業ごとの予定の期間と、日ごとの実績を、1 行に重ねて出す。見るだけで、入力はしない。サイドバーでは、作業管理の子の項目。`src/Plugins/MmmTool.WorkItems/Schedule/`(画面に依存しない計算は `src/Plugins/MmmTool.WorkItems.Core/`)。「(仮)」は、実装者が仮に決めたもので、ユーザーが確認するまで仮。画面の文言も、すべて仮。

## 置き場所と名前
- 画面の名前は「スケジュール」(ユーザーの決定)
- 作業管理の機能 (`MmmTool.WorkItems`)の中の画面で、別のプロジェクトにしない。作業報告 ([work-report.md](work-report.md))と同じ形
  - 読み込みと、他の人の更新の取り込み (`WorkItemService`)、「表示する案件」「自分の担当だけ」の設定を、作業管理と共有するため
  - 画面は、作業管理の表とは別にする (入力する表と、日付を横に並べて見る表示は、操作も内容も違うため)
- サイドバーでは、作業管理の直後に、字下げして並べる (ユーザーの決定。子として、常に出す。開閉は持たない)。ほかの項目と同じく、アイコン (カレンダー。Segoe Fluent Icons の `E787`)を付ける。作業管理を押すと表が開き、スケジュールを押すとこの画面が開く
  - 作業管理が設定でオフの間は、スケジュールも出さない。設定ページに、スケジュールの項目は作らない (親に従う。作業管理のデータだけを見る画面のため)
  - 登録は、SDK の `AddNavigationChildPage<スケジュールのページ, 作業管理のページ>` (親は、同じ機能のページを型で指す)。入れ子の項目 (`NavigationView` の子の項目)は使わない (親を押すたびに子の開閉が切り替わり、「押すと表が開く」動きと合わないため)

## できること
- 見るだけ。棒のドラッグ・セルの入力・行の右クリックのメニューは、持たない
- 1 行の高さは固定 (36。作業管理の表と同じ)

## 画面
- 余白 24・タイトル「スケジュール」。結果・エラーは、ページ上部の InfoBar に出す
- **上のバー**: 左に、「今日」・表示の単位 (「日」「週」「月」の 3 つから 1 つを選ぶ。既定は「日」)。右に、「表示する案件」(▼付きのボタン)・「自分の担当だけ」(トグルスイッチ。範囲の広い順)
  - 範囲の移動は、横のスクロールバーで行う。前へ・次へ動かすボタンは持たない (スクロールで自由に動けるため)
  - 「今日」は、今日の列を、見える範囲の左端から 25% の位置へ動かす
  - 表示の単位は、保存しない。開くたびに「日」から始まる (ユーザーの決定。設定の項目も持たない)
- **表** (SDK の `TreeGridView`): 左の固定部分 (横にスクロールしない)に、名前 (木構造。字下げ・開閉ボタン)・担当・進捗。右が日付の横軸で、横にスクロールする。縦のスクロールは、左右で連動する
  - 日付の棒は、1 つの広い列に、行ごとに描く (`ScheduleTimelineCell`)。日ごとに列を作らない (日数ぶんの列とセルが増えるため)。広い列は、フォーカスを受けない列 (`TreeGridColumn.IsFocusable` = false)にし、見出しは、軸ごとに作った部品 (`HeaderFactory`)を出す
  - 休みの日の背景と日付の線は、位置を軸ごとに 1 回だけ数えて全セルで使い (`ScheduleAxisVisual`)、図形はセルごとに持って、軸が変わったときだけ作り直す (行を使い回すたびに、日数ぶんの図形を作り直さないため。1 つの図形を、複数のセルの図形に付けない)
  - 木の字下げ・案件とグループの見た目は、作業管理の表と同じ ([work-items.md](work-items.md)の「画面」)。案件・グループとも広げて開き、三角で閉じられる (開閉の状態は保存しない)。担当の列は、ローカルモードでは出さない
  - 進捗は、作業の進捗度 (`{数値}%`)。案件・グループは、計算値 (`WorkItemTree`)
- 完了した作業とグループも、すべて出す (ユーザーの決定。作業管理の「完了」の選択には従わず、完了したグループも畳まない。予定と実績を見比べるには、完了した作業が要るため)
- 見出しは、上が月 (`2026/10月`)、下が日付と曜日 (単位ごとの出し方は、下の「表示の単位」)。土曜は青、日曜と祝日は赤の文字にする (どちらも、日付と曜日の両方)。日の単位では、今日の列の見出しを、強調色で塗る
- 休みの日の列の背景は、土曜は薄い青、日曜と祝日は薄い赤にする (ユーザーの決定。祝日が土曜に重なるときは、赤)。月の単位は、1 日が細すぎるので、塗らない
- **今日の線**: 今日の列の中央に縦線を引く。棒と数字の下に描く (数字を隠さない)
- 表示している案件が 1 つも無いときと、案件そのものが無いときの案内は、作業管理と同じ ([work-items.md](work-items.md)の「画面」)
- 色は、名前のついた色にして、ライトとダークの両方の値を決める。テーマ標準の色で足りないものだけ、足す
  - 実績の棒の中の数字は、棒の背景に対して 4.5 倍以上のコントラストにする (白い数字を、緑の背景に重ねると、ライトで細く見えて読みにくかったため。ライトは薄い背景と濃い文字、ダークは明るい背景と暗い文字)
  - 休みの日の背景 (土曜の薄い青・日曜と祝日の薄い赤)は、半透明の色にする。不透明にしない (ユーザーの決定。行の背景や罫線が隠れて、のっぺりした帯になる)。土曜と日曜で、作りをそろえる。行の背景が白の作業の行でも、約 1.2 倍以上の差で見えるようにする。ライトは、無効に見える中立の灰色にしない (青みのある色)。ダークは別の値にする (同じ差を両方に使うと、ライトで見えないため)

## 表示の単位
1 日の幅と見出しの中身は、すべて仮。

| 単位 | 1 日の幅 | 上の見出し | 下の見出し | 実績の時間の数字 |
| --- | --- | --- | --- | --- |
| 日 | 30 | 月 | 日付と曜日 | 出す |
| 週 | 10 | 月 | 月曜の日付 | 出さない |
| 月 | 3 | 年 | 月 | 出さない |

- 単位を変えても、いま見ている範囲の中央の日付を保つ (仮。11 月を見ているときに「日」から「週」へ変えて、今日へ飛ばないため)
  - 軸の全体が一度に見えているとき (月の単位)は、今日を基準にして、今日を「今日」ボタンと同じ位置 (見える範囲の左端から 25%)に置く (全体が見えているときの「範囲の中央」は、軸の真ん中や軸の外の日付になり、基準にならないため。今日を置く位置は、場面によって変えない)
- 軸の範囲は、読んだ作業の開始日・期限日・実績の日と今日のうち、いちばん早い日の月初めから、いちばん遅い日の月末まで (ユーザーの決定。余白は足さない。今日を入れるのは、今日の線と「今日」ボタンが、範囲の外にならないため)。日付が 1 つも無いときは、今日の月の月初めから月末まで。週の単位は、これを月曜から日曜までに広げて合わせる
- 開いたときの位置・「今日」ボタンの位置は、今日を見える範囲の左端から 25% に置く (ユーザーの決定。場面によって今日の位置を変えず、統一するため)
- 日付が「ない」を表す保存先の値 (`0001-01-01`・`9999-12-31`)は、Core で null になった値を使い、軸の範囲に入れない (入れると、軸が 1 年から 9999 年まで伸びるため)

## 棒の描き方
1 行に、予定の棒 (太い背景)と、実績の棒 (細く、予定の上に重ねる)を重ねる。

| 要素 | 描き方 |
| --- | --- |
| 予定の棒 | 開始日から期限日まで (両端の日を含む)。1 色で塗る (進捗度では塗り分けない。進捗度は、左の「進捗」の列で見る) |
| 実績の棒 | 時間が 0 より大きい日だけ塗る。連続した日は 1 本につなぐ。日付の間が 1 日でも空けば切る (土日に実績が無ければ、土日で切れる)。「日」の単位では、各日の時間を数字で入れ、日の境目を細い線で区切る |
| 案件・グループの予定の棒 | 下の作業の開始日の最小から、期限日の最大まで (`WorkItemTree`の計算値)。進捗度は計算値。日付の入った作業が 1 つも無ければ、棒を出さない |
| 案件・グループの実績の棒 | 下の作業の、日ごとの時間の合計 |
| 開始日だけの作業 | 開始日の列の左端に印を出し、右へ短い点線を続ける (期限が決まっていない側へ伸ばす)。予定の棒は出さない |
| 期限だけの作業 | 期限日の列の右端に、開始日だけの作業と同じ形の印を出し、左へ短い点線を続ける (開始が決まっていない側へ伸ばす。ユーザーの決定。形を分けない)。予定の棒は出さない |
| 日付が無い作業 | 予定の棒を出さない。実績があれば、実績の棒は出す |

- 実績の数字は、小数 2 桁まで。末尾の 0 は省く (`3.5`・`10`)
- 備考だけで時間が 0 の日は、実績の棒にしない
- 実績の棒を、予定の期間にそろえて切らない (予定より長くかかった作業は、はみ出して見えることに意味があるため)
- 土日をまたいで、実績の棒をつながない (働いた日と、働いていない日が、そのまま見えるため)
- 実績の時間は、作業の日ごとの記録 (`WorkRecord`の時間)で、全員の分を合わせた値

## 祝日
- 祝日のデータは、内閣府が公開している「国民の祝日」の一覧 (CSV。1955 年から翌年まで)を、ダウンロードしたままのファイルで、アプリの `Assets\Holidays\syukujitsu.csv` に置く (ユーザーの決定)。アプリは、祝日のためにも外へ通信しない ([CLAUDE.md](../../CLAUDE.md)の「外部送信」)
  - アセンブリに組み込まない (ファイルを、最新の一覧に置き換えられるように。置き換えたら、次の起動から使う)。Shift_JIS のまま読み、UTF-8 のファイルも読める
- 祝日の判定は、特定の機能に属さない汎用の部品なので、SDK に置く (スケジュールの中に持たない)
- ファイルが無い・読めないときと、一覧にない年 (ファイルの最後の年より先)は、祝日を出さず、土曜・日曜だけを塗る
- 出典を配布物のライセンスの一覧に書く。内閣府の公共データ利用規約 (第 1.0 版)が、出典の記載を求めるため ([build-and-distribution.md](../build-and-distribution.md)の「ライセンス」)。ファイルは変換せず、そのまま置くので、加工の記載は要らない
- 毎年、新しい年の分が内閣府から出たら、ファイルを取り直して置き換え、新しいバージョンとして配る (配ったあとは、利用者が自分で最新の一覧に置き換えてもよい)

## 期限切れ
作業管理の「期限切れの表示」([work-items.md](work-items.md))と、対象と見た目を同じにする。基準の日だけ違い、入力日ではなく**今日**で判定する (この画面に入力日は無いため)。

- 対象は、未完了の作業で、期限日が今日より前のもの (`WorkSummary.OverdueDays(今日)`)
- 予定の棒に、危険の色 (`SchedulePalette.Critical`。ライトとダークで別の値)の枠を付け、進捗の右に警告のアイコンを付ける。アイコンに触れると、「3 日超過」のように過ぎた日数を出す
- 案件・グループの行には出さない (作業管理と同じ理由)

## データ
- 読むのは、作業管理が選んでいる案件 (表示しない案件を除いた案件)の、作業・グループと、**すべての日の記録**。記録は、案件の番号で絞って一括で読む (`IX_WorkRecord_ProjectId_Date`・[database.md](database.md))
  - 読む範囲を、画面の日付で絞らない (ユーザーの決定。この画面では、記録の量を理由に、読む範囲を日付で区切らない)
  - 作業・グループは、作業管理と同じ `WorkItemService` の内容を使う。全期間の記録も、画面ではなく Core の `WorkItemService` が持つ (`LoadScheduleRecordsAsync`・`ReleaseScheduleRecords`・`BuildSchedule`)。保存先の口 (`IWorkItemRepository`)に、全期間の記録を読むものと、その差分を読むものを足す
  - 記録を読むのは、スケジュールを開くたび (作業管理の表と同じく、開くたびに読み直す)。アプリの起動時と、作業管理の表を開いたときには読まない (表が、使わないデータの読み込みを負担しないため)。スケジュールから離れたら、持っている記録を捨てる
  - 「表示する案件」が変わったとき (どちらの画面で変えても)は、見える案件になった分の記録を読み、見えなくなった案件の記録を捨てる
- 開いたとき: 画面を先に切り替えて描いてから、読み込みを始める。読み込みの途中は表を作り直さず (案件・実績を読むたびに作ると、実績が空の表を挟むため)、読み終えてから 1 回だけ作る。ページの出し入れで読み込みが重なったときは、最後の読み込みが終わったときだけ作る (先に終わったほうが作ると、あとの読み込みが捨てた実績の無い表を作るため)。前に開いたときの表は、読み込みの間も出したままにする (空にしない)
- 他の人の更新は、作業管理と同じ 60 秒ごとの取り込みの中で、同じ 1 回の問い合わせと同じ基準の時刻で反映する (取り込みを、画面で別に持たない)。記録は、更新日時 (`IX_WorkRecord_ProjectId_UpdatedAt`)の差分で読み、論理削除された行も含めて、持っている内容から外す。記録を持っていない間 (スケジュールを開いていない間)は、記録の差分を読まない
- 「表示する案件」は、作業管理と共有する (保存先は同じ設定。どちらの画面で変えても、もう一方に反映する)。「自分の担当だけ」も、作業管理と同じ設定 (`WorkItems.MineOnly`)を共有する。オンのときは、自分が担当の作業の行だけを出す。**案件・グループの棒と合計は、全員の作業から計算したまま変えない**。ローカルモードでは、トグルを出さない
- 設定や保存データを、新しく持たない ([storage.md](storage.md)の表は変えない)

## 重い操作
- 開いたあとの読み込み・単位の切り替え・「自分の担当だけ」の切り替え・案件とグループの開閉の間は、マウスカーソルを砂時計にする (「表示する案件」のチェックの付け外しは、案件の行のかたまりだけを出し入れするので、砂時計にしない) (SDK の `IBusyCursor`)。重い処理は UI スレッドで動くので、先に砂時計を描かせてから処理を始める
  - カーソルは、ページではなく、サイドバーを含むウィンドウ全体 (SDK の `NavigationHost`)に当てる (サイドバーを押した直後は、マウスがページの外にあるため)。ページだけに当てない
- 「表示する案件」のチェックの付け外しは、その案件の行の塊だけを、表から抜く・差し込む。表の全体を作り直さない (案件の中身は、ほかの案件に依存しないため)。抜き差しと名前の順の位置の決め方は、作業管理の表と共有する (`ProjectBlockRows`。[work-items.md](work-items.md) の「表示する案件」)
  - 外したとき: 軸の範囲は変えない (縮めない。開き直したときに、データに合わせて縮む)。縮めると、全部の日付の棒を描き直すことになる
  - 付けたとき: 案件の名前の順 (同じなら番号の順)の位置へ差し込む。その案件の日付が、いまの軸の範囲に収まらないときだけ、全体を作り直す (軸が広がるため)
  - 塊を抜く・差し込んだあとは、表に行の一覧を付け直させる (`TreeGridView.RebindRows`)。付け直さないと、画面に出ている行の前に差し込んだとき、スクロールするまで、行が作り直されず、表が空に見える
