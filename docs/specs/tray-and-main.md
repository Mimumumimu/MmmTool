# トレイ常駐・メイン画面・多重起動

トレイに常駐する動き・メイン画面・多重起動の防止・トレイアイコンとメニューの仕様。

## 常駐の挙動

- 起動時はウィンドウを出さず、トレイアイコンだけ出す。ウィンドウはトレイアイコンの左クリックで開く。
- 起動時にメインウィンドウも出すのは、次のときだけ (ログインが済んだあと、`tray.Show()` の後)
  - 初回の起動 (保存先を選んだとき)
  - 設定の「起動時にメイン画面を開く」がオンのとき
    - この設定の既定はオフ
    - 起動引数ではなく設定ページに置くのは、普段使いの操作として、アプリの中で切り替えられるため
    - 詳細は [settings.md](settings.md)
- ウィンドウの × / Alt+F4 は、既定ではトレイへ退避する (非表示)
  - 設定の「×ボタンを押したとき」を「終了する」にすると、トレイメニューの「終了」と同じ処理で終了する ([settings.md](settings.md))
  - 保存先は、DB モードでも、この PC の設定ストアのキー `Shell.CloseButtonAction` にする。PC ごとの動きで、ユーザーごとの設定ではないため
- 最小化は通常どおりタスクバーへ (Win+D でトレイに消えるのを避けるため)
- 完全終了はトレイメニューの「終了」と、設定を「終了する」にしたときの × / Alt+F4。未保存の編集内容は、確認せずに破棄して終了する。
- 「起動時にメイン画面を開く」の保存先は、DB モードでも、この PC の設定ストア (キー `Shell.OpenMainWindowOnStartup`)
  - PC ごとの起動の動きで、ユーザーごとの設定ではないため
  - [database.md](database.md) の後回しの「ユーザーごとの設定を DB に置く」の対象にしない

## 多重起動

- 同一 EXE の多重起動を禁止する
  - EXE パスのハッシュで Mutex 名を作る (SDK の `SingleInstanceGuard`)
  - Mutex 名は `MmmTool_` + EXE パスのハッシュ
  - Debug / Release など別パスの EXE は同時に起動できる
- 2 つ目は「すでに起動しています」のメッセージを出して終了する
  - 起動済みのウィンドウは出さない (メインウィンドウは必ず開くものではないため)

## メイン画面

- 左サイドバー (`NavigationView`)+ 右コンテンツ。下部に「設定」。
  - タイトルバーの左端の、左パネルのアイコンのボタンで、文字つき (220)とアイコンだけ (標準の 48)を切り替える。その右に「戻る」「進む」を並べる。サイドバーの中には、切り替えのボタンを置かない。サイドバーの項目のアイコン (作業管理の横線のアイコンなど)と形が似て、見間違えるため。幅は `Data/AppSettings.json` の `Navigation.IsPaneOpen` に保存し、次の起動で戻す。
    - 項目の根を `NavigationViewItem` にして、項目のアイコンは、中身に描かず、その `Icon` に入れる。中身に描くと、標準の枠が「アイコンなし」の状態になり、アイコンの列を 8 に縮めて、アイコンだけの幅で中身に渡す幅が狭くなり、アイコンが半分に切れる。
    - アイコンだけのときは、文字と「別のウィンドウで開く」ボタンを隠し、項目名はツールチップで出す。知らせの丸は、アイコンの角に重ねる。ドラッグで外す操作は、そのまま使える。
    - 完全に隠す段は持たない。サイドバーが機能への唯一の入口で、隠すと、今どの機能にいるかも、ほかの機能への行き方も見えなくなるため。
    - 実装は SDK の `NavigationHost` の 1 か所で、機能側の登録 (`AddNavigationPage`)は変えない。MmmBatch・MmmToolAdmin も同じ部品を使うので、同じ切り替えが付く。
- トレイの `WndProc` で予想外の例外が出たときは、ログ・ダイアログ・終了にする (`FatalErrorHandler`)
  - 詳細は [architecture.md](../architecture.md) の「エラーの扱い」
- ウィンドウの位置と大きさは、変更から 1 秒後に保存し、次回の起動で復元する
  - 保存には SDK の `WindowBoundsKeeper.Attach` を使う
  - 保存が無い・画面外 (面積の 50% 未満しか見えない)ときは、既定の 1280×720 DIP (DPI に合わせる)で作業領域の中央に出す
  - 最小化・最大化・非表示の間は保存しない
- ページは、ページごとのスコープから DI で生成してキャッシュする (SDK の `PageProvider`)
  - サイドバーの本体は SDK の `NavigationHost`
  - オフにできる機能のページは、オフにしたときにキャッシュから外してスコープを破棄 (`IReleasablePage`)し、オンに戻したときに作り直す
  - サイドバーの項目も、`NavigationHostViewModel.Refresh` で出し入れ・並べ替えする
    - 並びは、設定の「機能」の一覧で利用者が決める ([settings.md](settings.md))
  - サイドバーで選んだ順の履歴を `NavigationHostViewModel` が持ち、タイトルバーの左の「戻る」「進む」(SDK の `NavigationHistoryButtons`)と Alt+←・Alt+→ で、たどれる
    - 対象はサイドバーのページ移動だけで、ページの中の画面遷移は含めない (履歴の持ち方が機能ごとに違うため)
    - ショートカットはボタンに持たせ、ウィンドウのどこにフォーカスがあっても効かせる。キーフックは使わない (アプリが前面のときだけ効けばよく、フックはウイルス対策ソフトに疑われやすいため)
    - 戻る途中で別のページを選んだら、先の履歴は捨てる。オフにした機能の項目は飛ばす。履歴は 100 件まで
  - サイドバーの項目は、別のウィンドウに外せる (SDK の `PageDetacher`)
    - 外せるのは、作業管理・スケジュール・ノート・メッセージ・CLI補助の 5 つだけ。ほかの項目は、外せない。設定を含む。
      - リマインダー・リンク・Backlog・クリップボード転送・ツール・設定は、外せるようにしない。ユーザーの決定で、外す必要が無いため。
      - 各機能が `AddNavigationPage` の `canDetach: true` で決める。既定は外せない。
    - 外すときは、そのウィンドウ用にページを新しく作る。ウィンドウを閉じると、外したページを破棄する。
      - CLI補助は、SDK の `IHandoverPage` を持つ引き継げるページで、ページを作ったスコープを捨てず、同じスコープから新しいページを作り、画面の内容を引き継ぐ。ウィンドウを閉じるときも、同じ形でメインのページへ引き継ぐ。詳細は [cli-assist.md](cli-assist.md) の「別のウィンドウに外す」。
      - それ以外のページは、メインに残る同じ機能のページを捨てて、作り直す。
      - WebView2 を持つページ (ノート・CLI補助)は、作られたウィンドウから別のウィンドウへ移さない。移すと、日本語入力 (IME)が効かず、英字しか入らないため。
      - 外しても戻しても、画面で選んだ状態 (見ている日付・絞り込み・開閉・選んだ行など)は、そのまま引き継ぐ。機能をオフにしてオンに戻したときも同じ。持ち方は [architecture.md](../architecture.md) の「画面で選んだ状態」。
      - 見ている日付は、選んだ日の間だけ引き継ぐ。日をまたいだら、今日から始める。
      - 閉じたあとに項目を押すと、メインの表示領域に、新しいページを作って出す。
    - 外す操作は 2 つ。項目をメインウィンドウの外へドラッグして離す。または、項目にマウスを乗せたときに右端に出るボタンを押す。
    - ドラッグで離したときは、離した位置がタイトルバーの中央に来る位置に出す。ボタンで外したときは、メインウィンドウの左上から少しずらした位置に出す。
    - 大きさは、機能ごとに覚えた大きさ。無ければ、メインの表示領域と同じ大きさ。位置は覚えない。
    - 外している間、項目の右端に印を出す。その項目を押すと、外したウィンドウを前に出し、選択は元の項目に戻る。履歴の戻る・進むは、外している項目を飛ばす。
    - 外したウィンドウを閉じると、ページはサイドバーで開ける状態に戻る。次の起動では、外した状態を戻さない。
    - 機能をオフにするために閉じるときと、アプリの終了で閉じるときは、メインのページへ引き継がない。終了では、ウィンドウを閉じた直後に DI のホストを破棄するため。
    - 機能をオフにしたときは、ページを捨てる前に、外したウィンドウも閉じる。
    - 1 つの機能のページは、同時に 1 か所にしか出さない。
    - 並べ方は、利用者が Windows のスナップなどで決める。アプリは分割表示・並びの保存を持たない。
    - 外したウィンドウから開くダイアログは、最後に操作したウィンドウの上に出る ([dialogs.md](../../external/MmmSdk/docs/dialogs.md))
  - サイドバーの項目の右端に、知らせの丸 (バッジ)を出せる。各機能が `INavigationService.SetBadge` で出し入れする。選んでいる項目と、別のウィンドウに外している項目には出さない。詳細は [architecture.md](../../external/MmmSdk/docs/architecture.md)
    - 使っているのは CLI補助だけ ([cli-assist.md](cli-assist.md))
  - トレイメニューは並び替えに連動しない
  - サイドバーの項目は、各機能が `AddNavigationPage` で登録する ([architecture.md](../architecture.md))
- 開発用の DEBUG ページは持たない。通知ダイアログやリマインダーの画面は、各機能の画面から開いて確かめる。

## トレイアイコン・トレイメニュー

- アイコンとメニューの仕組み (Win32 直接・非表示ウィンドウ・オーナードロー・ダーク/ライト対応)は SDK の `MmmSdk.WinUI.Components.Tray` にある (SDK の `docs/tray.md`)
- WinForms の `NotifyIcon` / `ContextMenuStrip` は使わず、`Shell_NotifyIcon` を直接呼ぶ (WinUI 3 のアプリに、別の UI 基盤を混ぜないため)
- 項目はオーナードローで描く (標準のメニューは文字の大きさ・色を変えられず、ダーク / ライトの切り替えと、日本語に合うフォントが要るため)
- 枠 (外周・影)は Windows が描くので、uxtheme の非公開序数でシステムのダーク設定に従わせている
  - 非公開の仕組みに頼るため、動かない環境ではライトのまま
- アプリ側の設定は `ShellServiceCollectionExtensions.AddShell` の `AddMmmSdkTray(new TrayIconOptions(...))` で渡す
  - ツールチップは `MmmTool`、ウィンドウクラス名は `MmmTool_Tray` (どちらも `Shell/AppInfo` から作る)
  - アイコンは `Assets/app.ico`。EXE・ウィンドウ・トレイで共通で、差し替えはこのファイルを置き換える。
  - 終了の文言は「終了」 (アプリが渡す)
- 左クリックでメインウィンドウを開く (`OpenRequested`)
- メニューの「終了」で完全終了する (`ExitRequested`)
- メニューの項目は、各機能が `ITrayMenuSource` を DI に登録して足す
  - 機能のトレイ用の並び順の値 `trayOrder` の順に、区切り線で分けて並ぶ
  - 上から リマインダー → リンク → 終了
  - メニューは下から開くので、使う頻度の高い順に下、カーソルに近い側から置く
- 項目の処理の失敗は、トレイの通知 (バルーン)で知らせる

## アイコン

- 青のグラデーションのタイルに、とがったアーチの小文字 m を 3 つ白で重ね、下に細い線を入れたデザイン
  - m は奥ほど透明にする
  - 小さいサイズでは溶け合って「m」1 文字に見える
- 24px 以下 (トレイ)だけ、見た目の中心合わせをしている
  - いちばん濃い m が右上にあって右上寄りに見えたため、濃さで重み付けした重心を中央に寄せ、さらに 1px 下げた
  - 32px 以上は元の配置
- 生成は Python + Pillow のスクリプトで行っている (24px 以下は線を太くした別描画)
