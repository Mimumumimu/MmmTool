# リンク

よく開くフォルダ・ファイル・URL を登録し、トレイのメニューから開く機能。編集ページとトレイのメニューからなる。`Features/Links/`（Core 側は `MmmTool.Core/Links/`）。

## データ
- `Data/Links.json`：`{ "items": [ { "kind", "name", "path", "children" } ] }`。ローカル専用・ID なしの入れ子。無ければ空で生成する
- 種類は `kind`（`"link"` / `"folder"` / `"separator"`。Core の `LinkNodeKind`）で明示する。保存するときは必ず書く。名前から決めると、「-」という名前のリンクが、編集画面を開くだけで区切り線に変わってしまうため
- `kind` が無い古い JSON は、`LinkNode.ResolveKind` が以前の決め方で読み替える（`children` があればフォルダ・名前が `-` なら区切り線・それ以外はリンク）。次に保存したときから、`kind` が書かれる
- 編集用は `LinkTreeItem`。種類は作成時に固定する（名前で決めると、入力途中の「-」で区切り線に変わってしまうため）

## サービス（`LinkMenuService`）
- 最後に読み込み・保存した構成（`Current`）と読み込みエラー（`LoadError`）を持つ
- トレイはメニューを開くたびにここから作る（保存の通知・作り直しは不要）
- 起動時（`LinkStartup`）に一度読み込む
- ページはキャッシュされるので、画面の読み込みは初回表示時だけ（`InitializeAsync`）

## 編集ページ
- レイアウト：左にツリー、右に編集欄（2:3 のカード）
- `LinkEditorViewModel` の操作
  - 追加：選択がフォルダなら子の末尾に入れて展開、それ以外は選択の直後、未選択ならルートの末尾。追加後は名前欄へフォーカス
  - 削除、保存、破棄（読み直し）
  - コレクションの変更（ドラッグ＆ドロップの並べ替えも含む）と名前・パスの編集でダーティにする。保存・破棄はダーティのときだけ押せる
  - 読み込みに失敗したら保存を止める（破棄で読み直せる）。失敗したまま保存すると、手修正の誤りなどで読めなかった元のファイルを空の構成で上書きしてしまうため
- 削除の確認は、中身のあるフォルダだけ（`IDialogService.ConfirmAsync`）。リンク・区切り線・空のフォルダは即削除する（保存前なら破棄で戻せる）
- パスは手入力が基本で、「参照」（ファイル / フォルダーのドロップダウン）は補助
- パスの種類（URL / フォルダー / 実行ファイル / ファイル / 見つからない）を、入力が止まって 300ms 後にバックグラウンドで判定して表示する（`PathTarget.Classify`。環境変数を展開する）
- 「開いて確かめる」は `IPathOpener`（シェル実行をバックグラウンドで）
- ドラッグ＆ドロップは、リンク・区切り線の上には落とせない（`TreeViewItem.AllowDrop` = フォルダのみ）
- フォルダは開いた状態が基本。読み込み時・新規作成時は開き、閉じるのはユーザーが閉じたときだけ。閉じたフォルダでも、追加・ドロップで子が入ったら開く（`LinkTreeItem` が自分の Children を監視する）
- 行をクリックすると、選択して右に編集欄を出すだけ（名前欄へフォーカスは移さない。ツリーで矢印キー・Delete を使えるように）。追加した直後だけ名前欄へフォーカスする
- ショートカット：Ctrl+S 保存 / ツリーで Delete 削除
- 右クリックは、その行を選択してからメニューを出す
- 「保存しました」は 3 秒で自動的に閉じる

## 実装上の注意
- `TreeView.SelectionChanged` の中では `sender.SelectedItem` がまだ前の選択を返すので、`args.AddedItems` を使う（コードから選択したときは `TreeViewNode` で来ることがあるので、`Content` からも取り出す）
- 行（`TreeViewItem`）の DataContext もデータとは限らないので、行から項目を引くときは `TreeView.ItemFromContainer` を使う
- 行が右クリックを処理済みにするので、XAML の `ContextRequested` 属性では届かない。`AddHandler(..., handledEventsToo: true)` で `RightTapped` と `ContextRequested` の両方を受ける
- `TreeView` の選択は object 型で `x:Bind` の双方向にできないので、コードビハインドで ViewModel と相互に合わせる

## トレイのリンクメニュー（`LinkTrayMenuSource`）
「リンク」のサブメニューとして出す。

| 項目の状態 | メニューでの扱い |
| --- | --- |
| 区切り線（`kind` が `separator`） | 区切り線 |
| 子が 1 件以上 | サブメニュー |
| パスがあるリンク | 開く（`IPathOpener`） |
| それ以外（空のフォルダを含む） | 押せない項目 |

名前の `&` はそのまま表示される（オーナードローで `DT_NOPREFIX`）。サブメニューの左右の展開方向は、Win32 が画面端で自動で切り替える。
