# MmmBatch

サーバーに置いて動かし続ける、バッチ処理用のアプリ。最初の機能は、リマインダーを時刻になったら外部 (ntfy・Discord)へ一度だけ送る「リマインダーの送信」。この文書は設計で、実装した部分から、機能の仕様 (実装メモ)へ書き直す。

## 位置づけ
- MmmTool とは別のアプリ (別の exe・別のソリューション `MmmBatch.slnx`)。リポジトリは同じ。機能 (`src/Plugins/`)・DB (`src/Data/`)・SDK (`external/MmmSdk`)を共有する
- **外部へ送る処理は、MmmBatch の側 (`MmmBatch.*` のプロジェクト)にだけ置く。MmmTool には入れない** (ユーザーの決定。MmmTool の発行物に、送る処理のコードが入らないようにする)
  - MmmTool に入るのは、送信先の登録と、リマインダーごとの送信先の選択 (保存と画面)だけ。送る処理はもちろん、ntfy・Discord へ接続するコードは入れない
  - MmmTool のソリューション (`MmmTool.slnx`)に、`MmmBatch.*` のプロジェクトを入れない。MmmTool のプロジェクトから `MmmBatch.*` を参照しない (参照は MmmBatch から MmmTool の側への一方向)
  - SDK に送る処理を足さない (SDK は MmmTool も参照するため)
- 画面は WinUI の exe 1 つ。サービスにしない (exe を起動している間だけ動く)。画面は、送信の状況を見る 1 枚のウィンドウ。枠 (ウィンドウ・DI の組み立て)は、MmmTool の `Shell/` とは別に、MmmBatch が持つ

## 全体の形
| 場所 | 中身 |
| --- | --- |
| `src/App/MmmBatch` | ホスト。Host の構築・起動と終了の順序・メインウィンドウ・DB の接続の設定画面 |
| `src/Plugins/MmmBatch.Sending.Core` | 送信の処理 (UI に依存しない)。送る口 `INotifier`・ntfy と Discord の実装・送信の流れ・毎分の監視・`IReminderSendStatusRepository` などのインターフェース |
| `src/Plugins/MmmBatch.Sending` | 送信の状況の画面 (`SendMainControl` = 今日の送信予定 `SendPlanControl` と履歴 `SendHistoryControl`)・DI 登録の入口 (`AddSending()`) |
| `src/Data/MmmBatch.Data.SqlServer` | `ReminderSendStatus` の行・Repository の実装と作成の SQL、送る対象を読む問い合わせ。`MmmTool.Data`(リマインダー・チャンネルの行)と `MmmSdk.Db.SqlServer` を参照する |
| `src/Data/MmmTool.Data.SqlServer.WinUI` | DB の接続の入力欄 (`DatabaseConnectionForm` と ViewModel)。MmmTool と MmmBatch で共有する WinUI のライブラリ (元は MmmTool の exe の中にあった) |

- 参照の向き: `MmmBatch → MmmBatch.Sending → MmmBatch.Sending.Core → MmmTool.Reminders.Core`(発動の判定 `ReminderDates.OccursOn` を使う)。`MmmBatch.Data.SqlServer → MmmTool.Data → MmmTool.Reminders.Core`
- 機能のプラグインどうしは参照しない決まりがあるが、`MmmBatch.Sending` は MmmBatch の機能で、MmmTool の機能 (`MmmTool.Reminders`)の画面は参照しない。Core (`MmmTool.Reminders.Core`)の型だけを使う

## 送信の流れ
1. 起動時の準備で DB の接続を作る。設定が無い・つながらないときは、起動を止めず、画面の InfoBar で知らせ、接続の設定を開ける
2. 毎分 00 秒に (SDK の `MinuteScheduler`)、次を行う。起動の直後にも 1 回行う (止まっていた間の分を、起動後に送るため)
   1. 今日の日付で、送る対象を読む。対象は「今日発動する (`ReminderDates.OccursOn`)、削除されていないリマインダー」のうち、時刻が過ぎていて、削除されていない送信先の設定 (`ReminderSendSetting`)を持つもの。宛先 (`TargetUserId`)・対応状態 (完了・スヌーズ)は見ない (送信は、リマインダーを登録した人が選んだ送信先に、時刻に一度だけ送るもので、人ごとの対応状態とは別)
   2. 対象 1 件ごとに、先に `ReminderSendStatus` の行を `Pending` で作る。`(ReminderId, ChannelId, Date)` の一意制約で、作れなければ (すでに行がある)最初の送信はしない。作れたものだけを送る
   3. `INotifier` で送り、結果で行を更新する (成功は `Sent`・`SentAt`、失敗は `Failed`・`Attempts` を 1 増やす・`LastError`)
3. 失敗 (`Failed`)は、次の分から、試行が 5 回になるまで、送り直す (待つ時間は、回数 × 1 分)。日付をまたいでも、昨日の分の失敗・送信中のまま止まったものを、同じ上限まで送り直す (新しく送り始めるのは、今日の分だけ)。送り先がスマホの通知・Discord なので、0 時をまたいで届いても、数分の遅れで済むため (ユーザーの決定)。5 回で失敗したら、そのままにする (画面に出る)
4. 送信中 (`Pending`)のまま 10 分以上たった行 (送っている途中で落ちた)は、失敗と同じ扱いで送り直す。送り直しの前に送信が済んでいたときは、二重に送られうる (取りこぼすより、重複を許す側に倒す。「一度だけ」は、落ちなければ守られる。ユーザーに伝える)
5. 送り直しの権利も、行の更新で取る: `UPDATE ... SET Status = Pending, UpdatedAt = 現在 WHERE Id = @Id AND Status = @読んだ状態 AND UpdatedAt = @読んだ更新日時` で、更新できた (1 行)ときだけ送る。0 行なら、別の MmmBatch が先に取ったので、送らない。MmmBatch を、別のフォルダのコピーで 2 つ動かしても (多重起動の防止は、exe のパスごと)、二重に送らない
6. 送信設定の更新日時 (`ReminderSendSetting.UpdatedAt`)が、今日の発動時刻より後なら、今日の分は送らない。MmmTool は、送信先を選んだリマインダーを保存するたびに、送信設定を書き直して、更新日時を保存した時刻にする。つまり、保存した時点で、送る時刻がもう過去なら今日は送らず、まだ先なら、その時刻に送る (件名の直しなど、時刻を変えない保存でも同じ。送った後の保存は、送信の状況が「送信済み」なので、影響しない)。明日からは送る。起動直後の取りこぼしの救済 (止まっていた間の分を、起動後に送る)は、設定が発動時刻より前からあるものだけが対象 (ユーザーの決定)
7. 気づいてほしい失敗は、トレイの通知で知らせる (`ReminderSendService.AlertRaised`)。送信の失敗は、最初の失敗と、回数の上限での最後の失敗の 2 回だけ。DB の読み書きの失敗は、内容が変わったときだけ。ウィンドウを開かなくても気づけるようにするため (ユーザーの決定)

## 送る内容
- 件名・備考・リンクから作る。ntfy は、タイトルを「リマインダー」、本文を「件名」(備考があれば「件名 (備考)」)にし、リンクがあれば、通知をタップしたときに開くリンク (`click`)にする。Discord は、本文に「件名 (備考)」と、リンクがあればリンクを入れる
- 文言の細かい形は、画面の文言と同じ扱いで、実装の前にユーザーと決める
- ntfy は、JSON の発行 (サーバーの URL に JSON を POST。タイトルに日本語を使うため。ヘッダーに日本語を入れない)で送る。サーバーは `https://ntfy.sh` の 1 か所の定数
- Discord は、Webhook の URL へ JSON を POST する。`429`(送りすぎ)は失敗として扱い、次の分に送り直す
- 通信は `HttpClient` を 1 つだけ持つ (`SocketsHttpHandler.PooledConnectionLifetime` を設定。NuGet は足さない)。タイムアウトは 10 秒

## 送信先 (チャンネル)
- 区分は ntfy と Discord。値は、ntfy ならトピック名、Discord なら Webhook の URL
- ntfy のトピック名は、MmmTool の登録画面で、ユーザーが ntfy を選んだときに、`mmmtool-` + UUID (ハイフンなしの 32 文字)を、初期値として自動で作る (推測できない長さ)。自分で決めてもよい (ユーザーの決定)。使える文字は、半角の英字・数字・ハイフン・アンダースコアで、64 文字まで (ntfy の決まり。登録のときと、送る直前に確かめる)。短い名前・覚えやすい名前は、推測されやすく、知っている人なら誰でも読める・送れる点に注意登録名の初期値は「リマインダー」(ユーザーの決定。直せる。Discord に切り替えたときは、初期値のままなら空に戻す)。ユーザーは、スマホの ntfy のアプリに、このトピック名を入れる。再発行もできる (古いものは使えなくなる)
- Discord の Webhook の URL は、ユーザーが自分で貼る。サーバー側がボットの権限 (トークン)を預かる形にはしない (預かるものを、権限の小さい Webhook の URL に限るため)
- Webhook の URL は秘密として扱う: 一覧に出さない・編集の画面でも伏せる・ログに書かない。DB には平文で持つ
- リマインダー 1 件に、送信先を複数選べる (ユーザーの決定。ntfy と Discord など、複数へ同時に送れる)。何も選ばなければ、送らない。送る対象は、リマインダー × 送信先ごとに 1 行で、送信の状況も、その単位 (同じリマインダーでも、送信先ごとに、送信済み・失敗が別になる)
- 入力画面の選択肢は、自分が登録したもの (`CreatedByUserId` が自分)。入力画面は、種類と登録名 (例: ntfy「リマインダー」)を、チェックのリストで出す。**編集のときは、保存されている送信先が自分のものでなくても、選択肢に足す** (宛先の欄と同じ。ほかの人が登録した送信先を、見えるリマインダーの編集で、黙って外さないため)。選び直さなければ、送信設定は変えない
- 表が無いとき (`002_CreateSendTables.sql` などを流していない)は、読んだときの SQL のエラー (208)を、流す手順を伝えるメッセージの失敗にする。MmmTool は、入力画面で、送信先の欄を出さずに InfoBar で知らせ、送信先の一覧でも InfoBar で知らせる。MmmBatch も、送信の状況の画面の InfoBar で知らせて、送信しない

## DB 専用
- 送信先の登録・入力画面の送信先の欄・送信先の保存は、DB モードのときだけ出す・使う。ローカルモードでは出さず、`Reminders.json` に送信の項目は書かない (`Reminder` の型も変えない。設定は別の表・別の Repository に持つ)
- 機能のオン・オフの仕組み (DB のフラグ)は作らない (ユーザーの決定。「DB に接続しているときだけ出す」で足りる。オフにしたい要望が出たら、そのとき設計する)

## MmmBatch の画面
- 1 枚のウィンドウ (サイドバー無し)。上の「今日」「履歴」(`SelectorBar`)で切り替える。最初は「今日」
  - **今日 (今日の送信予定)**: 今日送るものを、時刻順に並べる。列は、時刻・件名・ユーザー (送信先を登録した人の表示名)・送信先 (種類と登録名。例: ntfy「自分のスマホ」。送る先の値は出さない)・状態 (未送信・送信中・送信済み・失敗 (理由))。今日の分でないもの・削除したもの・送信先なしは出さない。保存した時点で、送る時刻が過ぎていて、今日は送らないものは、状態を「対象外 (過去)」にして出す (なぜ送られないか、見えるように。右クリックの「今すぐ送る」で、送ることもできる)
  - 行を右クリックして、「再送」(まだ送ろうとしていないものは「今すぐ送る」)を選ぶと、状態や時刻にかかわらず、今すぐ 1 回送る。送信済みのものを再送すると、もう一度通知が届く (確認は出さない)。回数の上限に達した失敗も送れる (回数は数え続ける)。毎分の実行が動いている最中は、その終わりを待ってから送る。別の MmmBatch が先に同じものを送り始めていたときは、何もしない
  - **履歴**: 新しい順に、最大 100 件 (昨日以前の失敗も見られる)。列は、時刻 (最後に更新した日時)・件名・ユーザー・送信先・結果
- 一覧は、送信の状況が変わったときに更新する。「今日」は、毎分の実行のあとにも更新する (リマインダー・送信設定の編集を、すぐ反映するため)。読み込みや接続の失敗は、一覧の上の InfoBar で知らせる
- トレイに常駐する (SDK の `TrayIcon`。メニューは「終了」だけで、クリックでウィンドウを開く。MmmTool と同じ形)。× ボタン・Alt+F4 では終了せず、ウィンドウを隠すだけで、送信は動き続ける (ユーザーの決定)。基本は非表示で起動し、送信の状況を読めなかったとき (接続の設定が無い・つながらない)だけ、気づけるよう、ウィンドウを出す
- DB の接続の設定画面は、InfoBar の「接続の設定」ボタンから開く。入力欄 (`DatabaseConnectionForm`)と、保存・キャンセルを付けたウィンドウ (`ConnectionSettingsWindow` と ViewModel)は、共有のライブラリ (`MmmTool.Data.SqlServer.WinUI`)にあり、MmmBatch は開くだけ (`Shell/Settings/ConnectionSettingsDialogService`)。「接続を確認」できるまで保存できない作りは、MmmTool の保存先の画面と同じ。保存したら、覚えている接続を捨てて (`SqlServerDatabase.ResetConnection`)、再起動せずに新しい設定を使う
- 文言は、実装の前に、ユーザーと決める

## 決定の理由

### MmmBatch を、MmmTool とは別の exe にする
MmmTool に外部へ送る処理を入れない、という要件のため。送る処理を、MmmTool が参照しないプロジェクトにだけ置けば、MmmTool の発行物に DLL もコードも入らない。リポジトリを分けないのは、リマインダーの型・DB・SDK を共有し、ブランチと知識を 1 か所に置くため。ソリューションを分けるのは、MmmTool 側のソリューションに、送る処理のプロジェクトを並べないため。

### 管理ツールを、バッチと同じ exe に載せない
バッチは、無人で動き続け、必要最小限の権限だけを持たせたい。管理の操作 (パスワードの初期化など)は、人が必要なときだけ開く。権限が強い機能を、起動しっぱなしの exe に載せない。管理ツールは、最初の機能が決まってから別のアプリ (`MmmAdmin`)として作る。

### 画面なしの exe にしない
画面を持たない .NET の exe は、20〜40 MB 前後の見込みで (実測はしていない)、MmmTool の約 75 MB からの差は、約 3 分の 1。exe を 2 つに分ける手間 (設定ファイル経由の連携)に見合わない。ジョブの処理は UI に依存しない `.Core` に置くので、必要になったら、画面なしの exe に切り出せる。

### 枠 (`Shell/`)を SDK へ移さない
枠は、アプリごとに違ってよい (MmmBatch は、サイドバー無しの 1 枚のウィンドウ)。共通化の形は、2 つの実例 (MmmTool・MmmBatch)を並べてから決めるほうが、公開済みの SDK の API を一度で決められる。共通部分が見えたら、別の作業として SDK へ抽出する。

### 送信の記録を、別の表 (`ReminderSendStatus`)にする
- `ReminderState` にフラグを足さない。状態は、操作した人ごと・日ごとの行で、操作されなければ行を持たない。送信は、誰も操作していなくても付ける必要があり、全員宛てのリマインダーでは、どの人の行に付けるかが決まらない。書き手も違い (ユーザーと MmmBatch)、同時編集の上書きを検出しない仕様では、完了の操作と送信済みの印が衝突しうる
- `Reminder` に送信先の列を足さない。`Reminder` の型・DB の表・ローカルの JSON を、送信のために変えない
- 送信の記録は、ログではなく状態。「見て、送っていなければ送る」判断に使う。先に行を作り、一意制約で、先に作れた 1 つだけが送る (二重送信の防止)

### 名前
- `NotificationChannel`: 通知が届く先の登録を表す標準的な言葉。「もの」を表す名前
- `ReminderSendSetting`・`ReminderSendStatus`: 「送る」動きに関わる表なので `Send`。`Delivery`(配信)は、届いたことまで含む言葉で、MmmBatch に分かるのは、送信を依頼して、相手が受け付けたところまでのため、使わない
- 画面では「送信先」と呼ぶ

### 外部へ送る処理を SDK に置かない
SDK は MmmTool も参照し、公開もされている。送る処理を SDK に置くと、MmmTool の DLL に入る。
