# MmmBatch

サーバーに置いて動かし続ける、バッチ処理用のアプリの仕様。

## 機能

- 「リマインダーの送信」: リマインダーを時刻になったら外部 (ntfy・Discord)へ一度だけ送る
- 「メッセージの送信」: MmmTool で依頼されたメッセージを送る ([messages.md](messages.md))

## 位置づけ

- MmmTool とは別のアプリで、別の exe・別のソリューション `MmmBatch.slnx` にする
  - リポジトリは同じ。機能 (`src/Plugins/`)・DB (`src/Data/`)・SDK (`external/MmmSdk`)を共有する。
  - 別の exe・別のソリューションにするのは、MmmTool に外部へ送る処理を入れない要件のため
    - 送る処理を、MmmTool が参照しないプロジェクトにだけ置けば、発行物に DLL もコードも入らない
  - リポジトリを分けないのは、リマインダーの型・DB・SDK を共有し、ブランチと知識を 1 か所に置くため
  - ソリューションを分けるのは、MmmTool 側のソリューションに、送る処理のプロジェクトを並べないため
- **外部へ送る処理は、MmmBatch の側 (`MmmBatch.*` のプロジェクト)にだけ置く**
  - **MmmTool には入れない**
  - ユーザーの決定で、MmmTool の発行物に、送る処理のコードが入らないようにするため
  - MmmTool のソリューション (`MmmTool.slnx`)に、`MmmBatch.*` のプロジェクトを入れない
  - MmmTool のプロジェクトから `MmmBatch.*` を参照しない (参照は MmmBatch から MmmTool の側への一方向)
  - SDK に送る処理を足さない (SDK は MmmTool も参照するため)
- 画面は WinUI の exe 1 つ
  - サービスにしない (exe を起動している間だけ動く)
  - 画面は、左にサイドバー、右に機能ごとのページを出す 1 枚のウィンドウ (MmmTool と同じ作り)
  - ウィンドウの枠 (タイトルバー・トレイへの退避・DI の組み立て)は、MmmTool の `Shell/` とは別に、MmmBatch が持つ
  - サイドバーの本体 (`NavigationView` と、ページを作って保つ部品)は、SDK の `MmmSdk.WinUI.Components.Pages` に置き、MmmTool と MmmBatch の両方が使う (同じ部品を、2 つのアプリに写さないため)
    - バッチ処理が増えたとき、機能のプラグインを足すだけで、サイドバーに項目が増え、ホストは変わらない
  - MmmBatch の機能は、MmmTool と同じく、機能のオン・オフの管理 (`FeatureService`)へ「常にオン」の機能として登録する (オン・オフの画面は持たない)
  - 1 枚の一覧に、機能の違うもの (リマインダーとメッセージ)を混ぜない。機能ごとにページを分ける。
    - 混ぜると、列・状態・再送の意味が機能ごとに違って、機能が増えるたびに、一覧と、それを作るホストが崩れるため
  - 画面なしの exe にしない
    - 画面を持たない .NET の exe は、20〜40 MB 前後の見込みで、MmmTool の約 75 MB からの差は約 3 分の 1
    - exe を 2 つに分ける手間 (設定ファイル経由の連携)に見合わない
    - ジョブの処理は UI に依存しない `.Core` に置くので、必要になったら、画面なしの exe に切り出せる
- 管理の操作 (パスワードの初期化など)は、バッチと同じ exe に載せない
  - バッチは無人で動き続け、必要最小限の権限だけを持たせたいため
  - 権限が強い機能を、起動しっぱなしの exe に載せない
  - 管理ツールは、最初の機能が決まってから別のアプリ (`MmmAdmin`)として作る

## 全体の形

| 場所 | 中身 |
| --- | --- |
| `src/App/MmmBatch` | ホスト。Host の構築・起動と終了の順序・メインウィンドウ (サイドバーを載せる)・DB の接続の設定画面を持つ。個々の機能の名前を持たない (機能のプラグインを `AddFeaturePlugin` で 1 行ずつ登録するだけ) |
| `src/Plugins/MmmBatch.Sending.Core` | 機能に共通の処理 (UI に依存しない)を持つ: 送る口 `INotifier`・ntfy と Discord の実装・送信のログ (`ISendLog`)・仕事を動かす監視 `BatchMonitor`・仕事の口 `IBatchJob`・通知の窓口 `BatchAlertService`・送り直しの決まり `SendRetryPolicy` (回数の上限と待ち時間を持ち、機能どうしで参照し合わずに、同じ決まりを使うため) |
| `src/Plugins/MmmBatch.Sending` | 機能ごとの状態の文字列と一覧の列は、各機能の画面に置く。機能に共通の画面の部品 (読み込みの失敗の InfoBar `SendErrorBar`・接続の設定を開く操作を持つ ViewModel の基底 `SendViewModelBase`・履歴の ViewModel の基底 `SendHistoryViewModel`・画面に出す共通の文字列 `SendDisplay`) |
| `src/Plugins/MmmBatch.ReminderSending.Core` / `src/Plugins/MmmBatch.ReminderSending` | プラグインは `ReminderSendingPlugin`。リマインダーの送信 (仕事 (毎分)・送る対象・`ReminderSendStatus` の保存先のインターフェース)と、そのページ (「今日」「履歴」) |
| `src/Plugins/MmmBatch.MessageSending.Core` / `src/Plugins/MmmBatch.MessageSending` | プラグインは `MessageSendingPlugin`。メッセージの送信 (仕事 (5 秒おき)・`IMessageSendStore`)と、そのページ (「最近の依頼」「履歴」) |
| `src/Data/MmmBatch.Data.SqlServer` | `MmmTool.Data`(リマインダー・チャンネル・メッセージの送信依頼の行)と `MmmSdk.Db.SqlServer` を参照する。MmmBatch の DB のコードをすべて集める (`ReminderSendStatus` の行・Repository の実装と作成の SQL・送る対象を読む問い合わせ・メッセージの送信依頼の読み出しと状態の更新) |
| `src/Data/MmmTool.Data.SqlServer.WinUI` | MmmTool と MmmBatch で共有する WinUI のライブラリ。DB の接続の入力欄 (`DatabaseConnectionForm` と ViewModel) |

- 参照の向きは `MmmBatch → 各機能 (ReminderSending・MessageSending) → MmmBatch.Sending (共通の画面) → MmmBatch.Sending.Core (共通の処理)`
  - `MmmBatch.ReminderSending.Core` は `MmmTool.Reminders.Core`(発動の判定 `ReminderDates.OccursOn` を使う)と `MmmTool.NotificationChannels.Core`(送信先の型)を参照する
  - `MmmBatch.MessageSending.Core` は `MmmTool.Messages.Core`(送信依頼の型)と `MmmTool.NotificationChannels.Core` を参照する
  - `MmmBatch.Data.SqlServer → MmmTool.Data → MmmTool.Reminders.Core`
- 機能のプラグイン (ReminderSending・MessageSending)どうしは参照しない。共通の部分は `MmmBatch.Sending(.Core)` に置く。MmmTool の機能の画面 (`MmmTool.Reminders` など)は参照しない。Core の型だけを使う。
- 仕事 (`IBatchJob`)は、次を持つ
  - 名前
  - 動かす間隔 (`Interval`): リマインダーは毎分、メッセージは 5 秒。0 時からの区切りに合わせて動く。
  - `RunAsync(今の日時)`
  - 最後の失敗 (`LastError`): DB の読み書きの失敗
  - 結果が変わったときの通知 (`Changed`)
  - 実行が終わったときの通知 (`Ran`): 間隔の長い仕事の一覧が読み直すために使う
- 各機能が `AddBatchJob<T>()` で登録し、`BatchMonitor` が、登録された順に 1 つずつ動かす
- 1 つの仕事の DB の失敗は、ほかの仕事を止めない (仕事が自分で受け止めて `LastError` に残す)
- 画面の「再送」は、`BatchMonitor.RunExclusiveAsync` の 1 つのゲートを通る (仕事の実行と同時に送らない)
  - `BatchMonitor` は、機能ごとの再送の口を持たない
- 古い日の送信のログのファイルの整理 (`old` フォルダーへ移す)は、機能に共通なので、`BatchMonitor` が実行の最初に、日付が変わったときに行う (特定の機能の仕事に持たせると、その機能を外したときに整理が止まるため)
- 通知の窓口 (`BatchAlertService`): 各機能の仕事が、気づいてほしい失敗を報告し、ホストが、トレイの通知にする。ホストは、機能ごとの通知の購読を持たない。
- 送り直しの決まり (`SendRetryPolicy`)は、次の 3 つ
  - 1 つを送ろうとする回数の上限 (5 回)
  - 送信中のまま止まったとみなす時間 (10 分)
  - 失敗してから送り直すまでの待ち時間 (回数 × 1 分)
- 送り直しの決まりは、リマインダーとメッセージで同じものを使い、機能どうしが参照し合わないよう、共通の Core に置く

## 送信の流れ

1. 起動時の準備で DB の接続を作る。設定が無い・つながらないときは、起動を止めず、画面の InfoBar で知らせ、接続の設定を開ける。
2. `BatchMonitor` が、1 秒ごとに時計を確かめ、間隔が来た仕事 (`IBatchJob`)を 1 つずつ動かす
   - リマインダーの仕事は毎分 00 秒
   - 起動の直後にも、すべての仕事を 1 回行う (止まっていた間の分を、起動後に送るため)
   - リマインダーの仕事は、次を行う
     1. 今日の日付で、送る対象を読む
        - 対象は「今日発動する、削除されていないリマインダー」のうち、時刻が過ぎていて、削除されていない送信先の設定 (`ReminderSendSetting`)を持つもの
        - 発動の判定は `ReminderDates.OccursOn`
        - 宛先 (`TargetUserId`)・対応状態 (完了・スヌーズ)は見ない (送信は、リマインダーを登録した人が選んだ送信先に、時刻に一度だけ送るもので、人ごとの対応状態とは別)
     2. 対象 1 件ごとに、先に `ReminderSendStatus` の行を `Pending` で作る
        - `(ReminderId, ChannelId, Date)` の一意制約で、すでに行があって作れなければ、最初の送信はしない
        - 作れたものだけを送る
     3. `INotifier` で送り、結果で行を更新する
        - 成功は `Sent`・`SentAt`、失敗は `Failed`・`Attempts` を 1 増やす
        - 失敗の理由は、DB には書かず、下の「送信のログ」に残す
3. 失敗 (`Failed`)は、次の分から、試行が 5 回になるまで、送り直す (待つ時間は、回数 × 1 分)
   - 日付をまたいでも、昨日の分の失敗・送信中のまま止まったものを、同じ上限まで送り直す (新しく送り始めるのは、今日の分だけ)
   - 送り先がスマホの通知・Discord なので、0 時をまたいで届いても、数分の遅れで済むため (ユーザーの決定)
   - 5 回で失敗したら、そのままにする (画面に出る)
4. 送信中 (`Pending`)のまま 10 分以上たった行 (送っている途中で落ちた)は、失敗と同じ扱いで送り直す
   - 送り直しの前に送信が済んでいたときは、二重に送られうる
   - 取りこぼすより、重複を許す側に倒す
   - 「一度だけ」は、落ちなければ守られる。ユーザーに伝える。
5. 送り直しの権利も、行の更新で取る: `UPDATE ... SET Status = Pending, UpdatedAt = 現在 WHERE Id = @Id AND Status = @読んだ状態 AND UpdatedAt = @読んだ更新日時` で、更新できた (1 行)ときだけ送る
   - 0 行なら、別の MmmBatch が先に取ったので、送らない
   - MmmBatch を、別のフォルダのコピーで 2 つ動かしても、二重に送らない (多重起動の防止は、exe のパスごとのため)
6. 送信設定の更新日時 (`ReminderSendSetting.UpdatedAt`)が、今日の発動時刻より後なら、今日の分は送らない
   - MmmTool は、送信先を選んだリマインダーを保存するたびに、送信設定を書き直して、更新日時を保存した時刻にする
   - つまり、保存した時点で、送る時刻がもう過去なら今日は送らず、まだ先なら、その時刻に送る
     - 件名の直しなど、時刻を変えない保存でも同じ
     - 送った後の保存は、送信の状況が「送信済み」なので、影響しない
   - 明日からは送る
   - 起動直後の取りこぼしの救済 (止まっていた間の分を、起動後に送る)は、設定が発動時刻より前からあるものだけが対象 (ユーザーの決定)
7. 気づいてほしい失敗は、トレイの通知で知らせる (仕事が `BatchAlertService` に報告する)
   - 送信の失敗は、最初の失敗と、回数の上限での最後の失敗の 2 回だけ
   - DB の読み書きの失敗は、内容が変わったときだけ
   - ウィンドウを開かなくても気づけるようにするため (ユーザーの決定)

## 送る内容

- 件名・備考・リンクから作る
  - ntfy: タイトルを「リマインダー」、本文を「件名」(備考があれば「件名 (備考)」)にし、リンクがあれば、通知をタップしたときに開くリンク (`click`)にする
  - Discord: 本文に「件名 (備考)」と、リンクがあればリンクを入れる
- ntfy は、JSON の発行 (サーバーの URL に JSON を POST)で送る
  - タイトルに日本語を使うため、ヘッダーに日本語を入れない
  - サーバーは `https://ntfy.sh` の 1 か所の定数
- Discord は、Webhook の URL へ JSON を POST する。`429`(送りすぎ)は失敗として扱い、次の分に送り直す。
- 通信は `HttpClient` を 1 つだけ持つ
  - `SocketsHttpHandler.PooledConnectionLifetime` を設定する
  - NuGet は足さない
  - タイムアウトは 10 秒

## メッセージの送信

- MmmTool の画面が書いた送信の依頼 (`MessageSendRequest`)を読んで送る ([database.md](database.md))
- 画面の仕様は [messages.md](messages.md)
- 5 秒おきの仕事として行う (`MessageSendingPlugin` が登録する)
  - 日付は見ない (リマインダーのように「今日の分」は無い)
  - 依頼から送るまで、最大で約 5 秒かかる
  - メッセージは、依頼したらすぐ届くのが自然なため、リマインダー (分の単位)と間隔を分けた
  - 毎回読むのは、状態の索引で絞った送信待ち・失敗の行だけ
- 送る対象は、次の 3 つ
  - 状態が送信待ちの行
  - 失敗で試した回数が上限 (5 回)に達していない行 (待つ時間は、回数 × 1 分)
  - 送信中のまま 10 分以上たった行
- 送り直しの考え方は、リマインダーと同じ (「送信の流れ」の 3 と 4)
- 行を取る条件は、リマインダーと同じ: `UPDATE ... SET Status = Pending, UpdatedAt = 現在 WHERE Id = @Id AND Status = @読んだ状態 AND UpdatedAt = @読んだ更新日時` で、更新できた (1 行)ときだけ送る。MmmBatch を 2 つ動かしても、二重に送らない。
- 送信先の値 (トピック名・Webhook の URL)は、送る直前に `NotificationChannel` から読む。依頼の行には無い。送信先が削除されているときは、送れないので失敗にする。
- 内容は、次のとおり
  - ntfy: タイトルがあれば `title` に入れ、本文を `message` にする
    - タイトルが無ければ `title` は付けない
  - Discord: 本文を送り、タイトルがあれば太字の 1 行目にする
  - リンクは付けない
  - 送り方 (JSON の発行・`429` の扱い・タイムアウト)は「送る内容」と同じ
- 結果は、成功なら `Sent`・`SentAt`、失敗なら `Failed`・`Attempts` を 1 増やす。失敗の理由は DB に書かず、「送信のログ」に残す。
- 気づいてほしい失敗は、リマインダーと同じく、最初の失敗と回数の上限での最後の失敗の 2 回だけ、トレイの通知で知らせる
- 画面は、「メッセージの送信」のページ (下の「MmmBatch の画面」)に出す
  - リマインダーの画面とは混ぜない
- 失敗した依頼は、MmmTool の画面には戻らない
  - 送信済み・失敗を MmmTool の画面に出さない (結果は MmmBatch の画面とログで見る)

## 送信先 (チャンネル)

- 区分は ntfy と Discord。値は、ntfy ならトピック名、Discord なら Webhook の URL。
- 名前の付け方
  - `NotificationChannel` は、通知が届く先の登録を表す標準的な言葉
  - `ReminderSendSetting`・`ReminderSendStatus` は、「送る」動きに関わる表なので `Send`
  - `Delivery` (配信)は使わない (届いたことまで含む言葉で、MmmBatch に分かるのは、送信を依頼して、相手が受け付けたところまでのため)
  - 画面では「送信先」と呼ぶ
- ntfy のトピック名は、MmmTool の登録画面で、ユーザーが ntfy を選んだときに、`mmmtool-` + UUID (ハイフンなしの 32 文字)を、初期値として自動で作る (推測できない長さ)
  - 自分で決めてもよい (ユーザーの決定)
  - 使える文字は、半角の英字・数字・ハイフン・アンダースコアで、64 文字まで (ntfy の決まり)
    - 登録のときと、送る直前に確かめる
  - 短い名前・覚えやすい名前は、推測されやすく、知っている人なら誰でも読める・送れる点に注意する
  - 登録名は、新規のとき空にして、入力欄に「例: リマインダー」を薄く出す (ユーザーの決定)
    - 初期値を入れると、そのまま保存して同じ登録名が並び、宛先で見分けがつかなくなるため
  - ユーザーは、スマホの ntfy のアプリに、このトピック名を入れる
  - 再発行もできる (古いものは使えなくなる)
- Discord の Webhook の URL は、ユーザーが自分で貼る
  - サーバー側がボットの権限 (トークン)を預かる形にはしない (預かるものを、権限の小さい Webhook の URL に限るため)
- Webhook の URL は秘密として扱う: 一覧に出さない・編集の画面でも伏せる・ログに書かない。DB には平文で持つ。
- リマインダー 1 件に、送信先を複数選べる (ユーザーの決定)
  - ntfy と Discord など、複数へ同時に送れる
  - 何も選ばなければ、送らない
  - 送る対象は、リマインダー × 送信先ごとに 1 行で、送信の状況も、その単位
    - 同じリマインダーでも、送信先ごとに、送信済み・失敗が別になる
- 入力画面の選択肢は、自分が使用者のもの (`NotificationChannel.UserId` が自分)
  - 入力画面は、登録名と種類 (例: リマインダー (ntfy))を、チェックのリストで出す
  - **編集のときは、保存されている送信先が自分のものでなくても、選択肢に足す**
    - 宛先の欄と同じ
    - ほかの人が登録した送信先を、見えるリマインダーの編集で、黙って外さないため
  - 選び直さなければ、送信設定は変えない
- 表が無いとき (MmmTool の `001_CreateTables.sql` などを流していない)は、読んだときの SQL のエラー (208)を、流す手順を伝えるメッセージの失敗にする
  - MmmTool は、入力画面で、送信先の欄を出さずに InfoBar で知らせ、送信先の一覧でも InfoBar で知らせる
  - MmmBatch も、送信の状況の画面の InfoBar で知らせて、送信しない

## DB 専用

- 送信先の登録・入力画面の送信先の欄・送信先の保存は、DB モードのときだけ出す・使う
  - ローカルモードでは出さず、`Reminders.json` に送信の項目は書かない
  - `Reminder` の型も変えない。設定は別の表・別の Repository に持つ。
- 機能のオン・オフの仕組み (DB のフラグ)は作らない (ユーザーの決定)
  - 「DB に接続しているときだけ出す」で足りる
  - オフにしたい要望が出たら、そのとき設計する

## MmmBatch の画面

- 1 枚のウィンドウ。左のサイドバーで、機能のページを切り替える。
  - サイドバーの項目は「リマインダーの送信」「メッセージの送信」。最初は先頭の項目。
  - サイドバーは「移動」で、ページの中のタブとは別
  - ページの中のタブ (`SelectorBar`)は、1 段だけ置く
  - 機能 (バッチ処理)が増えたときは、サイドバーの項目が増えるだけで、ほかのページは変わらない
- 送信のログ (ファイル)は、アプリが読まない (ユーザーの決定)
  - 何かあったときに、人がログのファイルを読む
  - 画面の「履歴」は、ログのファイルではなく、**起動してから送った分だけをメモリに持って出す**
  - 揮発性で、起動時は空。送るたびに足し、アプリを閉じると消える。同時に、ログのファイルにも書く。
  - 古い分は、ログのファイルで見る
- **「リマインダーの送信」のページ**: タブは「今日」「履歴」。最初は「今日」。
  - **今日 (今日の送信予定)**: 今日送るものを、時刻順に並べる
    - 列は、時刻・件名・ユーザー・送信先・状態
      - ユーザー: 送信先を登録した人の表示名
      - 送信先: 登録名と種類で、送る先の値は出さない (例: 自分のスマホ (ntfy))
      - 状態: 未送信・送信中・送信済み・失敗 (失敗の理由は「履歴」で見る)
    - 今日の分でないもの・削除したもの・送信先なしは出さない
    - 保存した時点で、送る時刻が過ぎていて、今日は送らないものは、状態を「対象外 (過去)」にして出す
      - なぜ送られないか、見えるようにするため
      - 右クリックの「今すぐ送る」で、送ることもできる
  - **まだ時刻が来ていない予定 (状態が「未送信」)への「今すぐ送る」は、テスト送信**
    - 送るだけで、「今日の送信の状況」は作らない・変えない
    - そのため、状態は「未送信」のままで、時刻になれば、予定どおり、もう一度送られる (ユーザーの決定で、テスト送信が、予定の送信を消さないため)
    - 送ったことは、送信のログに残る (回数は 0)
    - 時刻が過ぎているのにまだ送っていないものへの「今すぐ送る」は、状況を作って送る
  - **履歴**: 起動してから、リマインダーを送った 1 回ごとの記録を、新しい順に、最大 100 件 (メモリ上)
    - 再送・送り直しのたびに 1 行増える
    - 列は、時刻 (送った日時)・件名・ユーザー・送信先・結果
    - 結果は、成功・失敗 (失敗は理由つき)で、送った 1 回の結果を表す
      - 「今日」の状態の「送信済み」とは別の言葉
- **「メッセージの送信」のページ**: タブは「最近の依頼」「履歴」。最初は「最近の依頼」。
  - メッセージには、リマインダーのような「今日の予定」が無いので、日付で絞らない (日付で絞ると、日をまたいだ失敗を、再送できなくなるため)
  - **最近の依頼**: 依頼を、日付や状態にかかわらず、新しい順 (`MessageSendRequest.Id` の降順)に、最大 100 件
    - 列は、依頼した時刻・送った人 (表示名)・宛先・件名・状態
      - 宛先: 「ユーザー名 - 登録名 (ntfy)」「ユーザー名 - 登録名 (Discord)」の形で、MmmTool の宛先と同じ。送る先の値は出さない。
      - 件名: タイトル (無ければ空欄)
        - 本文で埋めない (件名が付いていたかを、画面から見分けられるようにするため)
      - 状態は、リマインダーのページと同じ (失敗の理由は「履歴」で見る)
  - **履歴**: 起動してから、メッセージを送った 1 回ごとの記録を、新しい順に、最大 100 件 (メモリ上)
    - 列は、時刻 (送った日時)・送った人・宛先・件名・結果
      - 宛先: 「ユーザー名 - 登録名 (種類)」の形
      - 件名: 無ければ空欄
      - 結果: 成功・失敗 (失敗は理由つき)
- 両ページの「再送」: 行を右クリックして、「再送」(まだ送ろうとしていないものは「今すぐ送る」)を選ぶと、状態にかかわらず、今すぐ 1 回送る
  - リマインダーでは時刻に、メッセージでは待ち時間に、かかわらず送る
  - 送信済みのものを再送すると、もう一度届く (確認は出さない)
  - 回数の上限に達した失敗も送れる (回数は数え続ける)
  - 毎分の実行が動いている最中は、その終わりを待ってから送る
  - 別の MmmBatch が先に同じものを送り始めていたときは、何もしない
- 一覧は、送信の状況が変わったときに更新する
  - リマインダーの「今日」は、毎分の実行のあとにも更新する (リマインダー・送信設定の編集を、すぐ反映するため)
  - メッセージの「最近の依頼」は、実行のたびには更新しない (5 秒おきでは読み込みが多すぎるため)
    - 新しい依頼は、仕事が拾って送った結果で更新される
  - どの一覧も、ページを出すたびに読み直す
  - 読み込みや接続の失敗は、そのページの一覧の上の InfoBar で知らせる (一方の機能の表が無いだけで、もう一方のページを読めなくしない)
- トレイに常駐する (SDK の `TrayIcon`)
  - メニューは「終了」だけで、クリックでウィンドウを開く。MmmTool と同じ形。
  - × ボタン・Alt+F4 では終了せず、ウィンドウを隠すだけで、送信は動き続ける (ユーザーの決定)
  - 基本は非表示で起動する
  - 起動直後の 1 回の実行が終わったあと (`BatchMonitor.FirstRunCompleted`)に、どれかの仕事が、状況を読めなかったとき (接続の設定が無い・つながらない)だけ、気づけるよう、ウィンドウを出す
    - 仕事の失敗は `IBatchJob.LastError` で、判定は `BatchMonitor.HasError`
- DB の接続の設定画面は、InfoBar の「接続の設定」ボタンから開く
  - 入力欄 (`DatabaseConnectionForm`)と、保存・キャンセルを付けたウィンドウ (`ConnectionSettingsWindow` と ViewModel)は、共有のライブラリ (`MmmTool.Data.SqlServer.WinUI`)にあり、MmmBatch は開くだけ (`Shell/Settings/ConnectionSettingsDialogService`)
  - 「接続を確認」できるまで保存できない作りは、MmmTool の保存先の画面と同じ
  - 保存したら、覚えている接続を捨て、再起動せずに新しい設定を使う
    - 接続を捨てるのは `SqlServerDatabase.ResetConnection`

## 送信のログ

- 送った 1 回ごとの結果を、ローカルのファイルに書く
  - 結果は成功・失敗で、ファイルには `Sent`・`Failed` で書く
  - 送る処理が結果を決めたところで、1 行足す (再送・送り直しも 1 行ずつ増える)
  - アプリは、このファイルを読まない (読むのは、何かあったときの人)
  - 画面の「履歴」は、起動してから送った分をメモリに持った記録 (`RecentSendLog`)を出す。書くと同時にメモリにも足す。
  - 二重送信を防ぐ判断には使わない (判断は DB の送信の状況 `ReminderSendStatus` で行う)
- 送信の記録を、`ReminderState` にフラグで足さない
  - 状態は、操作した人ごと・日ごとの行で、操作されなければ行を持たない
  - 送信は、誰も操作していなくても付ける必要があり、全員宛てのリマインダーでは、どの人の行に付けるかが決まらない
  - 書き手も違う (ユーザーと MmmBatch)
  - 同時編集の上書きを検出しない仕様では、完了の操作と送信済みの印が衝突しうる
  - `Reminder` にも送信先の列を足さない (`Reminder` の型・DB の表・ローカルの JSON を、送信のために変えない)
- `ReminderSendStatus` はログではなく状態で、「見て、送っていなければ送る」判断に使う
  - 先に行を作り、一意制約で、先に作れた 1 つだけが送る (二重送信の防止)
- 送った経過 (再送・送り直し・失敗の理由)は、DB の表を増やさず、ローカルの日付ごとのログ (`Data/Logs/send_yyyy-MM-dd.jsonl`)に残す (ユーザーの決定)
  - `ReminderSendStatus` は、再送のたびに同じ行を更新するので、経過が残らないため
- 置き場所は、MmmBatch の EXE の隣の `Data/Logs/`
  - 1 日 1 ファイルの `send_yyyy-MM-dd.jsonl` (送った日のローカルの日付)
  - 1 行 1 件の JSON (JSON Lines)で、メモ帳で読める
  - エラーのログ (`yyyy-MM-dd.log`)とは、名前が重ならない
- 1 行の中身は、送った日時・リマインダーの番号と件名・送信先の番号・種類・登録名・送信先を登録した人の表示名・何回目か・結果・失敗の理由
  - メッセージは、リマインダーの番号と件名の代わりに、依頼の番号とタイトルを持つ。タイトルが無ければ空文字。
  - 行は、どの機能が送ったかの印を持つ (キー `source`)
    - 値は機能が決める文字列で、リマインダーは `Reminder`、メッセージは `Message`
    - 履歴を機能ごとに絞るために使う
    - このキーが無い古い行は `Reminder`
    - 機能が増えても、共通のコードは変わらない
  - メッセージの行は、送った人 (依頼した人)の表示名 (キー `senderName`)を持つ。リマインダーの行は空文字。
  - 件名・名前は、送った時点のまま持つ (あとで直しても、ログは変わらない)
  - **送る先の値 (トピック名・Webhook の URL)は書かない**
- ログは永遠に残す (ユーザーの決定)
  - 今日を含めて 30 日分を `Data/Logs/` に置く
  - それより古い日のファイルは、日付が変わった最初の実行 (起動時を含む)で、`Data/Logs/old/` へ移す
- このコンピューターの中だけのログで、別のコンピューターで動かした MmmBatch のログは、見えない
  - ログを書けない・読めないときは、画面の InfoBar とトレイの通知で知らせる (送信そのものは、失敗にしない)
- 書き込みは 1 つずつ行う (ロック)
- 壊れた行 (手で直した・書きかけ)は、読み飛ばす
