# 通知の設定

通知を出す機能 (メッセージ・ノート)が共有する、通知先と、機能ごとの「通知を受け取る」のオン・オフの仕様。

## 概要

- DB モード (サーバーモード)だけで使う。ローカルモードには、ユーザーの特定も、外部への通知も無い。
- 通知先は、1 人に 1 つの共通の設定。どの機能の通知も、同じ通知先へ届く。
- 機能ごとに、「通知を受け取る」のオン・オフを持つ。オフの機能の通知は、通知先にも、PC の通知ダイアログにも出さない。
- 通知は、MmmBatch が通知先へ送る。MmmTool と Web 版は、設定を DB に書くだけで、外部へは送らない。送る側は [mmmbatch.md](mmmbatch.md) を見る。
- 通知先を機能ごとに持たない。通知を出す機能が増えるたびに、選ぶ欄が増えるため。
- 通知先を指定していない人にも、メッセージは送れる。通知が届かないだけで、アプリを開けば読める。詳しくは [messages.md](messages.md) の「通知先」を見る。

## 保存

保存は、ユーザーごとの設定 `AppUserSetting` の 1 設定 1 行で、値は文字列。
表の定義と機能番号の台帳は、[database.md](database.md) の `AppUserSetting` を見る。

| 設定 | 機能番号 | 区分番号 | コード番号 | 値 | 行が無いとき |
| --- | --- | --- | --- | --- | --- |
| 通知先 | 0 (共通) | 1 | 1 | 送信先 `NotificationChannel` の番号 | 未指定 |
| メッセージの通知を受け取る | 5 (メッセージ) | 1 | 1 | 1 = オン / 0 = オフ | オン |
| ノートの通知を受け取る | 2 (ノート) | 1 | 1 | 1 = オン / 0 = オフ | オフ |

- 既定がオンかオフかは、機能が決める。メッセージがオンなのは、通知先を指定すれば、そのまま通知を受け取れるようにするため。ノートがオフなのは、通知先を持つ人に、ノートの通知が黙って届き始めないため。
- 「通知を受け取る」の区分番号は、機能番号の下の 1。機能を足すときは、その機能の番号の下に同じ形で足す。
- 画面の言葉は「通知先」で、コードの名前も `NotificationTarget` 系にそろえている。
  - 届いた通知は `ReceivedNotification`、相手に通知が届くかは `PeerNotifiable` と呼び、「通知先」とは別の意味なので、`NotificationTarget` 系にしない。

## 通知先

- 指定できるのは、自分が使用者の送信先のうち、種類が Web 版通知のもの 1 つ。ntfy と Discord は、指定できない。
  - 通知ダイアログが、PC のアプリの中で、通知を知らせる。外部への通知は、スマホへの知らせのためだけに要るため。
  - ntfy と Discord は、リマインダーの送信先として残る。リマインダー 1 件ごとに選ぶ。
  - 候補を絞るのは、PC の設定ページの部品と、Web 版の API。保存の検査は、Web 版の API が、絞った候補で行うので、Web 版の端末でない送信先の番号は断る。
- 複数を指定できる形にしない。1 通の通知が、通知先の数だけ送られるため。
- 指定を外すこともできる。外すと未指定になり、外部への通知は送られない。PC の通知ダイアログは、通知先に関係なく出る。
- 指定した送信先が削除されたときは、未指定と同じに扱う。
- 通知先は、受け取る人が決める。自動では入れない。
- 通知先の指定を、通知を出す機能の仕様に持たない。メッセージの通知先の扱いは、[messages.md](messages.md) の「通知先」を見る。

## 通知を受け取る機能

- 機能が、画面に出す名前・機能番号・既定を登録する。設定の画面は、登録されたものを読んで並べ、機能の名前を持たない。
  - 機能を足すときは、その機能が登録するだけで、設定の画面に並ぶ。
- 管理者が無効にした機能は、その人の設定の画面に出さず、通知も送らない。無効にする仕様は [mmmtooladmin.md](mmmtooladmin.md) の「機能の利用」を見る。
- オフにしても、通知先の設定は変わらない。ほかの機能の通知は、そのまま届く。

## 画面

文言は仮。

- PC 版: 設定ページ
  - 「通知先」の節: 自分が使用者の Web 版通知の送信先を、名前と種類で並べ、1 つ選ばせる。「指定しない」も選べる。選んだ操作の直後に保存する。
  - 「通知を受け取る機能」の節: 登録された機能を、登録順に、機能ごとのスイッチで並べる。切り替えた操作の直後に保存する。
  - 送信先の登録の画面は、設定ページの「送信先」にある。仕様は [reminders.md](reminders.md) を見る。
  - 「送信先」「通知先」「通知を受け取る機能」の 3 つは、どの機能にも属さない共通の節で、「選択肢」のすぐあとに、この順で並ぶ。管理者がリマインダーを無効にした人の設定ページにも出る。
    - 機能のキーを付けない。付けると、リマインダーを無効にされた人は、通知先を指定できなくなるため。
    - 登録は、`AddNotificationSettings` で、並び順の値をホストが渡す。
- Web 版: 設定の画面。仕様は [web.md](web.md) の「設定 (Web 版)」を見る。
  - 「通知先」の節と「通知を受け取る機能」の節を並べる。内容は PC 版と同じ。
  - Web 版の端末は、同じ設定の画面の「通知」の節で登録する。
- 書けなかったときは、画面の上に理由を出す。選んだ状態は、読み直した値に戻す。
