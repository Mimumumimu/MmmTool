# 設定ページ

設定ページの仕様。

## 概要

- 画面は `Features/Settings/SettingsPage` ＋ `SettingsViewModel`
- メイン画面のサイドバー下部に置く

## 構成 (機能ごとの部品を並べる)

- 設定の項目は、各機能が `AddSettingsSection<TControl>()` で、設定の部品 (`UserControl`)を登録する
  - `AddSettingsSection` は `Shell/ShellServiceCollectionExtensions` にあり、サイドバーの `AddNavigationPage` と同じ形
  - 設定ページは、並び順の値の順に縦に並べるだけで、特定の機能を知らない
  - 機能を足すときに触るのは、その機能のフォルダと `App` の 1 行だけ
- 並び順は、部品の並び順の値 (小さいほど先)で決まる
  - 各機能の部品は、機能の並び (利用者が決めた順)で並ぶ
    - 登録の `order` は、保存が無いときの順
    - 詳細は、下の「機能のオン・オフと並び順」
  - 機能に属さない部品は `Shell/SettingsSectionOrder` の値で、すべて機能より前に並ぶ
  - ページは「全般」→「保存先」→「アカウント」(DB のログイン済みのときだけ)→「機能」の一覧 →「選択肢」(ローカルモードのときだけ)→ 各機能 (機能の並びの順で、例はリマインダー → Backlog)の順に並べるだけで、どの部品も特別扱いしない
    - 「全般」や「機能」の一覧をページに直接書くと、並ぶ部品は必ずその下に出て、「全般」を一番上にできない。ページが特定の部品を知ることにもなるので、一覧も部品にして、並びを並び順の値だけで決める。
  - 「保存先」はアプリ全体の基本設定なので、各機能の設定より上にする
- 部品は設定ページを開くときに DI から作る (Transient)
  - 値の読み書きと画面の状態は、その機能の ViewModel・サービスが持つ (部品の見た目は設定ページと同じ縦並び)
- 見た目は、Windows 11 の設定アプリと同じ「見出し + カード」にする (ユーザーの決定)
  - PowerToys も同じ現行の形
  - 区切りの見出しは各部品が先頭に持つ (`App.xaml` の `SettingsSectionHeaderStyle`)
  - 項目は `SettingsCard`(`CommunityToolkit.WinUI.Controls.SettingsControls`)の行にする
  - 左に名前 (`Header`)と説明 (`Description`)を置き、右に操作を置く
  - ページは特定の機能を知らないまま、部品を並べるだけ
- 設定ページ全体は `ScrollViewer` に入れ、項目が画面に収まらないときも、下まで届く
- 項目の縦の間隔は、ページ・各部品とも `StackPanel Spacing="4"` でそろえる (カードの間隔)
  - 各部品の先頭にあるエラーの `InfoBar` は、閉じている間も要素が残って `Spacing` を取ってしまう
  - そのため、`Visibility` を `ErrorState.IsOpen` にバインドして、閉じている間は場所を取らないようにしている
  - 新しい設定の部品を足すときも、同じにする
- 保存の方式は 2 つ
  - 値が 1 つの項目 (スイッチ・数・API キー)は、変えた時点で保存する (保存ボタンは無い)
  - 保存先と接続と選択肢の名前は、カードから開く別のウィンドウで編集し、そこの「保存」で保存する
  - 一括の「保存」は無い (設定ページの中に即保存の項目と「保存」のボタンが並ぶと、「保存」が全体の保存に見えて紛らわしいため)
  - 保存先と接続は、確認 (「接続を確認」)を経て保存する性質なので、別のウィンドウに、その流れを閉じ込める
  - 選択肢の名前は、11 件のような複数の入力欄をまとめて保存するので、別のウィンドウにする (1 件ずつ即保存にしない)
- 新しい設定の部品は `SettingsControls` のパッケージが要る
  - 参照の仕方は、`Segmented` と同じ ([build-and-distribution.md](../build-and-distribution.md))
- `SettingsViewModel` はページ全体のことだけを持つ
  - タイトルと、設定ファイルを読めなかったとき (`ISettingsStore.LoadError`)の InfoBar
  - 機能のオン・オフの一覧は、部品 (`Features/Settings/FeatureList/FeatureListControl` ＋ `FeatureListViewModel` ＋ `FeatureItem`)が持つ
  - 読めなかったときは、各部品が、自分のサービスの `IsReadOnly` で入力欄を無効にする (元のファイルを上書きで消さないため)

## 機能のオン・オフと並び順

- 「全般」の下に、機能の一覧を出す
  - 「機能」の見出しと説明文 1 行の下に並べる
  - 各行は `SettingsCard`(左に取っ手 ⠿ と機能名、右に操作)
  - オフにできる機能 (`AddFeature` で登録したもの)には `ToggleSwitch`(オン / オフ)を付ける
    - オフにできる機能は、CLI補助・クリップボード転送・Backlog・作業管理・ツール・メッセージ
  - リンク・リマインダー (`AddAlwaysOnFeature` で登録する)は、スイッチなしで並べる
    - `FeatureInfo.CanDisable = false` で、`IsEnabled` は常に true
    - 押せない無効のスイッチを並べると、押せないものが増えて紛らわしいため
    - 並び順を決める行として並べる
  - 一覧は `FeatureService.Features` から作るだけで、特定の機能を知らない (`FeatureListViewModel` ＋ `FeatureItem`)
  - 設定の部品は、その機能がオン・オフされたときだけ並べ直す
- 行はドラッグして並べ替える (`ListView` の `CanReorderItems`)
  - 保存ボタンは無い
  - 一覧の変更 (`CollectionChanged`)を見て、操作が止まってから 300ms 後に 1 回だけ保存し、すぐ反映する
    - 遅らせる処理は `Debouncer` で行う
    - `DragItemsCompleted` は届かないため使わない
  - 失敗したときは InfoBar を出して、実際の並びへ戻す
  - 行の左に、小さな薄い色の取っ手 (ドラッグの目印)を置く
  - 一覧の下の「既定の順に戻す」で、保存した並びを消して登録の順に戻す
- 並び替えは「機能」の一覧に持たせ、専用の欄は作らない
  - 同じ名前の一覧を 2 つ並べると画面が長くなるだけで、1 つの一覧でオン・オフと位置を変えられるほうが迷わないため
  - VS Code のアクティビティバー・Chrome のツールバーのカスタマイズも同じ形
- 見出しを「表示・非表示」にしない (オフにすると起動時の読み込みも止まり、動きが伝わらないため)
- 機能が増えて並びだけ別に整えたくなったら、一覧から分ければ足りる
- 並びは、利用者が決めた順
  - 保存が無ければ、登録の並び順の値の順: CLI補助 → ノート → 作業管理 → リマインダー → メッセージ → リンク → クリップボード転送 → Backlog → ツール
  - 反映先は、サイドバーと、設定ページの各機能の部品
  - 「全般」「保存先」「アカウント」「機能」の一覧と「選択肢」は、先頭に固定 (動かせない)
  - トレイは連動せず、登録の `trayOrder` の順 (リマインダー → リンク → 終了)のまま (ユーザーの決定)
- 保存は、設定ストアの `Feature.Order`(機能のキーの配列)で、SDK の `FeatureService` が扱う
  - 載っていない機能 (あとから足したもの)は、後ろに登録の順で付く
  - 並びの値は `FeatureService.OrderOf(キー, 登録の値)` が返し、サイドバー (SDK の `NavigationHostViewModel`)と設定ページ (`SettingsPage`)が使う (並べる処理を 1 か所に置くため)
  - 並びが変わると `OrderChanged` が出る (`Changed` はオン・オフ用)
- 設定ページは、すでに並んでいる部品を作り直さず、順序の違うものだけを動かす
  - ドラッグの直後に「機能」の一覧を作り直さない
  - サイドバーも、項目を `Move` する
- 文言 (説明文「使う機能とサイドバーの並び順」・ボタン「既定の順に戻す」・エラーの文)は仮
- 切り替えはすぐ反映する (ユーザーの決定)
  - 再起動は要らない (トレイ常駐 + 多重起動の禁止のアプリで、再起動を求めると操作が重いため)
  - サイドバー・トレイメニュー・設定ページの部品が、`FeatureService.Changed` で変わる
  - オフにした機能のページは、`PageProvider.EvictDisabledPages` で捨て、表示中なら先頭のページへ移る
  - オンにしたときは、その機能の起動時の準備を実行する
- 状態は設定ストアの `Feature.<キー>.Enabled`(bool)
  - 保存が無い機能は、登録の既定値 (`AddFeature` の `defaultEnabled`)を使う。省略するとオン。
  - CLI補助・クリップボード転送・Backlog・作業管理が既定でオフ
  - ツール・メッセージは既定でオン
    - メッセージはサーバーモードのときだけ一覧に出て、ローカルモードでは、保存された値があっても効かない
    - 詳細は [messages.md](messages.md)
- CLI補助を、ターミナルが動いている間にオフにするときは、確認ダイアログを出す (`CliAssistDisableConfirmation`)
  - 確認の文は「実行中のターミナルと、その中の作業が終了します」
  - ターミナルが動いていなければ確認しない
  - 作業中のセッションが、誤操作で消えるのを防ぐための確認 (ユーザーの決定)
  - 確認は機能ごとに `IFeatureDisableConfirmation` で登録し、確認が要らない機能は登録しない
  - 取りやめると、スイッチは元に戻る
- 設定ファイルを読めなかったとき (`IsReadOnly`)は、スイッチを無効にする。保存できなかったとき (読み込めない・`DataFileException`)は、一覧の見出しの下の InfoBar で知らせ、スイッチを元に戻す。
- 登録・ページの破棄などの仕組みは、下の「機能の登録とページの破棄」

## 初回の機能の選択

- 初めて起動したときに、使う機能をオン・オフで選ぶ画面
- 初回の保存先の選択 ([database.md](database.md))のあとに、続けて出す
- 出す条件は、設定ストアの `Setup.FeaturesChosen`(bool)が `false` のとき
  - 初回の保存先の選択の決定が `false` を書き込み、この画面の決定が `true` に書き換える
  - キーが無いとき (この画面を足す前から使っているとき)は出さない
  - 選ばずに閉じても `false` のまま残るので、次の起動は、保存先の選択を飛ばして、この画面から始まる
  - 「機能の保存が 1 つも無いとき」では判定しない (機能の設定を触らずに使ってきた人にも出てしまうため)
- 出す順は、保存先の選択 → 機能の選択 → 各機能の準備
  - 選んだ内容を最初から効かせる (各機能の準備が、オフの機能を動かさないため)
- 一覧は、設定ページの「機能」の一覧と同じ条件の機能を、登録の並びで出す
  - 条件は、`FeatureInfo.CanDisable` が true で、今の保存先のモードで使えるもの
  - 常にオンの機能 (リンク・リマインダー)は出さない
  - 一覧は `FeatureService.Features` から作り、特定の機能を知らない
- 各行は、機能名・`ToggleSwitch`(オン / オフ)・説明 1 行
  - 説明 1 行は仮で、機能の登録 (`AddFeature`)で渡す
  - 並べ替えはしない (設定ページの「機能」でする)
- 最初の状態は、機能の登録の既定値 (`defaultEnabled`)
  - ただし、登録で `selectedOnFirstRun: true` を渡した機能 (CLI補助)は、最初からオン
  - 機能の名前をホストに書かずに済む (機能が増えても、登録の 1 行で足りる)
  - 登録の既定値は変えない (前から使っている人の動きが変わらないため)
- 「決定」(仮)を押すと、一覧の全部の機能の `Feature.<キー>.Enabled` を保存し、`Setup.FeaturesChosen` を `true` にして先へ進む。保存できなかったときは、画面の InfoBar に出して、閉じない。
- 閉じる (×)と、保存先の選択と同じく、アプリを終了する (仮)
- 初回の起動なので、メイン画面も出る ([tray-and-main.md](tray-and-main.md))
- 画面は、保存先の選択と同じ、モーダルのウィンドウ
  - ホストの `Features/Settings/FeatureSetup/` の `FeatureSetupWindow` ＋ `FeatureSetupViewModel`

## 項目

- **起動時にメイン画面を開く** (`src/App/MmmTool/Features/Settings/General/MainWindowSettingsControl` ＋ `MainWindowSettingsViewModel`)
  - ホスト側の部品で、`AddSettingsSections()` が `AddSettingsSection` で登録する (どの機能にも属さず、オフにならない)
  - 設定の部品のうち最初に登録するので、ページの一番上に並ぶ (Windows の設定アプリも、全般が先頭)
  - 見出しは「全般」
  - 設定の読み書き `MainWindowSettingsService` は、メインウィンドウと同じ `Shell/` にある
  - `ToggleSwitch`(オン / オフ)で、変えた時点で保存する
    - 機能の一覧と同じ
  - 保存は `MainWindowSettingsService` 経由で、設定ストアの `Shell.OpenMainWindowOnStartup`(bool)に書く。無ければオフ。
  - 説明の文言は付けない
  - 設定ファイルを読めなかったとき (`IsReadOnly`)は、スイッチを無効にする。保存の失敗 (`DataFileException`)は、画面の InfoBar に出す。
  - 反映は次の起動から
    - 起動の動きは [tray-and-main.md](tray-and-main.md)
- **音声機器を起こしておく** (`MainWindowSettingsControl` ＋ `MainWindowSettingsViewModel`)
  - 「全般」の 2 つ目の項目
  - 光デジタル出力など、無音が続くと信号を止める機器で、読み上げの頭が切れるときに、オンにする
  - オンの間、無音の出力を流し続ける (SDK の `IAudioKeepAlive`)
    - 仕組みは SDK の `docs/audio.md`
  - `ToggleSwitch`(オン / オフ)で、変えた時点で保存し、すぐに始める・止める
  - 説明文は「無音を流し続けて、音声機器が休止するのを防ぎます。通知の読み上げの頭が切れるときに、オンにします。」
  - 既定はオフ (一部の機器でだけ要り、無音を流し続けるのは、全員の PC にとって余計な負担になるため)
  - リマインダーの設定ではなく「全般」に置く
    - 読み上げ・通知音など、アプリ全体の音の頭が切れるのを防ぐ、音声機器の設定で、リマインダーに属さないため
    - SDK の部品も、`Speech` とは別の `Audio`
  - 保存と、始める・止めるは `Shell/AudioKeepAliveSettingsService`
  - 保存先は設定ストアの `Shell.AudioKeepAlive`(bool)で、無ければオフ
    - PC ごとの音声機器の事情なので、DB モードでも設定ストアに置く
  - 起動時は `AudioKeepAliveStartup` が、オンなら始める
  - 設定ファイルを読めなかったとき・保存の失敗の扱いは、「起動時にメイン画面を開く」と同じ
- **リマインダーのスヌーズ間隔** (`src/Plugins/MmmTool.Reminders/ReminderSettingsControl` ＋ `ReminderSettingsViewModel`)
  - `NumberBox`(スピンは Inline・小さい刻み 1 / 大きい刻み 10)と双方向で、変わったら即保存する
  - 保存は `ReminderSettingsService`(Core)経由で、設定ストアの `Reminder.SnoozeIntervalMinutes` に委譲する
  - 範囲は 5〜999 分で、既定は 15
    - 定数と補正は `ReminderSettingsService` の `MinSnoozeInterval` / `MaxSnoozeInterval` / `ClampSnoozeInterval`
    - 範囲外・空は範囲内に補正して、画面にも反映する (`NumberBox` は空にすると NaN になる)
  - 保存の失敗 (`DataFileException`)は、画面の InfoBar に出して続ける (`SaveSnoozeIntervalAsync`)
  - 想定外の失敗は、握りつぶさず安全網 (ログ → ダイアログ → 終了)へ流す
- **リマインダーの読み上げの声・速さ** (同じ `ReminderSettingsControl` の 2 行目)
  - 声と速さはアプリでは持たず、Windows の音声の設定 (時刻と言語 > 音声)に従う
  - そこへ移るリンク「Windows の音声設定を開く」(`HyperlinkButton` ＋ 外部リンクのアイコン)を置く
  - `ms-settings:speech` を `IPathOpener` で開く (`OpenSpeechSettingsAsync`)
  - 強調しないリンク型にしたのは、アプリの外へ出るだけの操作で、この画面の主な操作ではないため
  - 開けなかったとき (`PathOpenException`)は、画面の InfoBar に出す
- **リマインダーの読み上げの音量** (同じ `ReminderSettingsControl` の 3 行目)
  - `Slider`(0〜100・刻み 1)と、「試し聞き」ボタンを置く
    - `Slider` の右に「50%」の表示を出す
    - 「試し聞き」は強調しない通常のボタン。押すと今のスライダーの値で「読み上げの音量を確認します。」を読む。
  - 説明文は付けない
  - 既定は 50% (100% だと、Windows の音量を上げている PC でうるさいため)
  - 保存は SDK の `ISpeechService.SetVolumePercentAsync` 経由で、設定ストアの `Speech.VolumePercent`(整数 %)
    - リマインダーの設定サービスは通らない
    - 仕組みは SDK の `docs/speech.md`
  - スライダーを動かし終えて 0.4 秒たってから保存する (動かす間は、書き込まない)
  - 「試し聞き」は、予約中の保存を待たず、すぐ保存してから読む
  - 保存の失敗の扱いはスヌーズ間隔と同じ
  - 設定ファイルを読めなかったとき (`IsVolumeReadOnly`)は、スライダーを無効にする
  - 反映: 読み上げは、読むたびに保存値を使う
    - 設定を変えても、再起動は要らない
    - `ReminderStartup` は何もしない
  - アプリの再生音量 (`MediaPlayer.Volume`)で、Windows の音量 (ミキサー・全体)とは別
    - 実際の音量は両方を掛けたもの
    - 声と速さは変わらず、Windows の音声の設定に従う
    - 音量を Windows の音声の設定に任せない (ミキサーでも下げられるが、アプリの設定として見えず、試し聞きもできないため)
  - 音量の設定行の位置 (読み上げの声・速さの行の下)・「50%」の表示・試し聞きの文 (「読み上げの音量を確認します。」)は仮
- **作業管理の起動時の表示** (`src/Plugins/MmmTool.WorkItems/Settings/WorkItemSettingsControl` ＋ `WorkItemSettingsViewModel`)
  - 作業管理の機能の設定の部品で、`WorkItemsFeature.Key` で登録する。作業管理がオフの間は並べない。
  - 見出しは「作業管理」で、カードは 2 枚
    - 「作業管理の過去の完了」と「スケジュールの完了」で、説明は「アプリの起動時の表示。画面で変えた表示は保存しません」
    - 右に `ComboBox` (固定幅)で「表示」「グループのみ表示」「非表示」を選ぶ。選択肢の並びは、画面の「表示」の入れ物と同じ。
    - カードの題名に画面の名前を付ける。設定ページでは、「完了」だけだと、どの画面の話か分からないため。
  - 変えた時点で保存する。保存の読み書きは Core の `WorkItemDisplaySettings`。
  - 保存先は、設定ストアの整数のキー `WorkItems.InitialPastCompleted` と `WorkItems.InitialScheduleCompleted`。PC ごとの設定で、DB モードでも DB には置かない。
  - 既定は、作業管理の「過去の完了」が「グループのみ表示」で、スケジュールの「完了」が「表示」
  - 反映は次の起動から。画面の状態クラス (`WorkItemViewState`・`ScheduleViewState`)を最初に作るときに読むだけなので、動いている画面は変わらない。
  - 設定ファイルを読めなかったとき (`IsReadOnly`)は、選択欄を無効にする。保存の失敗 (`DataFileException`)は、画面の InfoBar に出す。
- **送信先** (`src/Plugins/MmmTool.Reminders/Settings/NotificationChannelSettingsControl` ＋ `NotificationChannelSettingsViewModel`)
  - リマインダーの機能の設定の部品 (`ReminderSettingsControl` の次に並ぶ)
  - 見出しは「送信先」で、カードは 1 枚
    - カードは「送信先の登録」で、押すと、送信先の一覧画面を開く (`IReminderDialogService.ShowChannelListAsync`)
    - リマインダーの一覧画面の「送信先の設定」と同じ画面
  - サーバーモード (DB モード)のときだけ並べる
    - 判定は `INotificationChannelRepository.IsAvailable`
    - ローカルモードでは、部品そのものを隠す (ページの `Spacing` の場所も取らない)
    - 「アカウント」と同じ
- **Backlog の API キー** (`src/Plugins/MmmTool.Backlog/Settings/BacklogSettingsControl` ＋ `BacklogSettingsViewModel`)
  - `PasswordBox` に API キーを入れる
  - 入力欄からフォーカスが外れたときに保存する
  - 保存先は設定ストアではなく、資格情報マネージャー ([backlog.md](backlog.md))
  - 保管庫を読めない・書けない失敗 (`SecretStoreException`)は、画面の InfoBar に出して続ける。Backlog の機能がオフの間は、この項目も並べない。
- **選択肢** (`src/CodeMaster/MmmTool.CodeMaster/Settings/CodeMasterSettingsControl` ＋ `CodeMasterSettingsViewModel`)
  - コードマスタの名前を、画面から直す入口。ホストの `AddCodeMasterSettings(order)` が `AddSettingsSection` で登録する。どの機能にも属さない。
  - 並びは「機能」の一覧の次で、値は `SettingsSectionOrder.CodeMaster`
  - 見出しは「選択肢」で、直せる区分ごとに、押せるカードを1枚ずつ並べる。押すと、その区分の編集ウィンドウ (`Edit/CodeNameEditWindow`)がモーダルで開く。
  - 区分は、各機能が `AddCodeCategoryEditor` で登録する。この部品は特定の機能を知らず、機能がオフの間は、その区分を並べない。
    - 作業管理は「進捗度の名前」を登録する。内容と決まりは [work-items.md](work-items.md) の「コードマスタ」。
  - 編集できるのは、ローカルモードだけ。DB モードと、並べる区分が無いときは、部品そのものを隠す。「アカウント」と同じ。
  - 編集できるかの判定は `ICodeMasterRepository.CanEdit`
  - 編集ウィンドウは、選択肢ごとに、固定の表記 (進捗度は `70%`)と名前の入力欄を並べる。一覧は固定の高さの枠で、選択肢が増えてもウィンドウの大きさは変わらない。スクロールバーは、常に出す (`Auto` だと、カーソルを合わせるまで見えず、続きがあることに気づけないため)。
    - 保存は「保存」を押したときだけ。入力できない名前は、ウィンドウの先頭のエラーに出して閉じない。
    - 保存したら、開いている作業管理の表記が、すぐ変わる。
  - 文言は仮で、見出し「選択肢」・カードの題名と説明・エラーの文が当たる
- **アカウント** (`src/App/MmmTool/Features/Users/Settings/AccountSettingsControl` ＋ `AccountSettingsViewModel`)
  - ホスト側の部品で、`AddUserSignIn()` が `AddSettingsSection` で登録する (並びは「保存先」の次)
  - DB に保存していて、ログイン済みのときだけ出す (隠している間は、ページの `Spacing` の場所も取らない)
  - 見出しは「アカウント」
  - 内容と動きは [database.md](database.md) の「アカウントの変更とログアウト」
  - カードは、次のとおり
    - 「表示名」「ログイン名」(説明に今の値)「パスワード」は、押すと編集のウィンドウが開く
    - 「ログアウト」は、右に強調しないボタン (押すと確認が出る)
- **保存先と DB への接続** (`src/App/MmmTool/Features/Database/Settings/DatabaseSettingsControl` ＋ `DatabaseSettingsViewModel`)
  - ホスト側の部品で、`AddDatabaseScreens()` が `AddSettingsSection` で登録する (どの機能にも属さず、オフにならない)
  - 設計は [database.md](database.md)
  - 設定ページには、「保存先」の見出しの下に、カード 1 枚だけを出す
    - カードは「保存先」で、説明に、今の保存先を「ローカル」または「サーバー (サーバー名)」で見せる
    - カード全体が押せる (右に ›)
    - 押すと編集のウィンドウが開く
    - 閉じたら、説明を読み直す
  - 編集のウィンドウ (`Features/Database/Edit/DatabaseEditWindow`)は、モーダルのウィンドウで開く
    - 開く口は `IDatabaseDialogService`
    - `ContentDialog` にすると、その上で出る再起動の確認と同時に開けず、例外になる
    - ウィンドウなら、`DialogService` が一番手前のモーダルを確認の親にするので、確認が重なって出る
  - 編集のウィンドウでは、保存先 (ローカル / DB)を `RadioButton` で選ぶ (初回の選択の画面と同じ)
    - DB のときだけ、接続の入力欄 (接続先のサーバー・データベース名・ユーザー名・パスワード)と「接続を確認」を出す
    - DB のときは、つながると確認できるまで、「保存」を押せない
    - ログインの方式と証明書は、画面の項目にしない (理由と動きは [database.md](database.md))
    - 入力欄は、初回の保存先の選択の画面と共有する部品 (`DatabaseConnectionForm`)
  - 保存は「保存」ボタンを押したときだけ (入力の途中を保存しない)
    - 保存先は起動時に決まるので、保存先の種類が変わった・DB のまま接続が変わったときは、「反映するには、アプリの再起動が必要です。今すぐ終了しますか？」と確認する
    - 「今すぐ終了」でアプリを終了する。「あとで」は保存だけ。
    - 終了は `AppExitService` が、トレイの「終了」と同じ処理で行う
    - 「今すぐ終了」は、ウィンドウを閉じてから頼む (終了の処理が、開いたままのウィンドウと重ならないように)
    - 保存できたら、ウィンドウを閉じる
    - 「閉じる」・× は、保存しない
  - 失敗は、ウィンドウの先頭の InfoBar で知らせる。成功 (「接続できました。」)も InfoBar。設定ファイルを読めなかったとき (`IsReadOnly`)は、カードと入力・「保存」を無効にする。

## 機能の登録とページの破棄

- 登録の単位は「機能」
  - オフにできる機能は、`<機能>Plugin.Register` の中で `AddFeature(キー, 表示名)` を登録し、ページ・起動時の準備・トレイメニュー・設定の部品の登録に同じキーを渡す
  - Shell は機能の名前を知らず、キーで絞り込むだけ
  - ページを持たない機能 (トレイだけ・常駐だけ)も同じ形で扱える
  - キーは文字列の定数 (`CliAssistFeature.Key`)で、設定ファイルにも使うので、決めたら変えない
- オン・オフの管理 (`FeatureService`・`FeatureChangeResult`)は SDK (`MmmSdk.Core.Components.Features`)に置く
  - UI にも特定の機能にも依存しないので、ほかのアプリも使える (理由は SDK の `docs/architecture.md` の「機能 (プラグイン)がホストへ入る口」)
  - ホストは `AddFeatureService()` で登録するだけ
  - サイドバー・ページのキャッシュ・設定ページへの反映と、オフにする前の確認の画面は、ホストが持つ
- トレイメニューは開くたびに項目を作るので、`RegisteredTrayMenuSource` が空を返すだけで、オフが反映される
- オフにしたページは捨てる
  - ルートのプロバイダーから作った `IDisposable` の Transient は、Host の破棄まで残る (オン・オフのたびに増え、ページ・WebView2 も残る)
  - そのため、`PageProvider` がページごとのスコープ (`IServiceScopeFactory`)から作り、オフにしたときにスコープを破棄する
  - 画面の部品に触れる後始末は `IReleasablePage.Release` に書き、スコープの破棄の前に呼ぶ
    - `IDisposable` をページに付けると、アプリの終了時にも DI が呼び、そのとき画面の部品に触れてしまうため
  - 残りのスコープは、`PageProvider` の `Dispose` (Host の破棄)で破棄する
  - オンに戻したときは、ページ・セッションを新しく作る
- `PageProvider` は `FeatureService` に、`FeatureService` は確認 (`IFeatureDisableConfirmation`)に依存するので、CLI補助の確認は、ページを引くとき (確認の実行時)に `IServiceProvider` から `PageProvider` を取り出して、循環を避ける
- 起動時の準備: `IStartupTask` は、`FeatureService` が持つ登録の一覧から、オンの機能の分だけ登録順に実行する
  - 共通の設定ファイルの先読みが先頭なので、オン・オフの判定は読み込み済みの設定で行われる
  - 起動時にオフの機能は実行せず、オンにしたときに実行する
