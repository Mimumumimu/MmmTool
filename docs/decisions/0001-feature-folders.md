# 0001 機能別フォルダ（Vertical Slice）で構成する

## 状況
画面・ViewModel・Entity を層ごとのフォルダ（`Views/` `ViewModels/` `Entities/` など）に置くと、1 つの機能を触るたびに複数のフォルダを行き来する。機能が増えるほど、関係するファイルが散らばる。

## 決定
- プロジェクトの中は機能ごとのフォルダにし、その機能の View・ViewModel・Entity・サービスを同じフォルダに置く（Core は `<機能>/`、アプリは `Features/<機能>/`）
- MVVM の役割はフォルダではなく、クラス名で分かるようにする（`*Page` / `*Window` = View、`*ViewModel`、Core の Entity・サービス = Model）
- 機能をまたぐものは `Shell/` `Interop/` に置き、これらは特定の機能を参照しない（機能 → 共通部分の一方向）
- 機能ごとに DI 登録の拡張メソッド `Add<機能>()` を持つ。サイドバーのページ・トレイメニューの項目・起動時の準備も機能側から登録する
- 共有ライブラリ（SDK）も同じ考え方で、機能の代わりに提供する部品ごとのフォルダにする

## 理由
- 機能を足す・直すときに触るのが、その機能のフォルダと `App` の 1 行で済む
- 保存先を替えるときも、その機能の `Add<機能>()` の 1 行を差し替えるだけで済む

## 影響
フォルダ名が名前空間になる。XAML で同じ名前空間の型は `local:` で参照する。名前空間がよく使う型名を隠さないよう、フォルダ名に注意する（例：`Debug` ではなく `Debugging`）。
