# 0013: 機能のフォルダを「つなぎ」「Main/」「1 画面 = 1 フォルダ」にそろえる

## 背景
機能のフォルダの中で、入口の画面がフォルダの直下にある機能 (CliAssist・Links・Settings・Debugging)と、`Main/` に入っている機能 (Reminders)が混ざっていた。また、DI 登録・起動時の準備などの「機能全体のつなぎ」と、画面の View・ViewModel が同じ段に並んでいて、見分けにくかった。

## 決定
どの機能 (と `Shell/`)も同じ形にする。名前空間はフォルダどおり。型の名前は変えない。動きも変えない。
- 機能のフォルダの直下: 機能全体のつなぎ (`Add<機能>()`・`<機能>Startup`・`<機能>TrayMenuSource` など、Shell へ登録するもの)と、複数の画面で共有するものだけ
- `Main/`: その機能の入口の画面。画面が 1 つだけの機能も `Main/` に入れる
- `<画面>/`: そのほかの画面。1 画面 = 1 フォルダ。その画面の View・ViewModel・行などの表示用の型を一緒に置く
- `Shell/`: 直下に DI 登録と、機能が登録に使う型・アプリ全体で使う型。`Main/` にメインウィンドウ (`MainWindow`・`MainViewModel`・`PageProvider`)

主な移動: CliAssist・Links・Settings・Debugging の入口の画面 → `Main/`(CliAssist の `Attachments/AttachmentItem` も `Main/` へ。フォルダは消した)。リマインダー設定の欄 → `Reminders/Settings/`。`Shell` のメインウィンドウ関係 → `Shell/Main/`。

## 理由
- 入口の画面の置き場所が機能ごとに違い、つなぎと画面が同じ段に並んで見分けにくかった
- 画面が 1 つだけの機能も `Main/` に入れる理由: フォルダが 1 段増えても、どの機能も同じ形にそろえることを優先する (標準化。1 つを覚えれば全部が読める)
- Core に同じ形を当てない理由: Core には画面が無く、中身は「その機能のデータと処理」の 1 種類だけ (保存先の実装は `Json/` に分かれている)
- XAML では、移した画面から、親のフォルダ (機能の直下)に残った型を、`local:` ではなく親の名前空間の xmlns で参照する (例: `MainWindow.xaml` の `shell:NavigationItem`)

## 最終形にどう近づくか
どの機能も「つなぎ + Main + 画面ごとのフォルダ」の同じ形になり、新しい機能・画面を足すときの置き場所が迷わず決まる。
