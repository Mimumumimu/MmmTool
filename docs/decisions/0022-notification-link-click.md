# 0022 通知ウィンドウのリンクのクリック判定は、今の方式のまま変えない

## 状況
通知ウィンドウ (SDK の `NotificationWindow`)は、クリックで閉じる。本文のリンク (`Hyperlink`)をクリックしたときは、閉じない。今は、`Hyperlink.Click` でフラグを立て、閉じる判定を Low 優先度で 1 サイクル遅らせて、リンクのクリックかどうかを決めている。発火順に依存しているため、将来壊れうる、とレビューで指摘された (Q-19)。

## 決定
- 今の方式のまま変えない (ユーザーの決定)
- レビューで「発火順に依存していて将来壊れうる」と指摘・提案しない

## 理由
- 今の動きは、実機で問題なく動いている
- 押下位置から判定する方式は、WinUI 3 の `TextBlock` に使える API が無い
- `RichTextBlock` へ替えると、見た目・操作 (テキスト選択・カーソル形状・クリックで閉じる)が壊れる

以上から、採らないと決めた。
